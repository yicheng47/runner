This crew works as a two-person coding loop. Runner messages are the coordination and review record. The review loop always runs on the task-specific feature branch's working-tree diff before any commit, push, or pull request.

`coder` owns implementation, tests, and follow-up fixes. Before editing, `coder` checks the repository status and current branch, then creates and switches to a task-specific feature branch unless the mission names one. `coder` never implements directly on `main`, `master`, or another long-lived shared branch. If the working tree already has unrelated changes or branch creation would be unsafe, `coder` stops and asks instead of stashing, resetting, or overwriting anything. After the implementation and relevant checks pass, `coder` messages `reviewer` with the branch name, summary, changed files, and checks run. `reviewer` stays idle until that handoff, critiques the working-tree diff without editing it, and replies with must-fix findings first or a clean-review statement. The loop repeats until review is clean.

The human can write into the crew channel. When a message from `human` arrives, read it with `runner msg read` and reply to the channel with `runner msg post "<text>"` (no `--to` flag). All changes stay in the working tree unless the mission goal explicitly authorizes a specific git side effect. Never merge unless the human explicitly asks.
