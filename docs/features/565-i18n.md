# 565 — i18n: Runner's UI in the user's language, 简体中文 first

> Tracking issue: [#565](https://github.com/yicheng47/runner/issues/565)
> Priority: P2.
> Status: planned, design first for the Language row.
> Design: `design/runner.pen`, SETTINGS band: frames to draw before phase 1 — `Settings — General · Language (565)`, and one `Settings — 中文 (565)` frame rendering the General and Appearance pages in Chinese to check widths.

## Motivation

Every string Runner shows is an English literal. A survey on 2026-09-11 counted about 600 unique labels across `crates/runner-app`, 67 sentences composed with `format!`, six hard-coded `chrono` date patterns, a keymap table whose `title` and `description` are `&'static str`, and a macOS menu bar built from literals in `main.rs`. Nothing in the app crate knows what language the user reads.

The app has a Chinese audience it addresses only in English. The README runs a WeChat user group for 中文用户, release notes have shipped bilingual since v0.8.4, and the #539 pi spec exists because the Chinese dev community is building GUIs around that agent. The agents are fine in English: they coordinate in it, their prompts are written in it, and mixing languages into a launch prompt degrades them. The human at the cockpit is a different reader. Settings, the sidebar, the mission rail, the dialogs, and the shortcuts editor are the human's surface, and that surface should be readable in the human's language.

Jason chose the shape on 2026-09-11: English plus 简体中文 in the first version, app UI only, a hand-rolled catalog rather than Fluent (Chinese has no plural forms, so a plural engine buys nothing; hand-rolled beats a framework per the working rules), priority P2.

## Vocabulary

- **Source string** — the English text, written once in `en.toml`. English is the source language and the fallback.
- **Key** — a stable dotted id for one string, e.g. `settings.general.title`. Code references keys, never text.
- **Catalog** — one flat TOML file per language under `crates/runner-app/i18n/`, embedded at compile time.
- **Language setting** — `AppSettings.language`: `System`, `English`, or `简体中文`. What the user picks.
- **Active locale** — the resolved language the UI renders in right now: the setting, or the OS language when the setting is `System`.
- **Agent-facing text** — anything an agent reads: launch and system prompts, `runner` CLI output, bus messages, `mission_warning`, MCP tool names and descriptions. Stays English, out of scope.

## Scope

### In scope

- **The setting.** `AppSettings` gains `language: Language` with `#[serde(default)]`, where `Language` is `System` (default), `En`, `ZhHans`, serialized kebab-case (`system`, `en`, `zh-hans`) like `ThemeIntent`. Settings → General gets a **Language** row in the segmented style of `render_theme_segmented`: **System** / **English** / **简体中文**, with each language's name written in that language so a user who landed in the wrong one can still find their way out. The row sits directly under the page header, before the defaults.
- **Resolution.** `System` resolves through `sys_locale::get_locale()` (the crate is already in `Cargo.lock` via gpui's `cosmic-text`; it becomes a direct dependency of `runner-app`): a tag starting `zh` resolves to `zh-hans` (a Traditional reader is better served by Simplified than by English until a `zh-hant` catalog exists), anything else to `en`. Resolution happens at startup and when the setting changes; the OS language is not watched live (macOS relaunches apps on a language change anyway).
- **The catalog module.** `crates/runner-app/src/i18n.rs` owns `Locale` (`En`, `ZhHans`), a process-wide `AtomicU8` for the active locale with `set_active` / `active` mirroring `theme::ACTIVE_VARIANT`, and the parsed catalogs in a `OnceLock`. Catalogs are `include_str!("../i18n/en.toml")` and `include_str!("../i18n/zh-hans.toml")`, flat `key = "text"` TOML parsed with the `toml` crate into a `HashMap<&'static str, &'static str>` (leaked once at startup so lookups hand out `SharedString`s without copying). Three lookups: `t(key) -> SharedString` for a plain string; `tf(key, &[(name, value)])` substituting `{name}` placeholders; `tn(key, n)` picking `<key>.one` when `n == 1` and `<key>.other` otherwise, with the count available as `{n}` (Chinese catalogs write the same text in both). A key missing from the active catalog falls back to `en.toml`; a key missing from `en.toml` renders the key itself and logs a `tracing::warn!` once per key, so a typo is visible in the UI in development and never panics in a release.
- **Live switch.** Picking a language calls `i18n::set_active`, then `AppStore::locale_changed`, which bumps `revisions.shell_settings` and notifies the way `theme_changed` does, and `cx.refresh_windows()` so every open window re-renders. Because every `render` reads `t()` at render time, no surface caches text across the switch; the two places that build outside render, the macOS menu bar (`cx.set_menus` in `main.rs`) and the Windows title bar tooltips, are rebuilt from the same handler. Nothing requires a relaunch.
- **Extraction.** Every user-facing literal in `crates/runner-app` moves into `en.toml` and is read through `t` / `tf` / `tn`: the settings pages (`settings_page.rs` and every file under `settings/`), `sidebar.rs`, `panes.rs`, `chat.rs`, `start_chat.rs`, `start_mission.rs`, `runners.rs`, `crews.rs`, `mission_workspace.rs`, `update_dialog.rs`, `toast.rs` callers, `file_links.rs` labels, the `ConfirmDialog` and `ContextMenu` users, the macOS menu bar, and `platform_ui/windows.rs` tooltips. Keys are named by surface then element (`sidebar.section.projects`, `mission.rail.add_runner`, `settings.appearance.app_zoom.caption`). The 67 composed sentences go through `tf` with named placeholders so word order is the translator's to choose; the handful of English plurals (`{} runners`, `in {} crews`, `{} sessions`, `{} missions`) go through `tn`.
- **Keymap.** `KeymapEntry.title` and `description` stay `&'static str` but hold keys derived from the entry `id` (`keymap.<id>.title`, `keymap.<id>.description`), resolved with `t()` at the two render sites (the shortcuts editor and the #559 command palette). Palette matching runs over the resolved text, so a Chinese user searches in Chinese. The `id` never changes, so `keymap_overrides` on disk are untouched.
- **Enum labels.** The `label()` methods in `app_settings.rs` and `file_links.rs` split: labels that are words (`Auto`, `Block`, `Underline`, `Bar`, `Default app`) become keys; labels that are names (`JetBrains Mono`, `Catppuccin Mocha`, `Runner`, `Dawn`, `Claude Code`, `Codex`, `VS Code`) stay literal in every language.
- **Dates.** The six `chrono` patterns become catalog keys (`time.short`, `datetime.long`, …) so `en.toml` keeps `%-I:%M %p` and `zh-hans.toml` writes `%H:%M` and `%Y年%-m月%-d日`. The macOS `NSDateFormatter` path in `settings/archived.rs` follows the active locale by setting the formatter's `locale` from `Locale`, instead of the OS default, so the app stays internally consistent when the setting and the OS disagree.
- **Tests.** One catalog test in `i18n.rs`: every key in `en.toml` exists in every other catalog and vice versa, no duplicate keys, and each key's `{placeholder}` set is identical across catalogs. The 24 existing tests that assert on English copy (`panes.rs`, `settings/mcp.rs`, `mission_workspace.rs`, `sidebar.rs`, `settings/skills.rs`, `update_dialog.rs`, `mission_markdown.rs`, `crews.rs`) compare against `t("<key>")` rather than the literal, so they stay valid in both languages and pin the key, not the wording.
- **The translation.** `zh-hans.toml`, written in one pass against a glossary agreed before translation starts. Proposed glossary, to be signed off in phase 3: `Runner` (the product and the runner entity) and slot handles stay English; crew → 小队; mission → 任务; session → 会话; lead → 队长; worker → 队员; pane → 窗格; tab → 标签页; window → 窗口; chat → 对话; project → 项目; skills → 技能; agent → 智能体; runtime → 运行时; settings → 设置; archived → 已归档. Keyboard shortcut glyphs (⌘ ⇧ ⌥ ⌃) and the `Ctrl`/`Alt` words on Windows are not translated. Jason reviews the Chinese as a native reader before it ships.
- **CJK fit.** The UI font stacks in `platform_ui/fonts_macos.rs` and `fonts_windows.rs` gain an explicit CJK fallback (PingFang SC on macOS, Microsoft YaHei UI on Windows) so Chinese never falls through to a mismatched glyph. The narrow surfaces are checked at Chinese widths in the `Settings — 中文 (565)` frame and then in the app: the sidebar section headers, the segmented controls (three Chinese labels in the theme picker's width), the rail cards, the settings navigation column, and the button rows in dialogs. Chinese is usually shorter than English, so the risk is the other way: labels that looked balanced at English width look sparse. Fixes are per-surface, not a global font-size change.

### Out of scope

- **Agent-facing text.** Launch prompts and system-prompt composition (`crates/runner-backend/src/router/prompt.rs` and friends), `runner` CLI help and messages, the `runner` broadcasts and `mission_warning` texts, MCP tool names and descriptions. Agents coordinate in English; this stays a product decision, not a gap.
- **Backend error prose.** The roughly 166 `Error::msg` sites in `crates/runner-backend/src/ops` reach toasts and modals as English sentences and keep doing so. Translating them means an error-code layer between the backend and the app; not worth it for text most users see rarely. Revisit if a specific error becomes a recurring Chinese-user support question.
- **Terminal content.** Whatever the agent prints in its PTY is the agent's.
- **User-authored content.** Runner names, crew names, mission titles, slot handles, system prompts, and notes render as typed.
- **Other languages.** 繁體中文, 日本語, and anything else land as later `<tag>.toml` catalogs by PR; the module needs no change beyond a `Locale` variant and a `Language` option. No in-app translation editor, no crowd-sourcing platform.
- **The landing page (#468), the docs, and the README.** Separate surfaces with their own audiences.
- **RTL layout, number and currency formatting, per-window language.** None apply to the two languages in scope.

## Implementation Phases

### Phase 1 — design, then scaffold

- Draw `Settings — General · Language (565)` in `design/runner.pen` (the segmented row and its caption) and the `Settings — 中文 (565)` width-check frame; stop for sign-off.
- `crates/runner-app/Cargo.toml`: add `sys-locale` and `toml`. `crates/runner-app/i18n/en.toml` seeded with the Settings → General keys; `crates/runner-app/i18n/zh-hans.toml` with the same keys so the completeness test passes from the first commit.
- `crates/runner-app/src/i18n.rs`: `Locale`, `Language::resolve`, the active-locale atomic, catalog loading, `t` / `tf` / `tn`, the fallback and the once-per-key warning, the completeness test.
- `app_settings.rs`: `Language` and the `language` field with its default. `app_store.rs`: `locale_changed`. `settings_page.rs`: `set_language` and the row. `bootstrap.rs`: resolve and set the active locale before the first window opens.
- Tests: the settings round-trip with and without the `language` key on disk; `Language::resolve` for `zh-CN`, `zh-Hant-TW`, `en-US`, and a missing OS locale; the completeness test.

### Phase 2 — extract

- Sweep the surfaces one file per commit so each diff is reviewable: `settings_page.rs`, then `settings/*.rs`, `sidebar.rs`, `panes.rs`, `chat.rs`, `start_chat.rs`, `start_mission.rs`, `runners.rs`, `crews.rs`, `mission_workspace.rs`, `update_dialog.rs`, `file_links.rs`, the `ConfirmDialog` / `ContextMenu` / toast call sites, `main.rs` menus, `platform_ui/windows.rs`. Every literal that lands in `en.toml` lands in `zh-hans.toml` as the English text for now, so the app keeps building and the completeness test keeps passing; the real Chinese comes in phase 3.
- Composed strings through `tf`; the plural sites through `tn`; the six date patterns through catalog keys, and the `NSDateFormatter` locale in `settings/archived.rs`.
- `keymap.rs`: titles and descriptions keyed by id; the shortcuts editor and the palette resolve with `t()`.
- Enum `label()` split into keyed words and literal names.
- Menu bar rebuild on `locale_changed`.
- The 24 copy-asserting tests compare against `t("<key>")`.

### Phase 3 — translate

- Glossary sign-off (the proposed table above), then `zh-hans.toml` written in one pass, reviewed by Jason.
- CJK fallback in `fonts_macos.rs` and `fonts_windows.rs`; width fixes on the surfaces the 中文 frame flagged.

### Phase 4 — smoke

- Settings → General → Language: switch English → 简体中文 → System → English; every open window follows at once, the menu bar follows, no relaunch.
- Quit and relaunch: the choice persists; a settings file without the key loads as `System`.
- macOS System Settings → Language set to 简体中文 with the app on `System`: the app opens in Chinese; set back to English: it opens in English.
- Command palette (#559) and the shortcuts editor show Chinese titles and match Chinese queries; a rebound shortcut survives the switch.
- Archived chats and the updates page show Chinese date formats; times are `HH:MM`.
- No clipped or overflowing label on the sidebar, the settings navigation, the segmented controls, the rail, or any dialog at the default zoom and at the smallest zoom step.
- Windows nightly on JASONPC: title bar tooltips, the Windows updates page, and the CJK font.

## Verification

- [ ] `AppSettings.language` defaults to `system`, round-trips through `save` / `load`, and an older settings file without the key loads without error.
- [ ] `Language::resolve` maps `zh-CN`, `zh-SG`, and `zh-Hant-TW` to `zh-hans` and everything else, including no OS locale, to `en`.
- [ ] The catalog test passes: same key set in every catalog, no duplicates, identical placeholder sets per key.
- [ ] A key missing from the active catalog renders the English text; a key missing from `en.toml` renders the key and warns once, in debug and release alike, without panicking.
- [ ] No user-facing English literal remains in `crates/runner-app` outside `en.toml`, proper-noun labels, and tests (a grep for capitalised literals in render code is part of the phase-2 review, not a CI gate).
- [ ] Switching the language re-renders every open window, the macOS menu bar, and the Windows title bar without a relaunch.
- [ ] Keymap ids and `keymap_overrides` are unchanged; the palette matches on resolved Chinese titles.
- [ ] Dates and times follow the active locale, including the `NSDateFormatter` path on macOS.
- [ ] The UI font stack renders CJK on both platforms with no tofu and no fallback to a mismatched family.
- [ ] Agent-facing text, backend error prose, and terminal content are byte-identical before and after the change.
