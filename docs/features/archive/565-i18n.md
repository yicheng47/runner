## Motivation

Runner's human-facing interface is English-only. Add English and Simplified Chinese without changing agent coordination, terminal content, user-authored data, or saved command identities. Keep the implementation small: embedded TOML catalogs and a hand-written lookup layer.

## Scope

Add `AppSettings.language` with `System`, `English`, and `SimplifiedChinese`, serialized as `system`, `en`, and `zh-hans`. Existing settings without the field use `System`. Resolve Chinese OS locales to `zh-hans` and all others, including unavailable OS locale, to `en`. Use `sys-locale`, already in Cargo.lock, and verify its current macOS/Windows behavior instead of assuming region and preferred display language are equivalent. Explicit selection switches the complete UI live, across open windows, without restarting agents or losing input. Persist the chosen intent, not merely the resolved locale.

Language is the first row in the existing General settings card, with a dropdown and no separate section heading. This follows Jason’s final 2026-10-16 revision of frame DhOgA and supersedes the initial segmented control. Neighboring General settings retain their existing grouping, and Theme remains in Appearance. Show `System` / `English` / `简体中文` in English, and `跟随系统` / `English` / `简体中文` in Chinese. Autonyms keep both explicit choices recognizable. The helper sentence says that display-language changes apply immediately.

Embed flat `en.toml` and `zh-hans.toml` catalogs under `crates/runner-app/i18n/`, parse once, and expose `t(key) -> SharedString`, named-placeholder `tf`, and a small `tn` interface for English one/other forms. Use the existing process-wide theme selection as a pattern for active locale, while explicitly notifying every affected window/view and rebuilding values cached outside render. Missing keys fall back to English, then the visible key with a once-per-key warning. Formatting must preserve Unicode and insert argument values verbatim; an inserted value containing braces must not become a second template.

Extract all app-owned human-facing text: settings, sidebar, tabs/panes, chat, roles and crews, mission workspace/rail/feed chrome, start dialogs, forms/placeholders, alerts, toasts, human-facing desktop notification titles/bodies, update dialogs, macOS app menus, Windows titlebar tooltips, command palette, shortcut titles/descriptions, display enum labels, counts and date patterns. Inventory the current code rather than applying the issue's old module names or counts. Dynamic display text derived from core protocol enums should be translated at the app boundary, without changing shared/agent-facing label methods or protocol values. Proper names (Runner, runtime/model/font/theme names), user names/prompts, paths, identifiers, handles, terminal bytes and stored history remain intact.

Keymap entry IDs, action identities and persisted overrides stay unchanged. Displayed shortcut titles/descriptions are looked up by ID, and command searches match translated text. Rebuild menus and cached selector/field labels on a language change while preserving any user-entered draft and selection. Dates use catalog patterns; number formatting is outside this feature.

## Implementation phases

### Extraction and invalidation audit (2026-10-16)

The pinned `sys-locale` 0.3.2 uses `CFLocaleCopyPreferredLanguages` on macOS and `GetUserPreferredUILanguages(MUI_LANGUAGE_NAME, …)` on Windows. Both read preferred UI languages rather than the regional date/number locale. Runner will resolve the first preference on startup, when selecting System, and on window activation while System is selected. This does not subscribe to OS language-change notifications, and native OS-owned controls retain the OS's language. Sources: the locked crate's `src/apple.rs` and `src/windows.rs`, also published in the [crate source](https://docs.rs/crate/sys-locale/0.3.2/source/src/).

`AppStore` already has settings revisions and per-window observers. Language gets its own revision so every `NativeRoot`, `MissionWorkspace`, and mounted settings child can notify without reloading role/crew forms or applying terminal settings. `ShellSettingsSnapshot` must include language intent. Catalog activation and native menu rebuilding happen in the store's language-change path before observers run. Startup activates language before constructing fields or menus. Cached regions observe their owner and therefore follow owner notifications.

Metadata refresh must preserve the entities holding drafts, text selections, focus, selected option values, highlighted destinations, and open state. Audit the cached placeholders/options in SettingsState; start-chat/start-mission; role create/edit; crew create/editor/add-slot; mission add-role/attach; model fields; mounted settings search/editor panes; and the command palette. Use placeholder/option metadata setters or deferred catalog keys in existing widgets, never reconstruct whole forms. Command-palette refresh preserves the query and selected destination by stable identity. Existing stored toasts/confirmation copy also needs a locale-aware representation or refresh, with user/backend text kept literal.

Keymap entries keep stable IDs, action mapping, default combinations, scopes and serialized overrides; title/description catalog keys derive from entry IDs. Palette commands use those same display keys and include translated labels/descriptions in search while retaining English aliases. Protocol enum words are translated only in app presentation helpers. Runtime/model/font/theme proper names remain literal.

Formatter implementation will scan only the catalog template once, append named arguments verbatim, and leave unmatched placeholders visible. Catalog tests compare exact keys and placeholder sets and validate date patterns. English plurals choose `one` only for 1; Chinese uses its `other` form. Tests use explicit-locale lookup helpers and scoped thread-local overrides for UI assertions rather than changing the process-wide locale beneath unrelated parallel tests.
