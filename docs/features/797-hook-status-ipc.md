# 797 — Replace hook-status file feeds with local IPC

> Tracking issue: [#797](https://github.com/yicheng47/runner/issues/797)
> Priority: P2, 0.13.x (Jason, 2026-10-07: moved up to end the Windows Codex hook stall). Platforms: macOS and Windows.
> Status: implementation direction agreed on 2026-10-07. The crew must validate event projections, startup recovery and latency targets with the reviewer before switching hook registration.

## Motivation

Runner's native agent hooks currently report status through per-session NDJSON feeds and payload files. A short-lived reporter writes the event, and Runner watches and reads the files. This works for direct chats and missions, but carries file creation, watcher, partial-read, and cleanup machinery for live status delivery.

Replace this transport with a small Runner-owned local IPC callback while retaining native CLI hooks and the interactive PTY. Jason requested this direction during the runtime walkthrough on 2026-10-03 after reviewing cmux and Orca.

On Windows the hook path is also slow enough to feel. The 2026-10-06 PC regression (F6 in [the PC regression record](../tests/archive/2026-10-06-pc-full-regression.md#f6--windows-codex-hooks-delay-escape-and-startup)) found that Escape in a Codex chat visibly stalls with Runner's hooks on and is instant with `--disable hooks` or in a plain PowerShell outside Runner. The synchronous `Interrupt` hook makes this path directly relevant to cancellation; startup also runs a hook. A supplemental Windows PowerShell 5.1 fixture measured the current ScriptBlock reporter at median 313 ms and p95 322 ms across 30 samples, with about 140 ms spent starting an otherwise empty PowerShell. These are start-to-exit fixture measurements, not a captured native Codex cancellation timeline, and the fixture did not prove accepted delivery for every invocation.

## Windows: the shell floor

An IPC reporter alone does not remove the per-event shell launch. Codex 0.159.3 runs command hooks through the selected local shell, PowerShell on Windows with `cmd /C` as fallback, and never executes the command directly. A `runner hook report` command inside a command hook still pays that shell start. The PS5.1 fixture's native-helper startup proxy was about 150 ms; it was not an implemented IPC reporter. The shell actually selected by Codex must be captured in the before/after test.

Removing the shell on Windows needs a reporter that stays alive for the session. Codex 0.159.3 supports `mcp_tool` handlers for eight of the nine registered events: Codex starts a stdio MCP server once per session and sends those events as tool calls, with no process per event. SessionEnd rejects MCP handlers and uses a command reporter only at graceful teardown, as documented in the reviewed correction below. For Codex on Windows, the reporter is therefore a long-lived `runner` CLI mode (provisionally `runner hook serve`) that Codex launches as a per-invocation stdio server and that forwards each event to the same listener as `runner hook report`. It is a second entry into the one hook transport, not a separate status path, and it exposes no tools beyond hook admission. Agents still control Runner only through the CLI.

Two findings from the regression constrain it:

- **Root and child identity.** In Codex 0.159.3, `session_id` is shared by the root thread and all descendants and equals the root thread ID (`core/src/agent/control.rs`). The hook MCP executor attaches the concrete caller `threadId` in request `_meta` (`core/src/hook_mcp_executor.rs`), and the MCP client forwards it. The proposed root filter requires nonempty `_meta.threadId == payload.session_id`; it does not adopt the first caller as root or depend on seeing the first `SessionStart`. Reject a missing or different thread ID before changing status or conversation identity. Prove this relation for fresh, resumed, cleared and forked root conversations and for descendants against the supported Codex version.
- **Startup readiness.** Hook MCP calls do not wait for the server to be ready, so the first `SessionStart` can miss a slow reporter. Keep the server optional and recover identity from later validated root reports, as specified below. A short fatal startup timeout would turn a slow reporter into a failed Codex start and is rejected. Measure startup overhead against the first-spawn targets below.

Other runtimes keep command hooks on Windows unless they offer a similar long-lived handler: Claude Code runs its hooks under its own Git Bash, which starts in about 40 ms on the same PC, and pi reports from Node in-process. GitHub Copilot CLI uses the same per-event PowerShell reporter as Codex (inline in its plugin's `powershell` slot), so it likely pays the same cost per event; measure it and check whether Copilot offers a long-lived handler before deciding its Windows path. Check which shell Codex selects: the regression PC resolves `pwsh` to the Store PowerShell 7.6 as well as the legacy 5.1, and Codex prefers `pwsh` when it finds one, so measured costs there may be higher than the 5.1 numbers above.

## What cmux and Orca actually do

Read from local shallow clones on 2026-10-07: cmux at `06dfd2196cf01e7c59862c53b9572577e5612e3f`, Orca at `988f87e743ec52aa24ae1f25a308e66d6d8d2e59`. These are source findings; neither peer was launched or benchmarked on this PC.

| Project | Hook path | What it establishes for Runner |
| --- | --- | --- |
| cmux | macOS command hook → native `cmux hooks enqueue` → `agent.hook.enqueue` over its socket → app-owned ordered queue → neutral `{}` response | Admission can finish before downstream processing. The current policy bounds socket acknowledgment at 0.5 s and the whole CLI command at 2 s; these are limits, not measured normal latency. cmux is macOS-only and has no equivalent native Windows PowerShell path to copy. |
| Orca, native Windows Codex | Command hook → bare managed `.cmd` path or explicit `cmd.exe` → system `curl.exe` → authenticated local HTTP POST | Orca explicitly replaced its inner PowerShell POST helper because it cost about 300 ms per post and damaged UTF-8. Its command hook still runs inside Codex's selected outer shell. This reduces the interpreter chain but does not prove elimination of the PowerShell floor. |
| Orca, POSIX | Shell script → `curl` → local HTTP POST, with bounded connection/request time and a spool fallback | IPC and bounded failure are established patterns. Its endpoint file is reloaded on invocation so surviving sessions can reach the current server. |

Orca's Windows launcher utilities still contain PowerShell paths for other hook consumers. Its Codex reporter specifically uses `.cmd` and `curl.exe`; saying that all Orca hooks use PowerShell, or that its Codex hook starts no PowerShell at all, would both miss the outer-shell distinction. Its Windows contract tests invoke the managed command through PowerShell. cmux also retains spool paths, so neither peer is evidence that replacing all status files automatically solves cancellation latency.

For Runner, use the peers' quick admission and neutral response contracts. A native command reporter is a useful transport cleanup; the persistent Codex reporter is the proposed way to remove the per-event process launch that affects Escape.

## Implementation contract

### One daemon admission path, two reporter entries

MCP support and dependencies stay confined to the CLI hook adapter. `runner-core` and `runner-daemon` remain free of MCP dependencies and tool registries. The adapter admits hook telemetry only; it exposes no Runner session, mission, message or settings operations. This preserves #822's CLI and typed IPC architecture.

[#645](https://github.com/yicheng47/runner/issues/645) shipped in 0.13.0, so `runnerd` already owns sessions while the cockpit is closed. [#821 / PR #822](https://github.com/yicheng47/runner/pull/822) then moved the CLI to the typed daemon protocol and removed the daemon MCP service. Reuse that existing Unix socket / Windows named pipe and add a typed hook-admission request; do not restore the removed general MCP service. The small stdio MCP reporter is a Codex-facing adapter in the bundled CLI, separate from the daemon's transport.

- `runner hook report --runtime <runtime> --event <event>` consumes command-hook stdin and sends one report. Launch metadata supplies the exact daemon endpoint, Runner session ID and hook generation. Invoke the bundled executable by its resolved absolute path.
- `runner hook serve` stays alive as Codex's per-invocation stdio MCP server and forwards projected hook events to the same admission request. It exposes only the hook reporter operation. It starts through structured executable/argv configuration, without a shell wrapper.
- pi's existing in-process extension can use the same admission path without spawning a command for every event. Command-hook runtimes continue to use `hook report` until their native APIs offer an appropriate persistent path.

The envelope carries a version, runtime, Runner session ID, hook launch generation, event name, provider payload and, for MCP reports, caller thread identity. Runner's routing metadata comes from the launch, never from a provider's `session_id`, which is a conversation identity. Validate the runtime and generation against the live launch both before enqueue and before consumption, so an old queued event cannot affect a replacement process. Remove a launch's route and queue when it ends.

Admission places an immutable report in a bounded queue for that launch and replies immediately; parsing runtime records, reducer effects, database writes, router delivery and UI publication happen after admission. Preserve FIFO admission order per launch. Keep existing runtime interpretation and the #791 session reducer as the owners of status and conversation changes. Transcript/rollout readers remain where they supply information hooks do not contain.

### Delivery and failure contract

Hook reporters connect to the injected endpoint only. They must not use the ordinary CLI's auto-start/restart behavior or its ten-second request timeout. Apply a 250 ms total deadline across connect, handshake, write and admission acknowledgment; test the entire deadline, including the Windows pipe-busy case. Limit each serialized admission envelope to 8 MiB and each launch's queue to 64 reports or 16 MiB, whichever fills first. These are v1 bounds within the existing protocol's 64 MiB frame limit; confirm that retained large UTF-8 fixtures fit, and record any reviewer-approved adjustment in this spec.

Acknowledgment means queued in daemon memory, not durably stored or already applied. There is no disk spool or retry after an ambiguous write/acknowledgment timeout in v1. A lost event can reduce status fidelity; it must not be delivered late across a new turn or launch. A rejected current-launch report caused by queue exhaustion must mark that launch's bridge unavailable through the existing session-state path instead of silently presenting a healthy hook stream with a missing boundary. Test both queue bounds and the report-size boundary before switching producers.

Unavailable daemon, malformed input, stale launch, oversize report or admission timeout must return the provider's neutral hook result and must not block agent work. Keep diagnostics off hook stdout. A healthy stdio reporter returns successful MCP content containing the neutral JSON even when forwarding fails; stdout otherwise contains only MCP protocol messages. Provider-specific outputs, including Copilot's pre-tool response, must retain their existing meaning.

### Codex projections and startup readiness

Codex's MCP templates reject missing fields and have no whole-event placeholder. Generate a projection for each registered event using only fields guaranteed by that event's schema. Preserve `session_id`, `turn_id` where present, `transcript_path`, `SessionStart.source` and event-specific fields consumed by Runner; nullable transcript paths remain JSON null. Do not template optional `agent_id`. Apply the thread-identity filter above before passing a root report to the Codex parser.

Keep `--disable hooks`, `--disable=hooks`, `features.hooks=false` and explicit user hook configuration opt-outs. Install the reporter and hook definitions per invocation, without editing the user's global Codex configuration.

Use an optional MCP server (`required=false`) so failed or cold reporter startup cannot abort a Codex chat. A short fatal startup timeout is rejected. The server answers initialization without waiting for a daemon callback. Codex 0.159.3 calls hooks with `wait_for_server=false`, so an early `SessionStart` can still be missed. The first later validated root report must be able to capture conversation identity and attach its available transcript path without inventing a `SessionStart`. Keep status on the existing baseline/unavailable path until a valid turn boundary arrives; preserve the reducer's existing handling of an explicit interrupt. Do not infer a completed turn or replay missing events to hide a startup gap. Test missed starts for fresh, resumed, cleared and forked conversations, including a changed identity after an established conversation. Verify startup ordering and this recovery path before switching Windows registration; the reviewer must explicitly approve the method with `SPEC OK`.

### Performance acceptance targets

These are proposed acceptance targets, not measured results. On the regression PC, a warmed Codex stdio hook call through daemon admission should have p95 latency at or below 20 ms across at least 100 accepted reports, with no new shell or reporter process per event. Compare matched first-spawn runs with and without the helper: additional startup time should have median at or below 100 ms and p95 at or below 250 ms across at least 30 runs. Use fixture clients for the initial method review; record runtime versions, actual shell selection, process counts, delivery acknowledgments and distributions. A failed target requires reviewer-visible evidence and a spec decision, not silently relaxed expectations.

Fixture transport timings cannot establish physical Escape responsiveness. The fresh-build native Escape A/B remains a separate acceptance check that Jason must explicitly authorize or perform; mark it Incomplete until measured. Record command-hook runtimes' remaining shell cost separately from IPC admission latency.

### Migration boundaries

Fix Windows Codex first, then migrate the other producers through the same receiver. Audit Claude and pi's separate `session-keys` drop files as well as status feeds: their reporters also change conversation identity, and pi reports editor drafts. Carry those observations through the existing generation-guarded key/reducer path before retiring their file watcher. Preserve Copilot's permission/result correlation and Antigravity's currently supported platform set. Keep mission coordination `events.ndjson`, agent transcripts, rollouts and unrelated file watchers.

## Reviewed implementation decisions, 2026-10-07

Reviewer approved the method with `SPEC OK` in Runner message `01M4ANE2BT2VPGCZNR0NJXKJCG`; follow-up `01M4ANE9K7E8Z7YSYS21DC0317` supplies the reducer-reset and timing requirements. The source evidence and executable method fixtures are recorded in [the validation record](../tests/797-hook-status-ipc.md). Production code review remains a separate gate.

All platforms use the optional Codex server `runner_hooks`, with structured absolute `command`, `args=["hook","serve"]`, and explicit inherited endpoint/session/generation environment names. `required=false` is explicit; no short startup timeout is added. The eight MCP events project `hook_event_name`, `session_id`, and nullable `transcript_path`. SessionStart additionally projects `source`; the other MCP events project `turn_id`. No projection includes `agent_id`. SessionEnd uses the provider’s complete command payload and the narrowly checked root-only entry described below. Pinned Codex starts MCP initialization before hook dispatch but calls with `wait_for_server=false`, so this implementation explicitly tolerates a lost initial boundary.

A validated new identity without SessionStart clears both Codex parser state and the actual AgentModel turn, outcome, tool and interaction state. SessionModel publishes its existing baseline/unavailable fallback and disarms stale completion before any subsequent valid boundary is reduced. Identity and available transcript are captured independently. Explicit Interrupt retains interruption settlement. Delayed reports from retired identities cannot roll the current key backwards: A→B→A requires an explicit validated SessionStart for the intentional return. If that return's start is lost, the return remains rejected because its telemetry is indistinguishable from delayed A reports. This is an intentional fidelity limit, without replay or first-caller root adoption.

The 8 MiB envelope and 64-report/16 MiB queue bounds remain unchanged. The daemon limits hook request frames to envelope size plus 1 KiB of framing/typed-call allowance, then validates exact serialized envelope size. Admission acknowledgment releases a FIFO entry before the consumer can parse it. Teardown and replacement close the old queue; final status publication also checks the active launch token under the session-state lock.

Review correction approved in Runner message `01M4AS23GZYG9GS9RRGS4NJW27`: pi also latches failure when its local FIFO reaches either bound, suppresses unsent and later callbacks, and makes exactly one 250 ms control attempt outside that FIFO. The existing typed envelope carries a default-false `bridge_unavailable` field. Admission validates its envelope/runtime/session/generation/root identity normally, then clears and permanently fails the current receiver under the queue lock, even when the queue is full. Stale controls cannot fail a replacement launch. Notification is best effort if the transport is unavailable; pi remains latched and never retries ambiguous delivery or resumes telemetry across the lost boundary.

Identity-only Codex recovery releases terminal hook ownership as well as reducer ownership, allowing the existing native title baseline to continue. A recovery batch containing a valid turn boundary or explicit Interrupt still takes hook authority. This prevents byte-idle fallback from prematurely overriding a working title after a missed SessionStart.

Claude and Copilot keep their supported shell handler forms and invoke the bundled one-shot native reporter. Copilot's current documentation describes structured `exec`/`args`, but that form has not been proven for this machine's pinned 1.0.88 runtime; switching to it is outside this implementation. Its remaining shell startup cost is measured separately. Native Windows 1.0.88 validation captured projected `PreToolUse`/`PostToolUse` stdin naming the shell `Bash`, while `PermissionRequest` and transcript records use `powershell`; normalize both names to the same tool owner so approval and completion remain correlated. Preserve input matching and the existing reducer. Copilot and Claude preserve empty/default neutral output; Antigravity preserves `{}` and the PreInvocation workspace `injectSteps` object. Pi connects in-process through Node sockets/pipes and uses the same frames, admission deadline and no-replay rule.

Production hook status feeds, payload files and conversation-key drop watchers are retired. Retained file-transport helpers are test-only historical parity fixtures; they are not registered or reachable in a production build. The scenario corpus now enters through typed admission, including Claude/pi conversation keys and pi drafts. Mission logs, transcript/rollout readers and unrelated watchers remain in place.


### SessionEnd compatibility correction, 2026-10-07

F5 native Codex 0.160.1 rejects SessionEnd MCP hooks. The pinned 0.159.3 implementation also [rejects that handler kind](https://github.com/openai/codex/blob/01fc69f4026735edfdf6789820549727a4867b11/codex-rs/hooks/src/engine/discovery.rs), despite defining the event’s input schema. The initial schema audit missed this handler eligibility restriction. Reviewer approved the corrected method with `SPEC OK` in Runner messages `01M4B3J00TZ70M7E6RWNVZ3T7Z` and `01M4B3J0TFHN1CCKWZ7A15DYZ3`, after root-only and payload checks; method fixture review is `01M4B3JZWHF49QW1Y9CTF1NFK2`.

Keep SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, PreCompact, PostCompact, Stop and Interrupt on the optional persistent MCP adapter. SessionEnd alone invokes the existing absolute native `runner hook report --runtime codex --event SessionEnd` command with a one-second provider timeout. Codex runs it synchronously during graceful teardown, with a three-second maximum; it is an explicit one-shell/one-reporter exception to process-free MCP reporting. This exception does not change startup, turn or Escape handlers. Abrupt process termination may omit SessionEnd, and no missing event is synthesized. The reporter still bounds connect/handshake/write/ack to 250 ms and returns neutral `{}` on failure.

Pinned [root teardown dispatch](https://github.com/openai/codex/blob/01fc69f4026735edfdf6789820549727a4867b11/codex-rs/core/src/hook_runtime.rs) excludes every SubAgent source before emitting SessionEnd. Its [command payload](https://github.com/openai/codex/blob/01fc69f4026735edfdf6789820549727a4867b11/codex-rs/hooks/src/events/session_end.rs) guarantees `session_id`, nullable `transcript_path`, `cwd`, `hook_event_name=SessionEnd` and `reason=other`. Only the CLI command entry may derive its caller identity from this proven root-only event: require exact requested/payload event, nonempty session ID and cwd, present string/null transcript, reason `other`, and absent `agent_id`/`agent_type`, including null metadata. Ordinary Codex command events remain invalid. Every MCP report still requires actual nonempty `_meta.threadId == payload.session_id`, including SessionEnd if submitted through MCP. Core/daemon validation, generation guards, FIFO admission and retirement remain unchanged. Do not adopt the first caller or relax descendant rejection.

## Scope

- Add a hook-reporting CLI entry point, provisionally `runner hook report`, that reads the provider payload from stdin and sends it to a local listener.
- Reuse Runner's Unix-socket / Windows-named-pipe infrastructure and typed daemon request protocol; the former daemon MCP service was removed by #822.
- Carry runtime, Runner session identity, launch generation, event name, and provider payload. Preserve stale-generation rejection and runtime-specific interpretation through the session-state boundary in #791.
- Acknowledge admission promptly and process events in a daemon-owned queue. Bound reporter execution and preserve each provider's neutral hook response so telemetry does not interrupt the agent.
- Cover existing hook-status producers on macOS and Windows. Audit reporters that also emit conversation identity before retiring their file path.
- On Windows, register Codex hooks as `mcp_tool` handlers against the long-lived reporter described in Windows: the shell floor, with `threadId`-based child filtering and a stated startup-readiness policy. Keep the `--disable hooks` and `features.hooks=false` opt-outs.
- Keep listener ownership in the shipped `runnerd`, available when the cockpit closes. This is 0.13.x follow-through, not a new #645 release gate.
- Keep mission coordination logs separate from this status-transport change. No vendor app-server protocol or replacement of the interactive CLI is in scope.

## Implementation phases

1. Validate the Windows Codex method: complete event projections, root/child filtering, optional-server startup recovery and measured latency budgets. Use fixture reporters first; a live runtime smoke test needs explicit authorization under `AGENTS.md`.
2. Add shared daemon admission and the two CLI reporter entries, then switch Windows Codex. Compare accepted before/after events and process creation, followed by a fresh-build native Escape A/B.
3. Migrate macOS Codex, Claude, Copilot, pi and supported Antigravity hooks, including conversation and draft observations. Retire superseded feed, payload-file, rekey-drop and watcher machinery only after parity is established.

## Verification

- Hook-derived status and conversation identity behave consistently in direct chats and missions; shell sessions do not require this channel.
- Concurrent sessions route events correctly, stale launch generations are rejected, and event ordering preserves turn boundaries.
- An unavailable or restarting listener, pipe-busy condition, lost acknowledgment, the 8 MiB envelope boundary and either queue bound stay within the 250 ms reporter deadline and preserve the agent's neutral result. Verify the stated event-loss contract and bridge-unavailable behavior.
- macOS shell reporters and Windows reporters both deliver through local IPC.
- On Windows, a Codex chat with hooks on shows no visible Escape difference from one started with `--disable hooks`. Measure warm per-event latency and first-spawn delta against the targets above, and prove from process creation that no shell starts per Codex MCP event; record the separate graceful SessionEnd command exception. The fresh-build native A/B is required for full acceptance; absent live authorization or evidence remains an explicit Incomplete row in the PR.
- Missing `_meta.threadId` and a child's tool or `UserPromptSubmit` event cannot change root status or conversation identity. Cover child lifecycle callbacks, rejected child reports arriving first, resume, `/clear`, fork and a missed initial `SessionStart`.
- Replay the existing status fixtures through admitted reports and compare status/key timelines. Preserve tool correlation, compaction, interruption settlement, permission prompts, pi editor drafts and large non-ASCII payloads.
- Session-host operation keeps reporting while the cockpit is closed and reconciles status on reattach.
