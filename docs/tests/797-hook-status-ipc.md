## Proposed implementation method for review

1. Add a versioned `HookReport` and typed admission request in runner-core's existing protocol. The CLI gets a connect-only, deadline-bound exchange using the injected endpoint, Runner session ID and generation, without ordinary CLI startup/probe calls. A single 250 ms deadline covers connect, handshake, request write and acknowledgment, including pipe busy. MCP JSON-RPC stays exclusively in the CLI adapter; initialize/list/ping require no daemon. Successful hook tool replies always contain neutral `{}` even on delivery failure. One-shot report preserves Copilot's pre-tool neutral result.
2. Register a bounded queue for each runtime launch before starting its process. Admission checks runtime, Runner identity, generation, envelope size and Codex caller identity, then enqueues immutable reports under a short queue lock. The acknowledgment is independent of parser/reducer/database/UI work. Preserve FIFO under concurrent producers. The existing status consumer owns interpretation; it rechecks route liveness/generation before consumption. Teardown retires and clears the route; a replaced launch cannot consume old work. Overflow of either 64 reports or 16 MiB fails the bridge through the existing StatusBridgeFailed path and invalidates remaining queued telemetry, rather than applying a later completion after a lost boundary. No spool or delivery retry.
3. Codex recovery runs only after caller validation. A new valid identity captures its key and available transcript and clears previous parser turn state; it does not emit StartupReady. Unknown Stop/tool/compaction/end reports cannot infer a completed turn. Until a valid UserPromptSubmit boundary the current baseline/unavailable behavior remains; an explicit Interrupt retains the existing interrupted/unavailable path and correlated transcript settlement. Remember retired identities within the launch so delayed old reports cannot roll identity back; an explicit SessionStart remains the intentional handover/resume boundary. Test this through the real reducer, including initially missing SessionStart and changed identity.
4. Generate per-invocation Codex `mcp_tool` handlers for all nine events and a structured absolute executable plus argv server definition, optional `required=false`, with ordinary nonfatal startup behavior. Preserve all existing hook opt-outs and explicit user configuration. First switch Windows Codex after the fixture/adapter gate, then other Codex, Claude, Copilot, pi and supported Antigravity producers. Keep pi in-process using Node's socket/pipe support and the same typed frames/admission acknowledgment; serialize its callbacks to preserve order. Preserve conversation keys and editor drafts before removing feed/payload/rekey machinery. Retain transcript, rollout and mission event-log readers.
