## Coverage boundary

On macOS, fresh and resumed Runner-spawned Codex sessions receive additive invocation hooks: SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, PreCompact, PostCompact, Stop, Interrupt and SessionEnd. Their short observer command consumes stdin, emits `{}`, exits zero, and has a two-second CLI timeout. No permission decisions, input rewrites, persistent hook/trust entries, CODEX_HOME mirror, authentication edits or conversation edits are added. The invocation trust-bypass flag also applies to hooks supplied by trusted project/repository configuration. New or changed hook definitions from those layers run without the usual per-hook review; project trust still controls whether project layers load. Codex displays its normal warning. `--enable hooks` overrides a stored `features.hooks=false` for this invocation; use explicit runner arguments `--disable hooks` or `-c features.hooks=false` to opt out. No stored setting is rewritten. These flags are verified on 0.154.0; a future CLI removing them requires an adapter update.

UserPromptSubmit establishes Working. Current-turn tool/compaction work can restore Working after a continued Stop. Stop establishes Idle/Completed, while late tool results cannot override completion. SessionStart alone proves no activity. A native Interrupt records Interrupted and Status unavailable until the matching rollout turn_aborted establishes Idle; it never creates successful-completion attention. Old generations, other-session work/end events, retired turns, child hooks and late results cannot take ownership. Root SessionStart is the authoritative navigation boundary, independent of its source string; it also permits returning to a previously visited conversation. Explicit feed/helper loss releases the hook latch and uses the existing estimated baseline. Silent tools do not time out the status.

**Codex Approval needed, Answer needed, and human-dialog delivery protection are unsupported in this slice.** Native fixtures prove that raw PermissionRequest and even PreToolUse(request_user_input) plus a Plan-mode rollout call can precede automatic handling/rejection without a human dialog. No elapsed-time assumption closes that gap. Real Codex dialogs can therefore still consume a crew nudge; do not interpret Working or this smoke test as proof of safe delivery while such a dialog is open. The independent typed-draft/recent-typing gates remain. Claude follows its existing early question/plan policy and now also raises matched command approvals immediately; see the [Claude checklist](347-status-ui-smoke.md). Nonblocking Codex question attention, fatal-turn failure classification, Windows status-hook integration, TRAE and title-spinner removal remain outside this slice.
