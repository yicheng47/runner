## Coverage boundary

On macOS, Runner regenerates `<app data>/copilot-hooks/` at startup and adds `--plugin-dir <app data>/copilot-hooks` to every Copilot invocation, even when the runner already supplies another plugin directory. The plugin inherits `RUNNER_COPILOT_STATUS_PATH` and `RUNNER_COPILOT_STATUS_GENERATION`; its two-second command reporter silently spools stdin through the shared side-file feed and exits zero. No hook, setting, trust entry, authentication file, or session record under `~/.copilot` is installed, edited, or deleted by the adapter.

UserPromptSubmit, PreToolUse, PostToolUse, PostToolUseFailure, and PreCompact establish Working. `Stop(stop_reason=end_turn)` establishes Idle/Completed and following work corrects a continued stop. `Notification(agent_idle)` is secondary confirmation. Root SessionStart owns the session/generation, including `source: new | resume`; a delayed same-session SessionStart cannot overwrite work because live 1.0.83 appended UserPromptSubmit first in these probes. SessionEnd ends ownership. SubagentStart/SubagentStop never change the main agent. Escape/Ctrl+C use Runner's existing input signal; an unresolved interaction remains held until its owning hook or transcript completion clears it.

PermissionRequest alone never raises attention. A matching `Notification(permission_prompt)` raises Approval needed against the pending PreToolUse. PermissionRequest correlation may use the unique pending canonical-name fallback because the live Edit request's `{file_path,diff}` differs from the raw patch-string PreToolUse input; transcript correlation never uses that fallback and requires canonical name plus exact structured input. `PreToolUse(AskUserQuestion)` raises Answer needed immediately and `Notification(elicitation_dialog)` confirms that same interaction. Owning PostToolUse/PostToolUseFailure or transcript `tool.execution_complete` clears the wait. Only these unresolved interactions add the existing normalized crew-delivery hold; Working, Idle, bridge loss, and estimated baseline status do not.

`ErrorOccurred(recoverable=false,error_context=model_call)` remains intentionally unmapped: no real fatal model-call payload was captured, so this mission does not guess Response failed. Windows, tool/compaction detail labels, Copilot controls inside Runner, and changes to Claude/Codex semantics are outside scope.

## Live PTY evidence

The probes ran the installed CLI in a real `pty.fork` session from a trusted working directory with a scratch plugin under `/tmp/runner-copilot-hook-probe.mTuNqg`. Its `hooks/hooks.json` used the shipped Notification matcher `^(permission_prompt|elicitation_dialog|agent_idle)$`; Copilot 1.0.83 invoked the reporter for both observed matching types, including two `permission_prompt` records and one `elicitation_dialog`, so the matcher neither rejected the entry nor interpreted those values as tool names. Each child exited through `/exit` or the driver's bounded master-close/SIGKILL fallback; a final process check found no survivor. The probe did not write user hook/settings/config files and did not remove anything under `~/.copilot/session-state`. Full payloads remain local; the code tests retain only the sanitized structural fields needed by the adapter.

## Jason's manual smoke checklist

1. Open a fresh Copilot direct chat on macOS in Default mode. Submit a short prompt, confirm Working has no estimated tooltip, then confirm normal completion becomes Idle. Stop/resume it and confirm the original conversation returns, the first turn is not replayed, and the next turn still moves Working → Idle.
2. Ask Copilot to run `echo runner-copilot-auto`. Confirm it auto-approves without ever showing Runner's Approval needed. The raw request must not hold delivery.
3. Ask Copilot to create a disposable file with the Edit tool. While Copilot's permission dialog is visibly open, confirm Runner shows Approval needed. Press Enter; confirm it clears to Working before the final Idle. Repeated path/edit notifications must still show one wait.
4. Ask Copilot to use `ask_user`. Confirm Answer needed appears as the question opens. Answer it and confirm Working resumes, then Idle. Repeat and cancel with Escape; the wait must persist only until the correlated transcript completion, finish Idle/Interrupted without a completion dot, and accept the next prompt normally.
5. In a real crew with a Copilot slot, post a message while it is Working and again while Idle; both nudges remain eligible. Open an Edit approval or ask_user dialog, post another message, and confirm the delivery is held until the dialog resolves. Type an unrelated unsent draft at the normal prompt and confirm the independent draft gate still protects it.
6. Configure a disposable repository with `.github/copilot/settings.local.json` containing `{"disableAllHooks":true}`. Start Copilot there and confirm status is estimated rather than hook-confirmed. Remove that disposable override outside Runner, start another session, and confirm hook status returns. Do not change the user-level `~/.copilot/settings.json` for this test.
7. Give a runner its own `--plugin-dir` and confirm both it and Runner's status plugin execute. Remove or make unavailable only the Runner-owned reporter in a disposable app-data copy and confirm terminal use continues on estimated status with no manufactured completion.
8. Spot-check the same state in a single-pane tab, split-pane header, collapsed sidebar, and mission card/tab/row. On Windows, confirm Copilot receives no Runner status plugin/env and continues to show estimated status.
