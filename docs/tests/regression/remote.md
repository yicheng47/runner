# Remote access

These cases need two computers, preferably one macOS and one Windows, signed in to the same hosted-service account, which needs an invite. `account` in Needs means that hosted account, not an agent account. Run each case from both directions where Platform is `both`, swapping which computer is the client and which is the host. Crew slots never read a secret store or touch pre-existing production computers; when no second physical development host is available on macOS, QA may spin up two isolated private-`HOME` wrappers on the same Mac using Chrome's existing signed-in account under the [same-Mac two-host relay fixture](../full-smoke-test.md#same-mac-two-host-relay-fixture-macos) rules, strictly cleaning up and revoking only its disposable enrollments afterward. Use the development app or candidate builds on both computers, and never Reset, Revoke or Forget pairings the run did not create.

Current authority: the [remote access guide](../../guide/guides/remote-access.md), the [machinery walkthrough](../../tech/remote-control.md), the daemon's [remote module](../../../crates/runner-daemon/src/remote), the [client surfaces](../../../crates/runner-app/src/surfaces/remote_client), [Settings → Remote access](../../../crates/runner-app/src/surfaces/settings/remote.rs) and the [CLI](../../../crates/runner-cli/src/remote.rs). The [spec](../../features/archive/836-web-remote-control.md) and the [#836 records](../archive/836-release-checks.md) are history.
