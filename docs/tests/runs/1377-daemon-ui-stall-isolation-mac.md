### Reproduction details

1. In either client-side remote terminal, start `cat > receiver.txt`, press Return, then paste `QA1377 中文 é 😀` as the next native action. Press Return and Ctrl+D. The expected file is `51413133373720e4b8ade696872065cc8120f09f98800a` in hex. Both rapid attempts added a leading `1b5b3230307e` and inserted `1b5b3230317e` before the newline. Waiting for the foreground receiver before pasting produced exact bytes. The logs and screenshots establish the symptom. A stale bracketed-paste mode is a hypothesis, with no baseline binary comparison.
2. In the candidate's development app, open a standalone zsh tab, then type `exit` at its prompt. If a previous tab is open, it becomes the selected route. The deleted shell ID still appears in a persistent red `direct chat not found` banner. The string is emitted by `ensure_attached` in `crates/runner-app/src/surfaces/chat/attachment.rs:120–123`. The behavior also occurred without any relay setup. A baseline binary comparison was not run.
