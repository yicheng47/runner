## Implementation verification

The session layer owns one `TerminalModel` per live session and a per-session input worker. `runner-terminal` depends on `runner-core`, with no backend dependency, including dev dependencies; the backend implements the small host trait. Both model and mirror call the same parse function. The model alone scans scheme queries/OSC 7, records fixtures, derives input observations and answers PTY queries. Mirrors keep display, selection, scroll and encoding. `SessionEvents::output` is removed; a 64-frame bounded subscription connects `DaemonClient::attach` to the mirror. Overflow replaces queued frames with `Resync`, removes that subscriber and requires a fresh attach snapshot.

The existing per-session state mutex covers sequence assignment, frame push and model parse in that order; attach serializes and subscribes under that mutex. Input observations publish after releasing it to avoid recursively taking the same state lock. Resize updates the originating mirror immediately, then synchronously performs the existing in-process PTY call and sends sequenced `Resized` frames to the other subscribers. Existing 175 ms resize persistence coalescing is retained. All sessions queue UI bytes with the existing `inject_direct_stdin` semantics; worker failures retain `session/input-error`. Direct-chat subscriptions display matching errors in the active tab (including its split panes and drawer); the update modal displays matching errors in its running footer through the existing exit-event receiver. The update modal prepares its unlisted terminal, attaches by id before launching, and subscribes to exit events before preparation.

Calls retain their original threads: model construction and initial DB/title/cwd reads run on spawn/resume or the modal's existing background start thread; output parsing and input-state observations run on the existing output forwarder; title persistence and query writes run on the existing terminal event worker; configuration, palette, key encoding/input observation, lazy link-cwd DB lookup and PTY resize remain on their prior calling threads. A weak terminal lifecycle observer in the in-process transport invokes mirror spawn/exit/title handling synchronously on those original callers; it does not add a lifecycle ordering queue. Shell titles notify only that observer, preserving the prior transient-title behavior without adding `session/updated` to the app event stream; the existing shell-title test now verifies mirror refresh, one wake, no persisted title and no app event. Only the required per-session input worker and per-subscriber frame receiver are new workers. Draw reads the mirror and cached metadata. In-memory metadata/configuration/palette/input-tracker requests are `fast`; the link-cwd fallback still reads SQLite lazily on first link lookup.

Snapshot gates cover all 19 recordings (14 original plus five Stage 0 captures), at every Data chunk boundary and 200 xorshift-generated offsets per recording, seed `0x6451b`, including offset 0 and end. Deduplication yields 5,793 tested positions; `/tmp/645-m2-split-coverage.json` lists counts per recording. Small recordings naturally have fewer than 200 distinct random positions. Each split compares the original and restored state immediately after snapshot replay, before feeding any suffix, and again at the end of the recording, following Jason’s addition in `01M45YAGER87K1D9W96Q95R053`. Comparisons check every logical grid/history cell's character, colours, flags, zero-width marks and underline colour; current/saved cursor, modes, primary grid when alternate is active, inactive saved cursor, scroll region, title/title stack, tabs, both kitty stacks, optional cursor style and active charset. They normalize an absent zero-width list and an empty list, and deliberately exclude OSC 8 hyperlink metadata. Synthetic tests additionally cover every byte of a mode/kitty/charset/synchronized sequence, saved alternate cursor continuation while attached on primary, and resize during a partial sequence or held update. The review regressions cover default/custom tabstops, a tab at the right margin, styled tab cells and tabbed history; REP after printing, cursor moves, charset changes, erase and held updates; and LF, CR, BS and HT in unfinished ESC/intermediate, CSI, OSC, DCS header/string/terminator, SOS/PM/APC and synchronized CSI sequences. They compare immediate state and continuation at every byte, preserving actual tab cells rather than normalizing them. No serializer snapshot golden is added; Stage 0 screen snapshots are only 25–39 lines each. A byte-for-byte check against HEAD confirms all 36 original terminal fixture files are unchanged.

The fixture schema now accepts and records backward-compatible `Resize` events, and replay retains one parser across those events. Stage 0's raw streams and frozen snapshots are unchanged, so their documented lack of exact resize ordering remains a corpus limit; synthetic resize tests provide deterministic ordering coverage. Existing input-state goldens and all 36 original fixture files are unchanged. Backend-dependent terminal tests moved to the backend with a synchronous model/mirror test facade; independent seam tests exercise actual subscriptions and workers. Headless session tests now account for the model's initial observed idle state, which the old app terminal already supplied; the input reducer and its frozen expectations are unchanged. The native wheel test waits for queued writes before asserting the same encoded bytes and geometry.
