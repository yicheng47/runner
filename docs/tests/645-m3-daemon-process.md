## Implementation

The existing CLI sidecar dispatches as `runnerd` by executable stem and is installed as both `runner` and `runnerd`. The daemon owns the database, managers, authoritative terminals, router mounting, stale-row and orphan cleanup, resume claims, discovery/usage and MCP. The app's normal dependency graph ends at `runner-core` and `runner-terminal`; backend access remains a dev dependency for in-process tests. Existing terminal snapshot, parser and split-point tests are unchanged.

The app uses one reader and writer per local socket connection, request IDs with independent replies, binary terminal chunks capped at 64 KiB, bounded event/terminal queues, and the existing `Resync` attach path. Synchronous requests remain on their existing threads and have a 10-second client deadline. A separate lifecycle thread avoids calling attach from the socket reader. Reconnect cancels the active subscription to wake and join the old mirror frame worker before replacing its snapshot, including when Resync has already replaced the subscription, replays terminal palette and window ownership, refreshes the store, and attaches all live sessions. The disconnect notice survives refresh failures and increments the existing error revision; reconnect clears it. It permits three restarts in a rolling five-minute window; the next disconnect stops recovery and shows the `runnerd.log` path.

App and CLI starters serialize using `runnerd-start.lock`. The daemon separately owns `runnerd.lock`; a second daemon starter exits 0. A mismatch is handled under the startup lock in the required order: stop, wait for the daemon lock, install, spawn and handshake. Installation compares contents rather than trusting size/mtime and skips replacing a locked daemon and its ConPTY companions. Detached starts strip `RUNNER_*` and Runner bin/mission PATH entries, use null stdio and home cwd, `setsid` on Unix, and the specified Windows flags and breakaway refusal behavior.

Socket window mutations carry connection ownership. Only the in-memory window mutation is locked; SQLite work runs outside that lock, and node activation rechecks ownership after its database operation. Disconnect marks that connection closed before cleanup, unregisters only its labels and broadcasts the focus map; a mutation already running finishes before cleanup, while queued requests cannot recreate dead windows or modify a label registered by another client. Both sockets have mode 0600 on Unix. Both Windows listeners receive an explicit protected DACL granting the actual process-token user SID access and reject remote clients. Every two seconds the daemon checks both Unix device/inode identities or its retained Windows server-pipe handles. A replacement takes the same shutdown path; cleanup removes only the daemon's own Unix files.

## Shutdown and #709 obligation

All explicit Stop Sessions frames, CLI daemon stop, Unix SIGTERM and Windows close/logoff/shutdown events use one path: drop the daemon listener and stop accepting MCP clients; disable polling/cancel connections; stop the startup resume consumer and quiesce its current claim; block further PTY spawns; stamp running rows for resume; cancel pending spawns and `kill_many` (including live sessions without rows); drain/join input, model event/sync, Claude session-key and PTY reader/monitor workers; stop MCP; remove owned socket files; release `runnerd.lock`; exit. Quit sends the frame and waits up to 10 seconds for the daemon lock to be released.

The session teardown task, including resume-consumer quiescence, has an 8-second deadline. The claim/take/resume/finish step is serialized with stop so no claim can be taken after shutdown stamps the rows. Pending claims remain queued; a stuck claimed row is requeued by the existing next-boot cleanup. The app no longer starts a separate startup claim consumer. On a missed deadline it logs the failure, proceeds to endpoint cleanup, and exits; OS process teardown closes remaining PTYs and Windows kill-on-close job handles. The resume task gets at most one additional second, and the Tokio runtime gets a one-second shutdown timeout. A stuck blocking worker cannot extend process lifetime indefinitely. SIGKILL cannot stamp resume; the next boot's existing stale-row cleanup demotes those rows. Tests verify that the shell child disappears on ordinary shutdown, SIGTERM and forced daemon death.
