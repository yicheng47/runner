# #1292 — Antigravity CLI title probes

Preserved from the [feature spec shipped in 0.19.9](https://github.com/yicheng47/runner/blob/v0.19.9/docs/features/1292-antigravity-session-title.md#problem). The original record identifies real-PTY probes of installed `agy 1.5.8` but supplies no separate probe date, candidate SHA or screenshot paths. These observations are provider investigation evidence, not a current Runner or cross-platform QA pass. The dated Runner failures, correction and native rerun remain in the [2026-11-13 run](../runs/2026-11-13-mac.md#1292-antigravity-session-titles--macos-qa-2026-11-13).

- `agy` resolves the `title` command hook from `~/.gemini/antigravity-cli/settings.json`, with top-level keys overridden by CLI `--settings`. Multiple settings flags replace the whole object rather than merge it; Go flag parsing accepts `-settings`, `--settings`, `-settings=...` and `--settings=...`.
- An enabled command hook receives a JSON payload on stdin including cwd, session/conversation identity, product and, once available, `conversation_title`. The implementation invokes `sh -c` on Unix and `cmd /c` on Windows; the original real-PTY record does not establish native Windows execution.
- Nonempty hook stdout becomes OSC 2. Empty stdout, a missing executable or nonzero exit emits no title or stderr noise. Whitespace-only stdout still becomes a whitespace title, so Runner trims and suppresses it.
- In 1.5.8, background first-turn naming writes `conversation_summaries.db` and broadcasts a summary, but `applySubagentSummaries` skips the current conversation without updating its in-memory title or notifying the store. The title hook fires on `/rename` and conversation resume; first-turn automatic naming needs Runner's read-only summary lookup. Current implementation and safety boundaries are documented in the [architecture](../../arch/arch.md#510-busy--idle-inference).
