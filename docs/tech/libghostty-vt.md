# libghostty-vt: the terminal engine behind runner-terminal

Written against Ghostty `libghostty-vt` `vt-1.0.2` (commit `573c4a21e02311ae87844af26b6a7a179f82858e`, MIT), built with Zig `0.17.0` via `crates/ghostty-vt-sys` and wrapped inside `crates/runner-terminal/src/vt/`. Source lives vendored in `vendor/libghostty-vt/` (provenance and SHA-256 digests in [`vendor/libghostty-vt.vendor.json`](../../vendor/libghostty-vt.vendor.json)) with tracked local patches in [`vendor/libghostty-vt.patches.md`](../../vendor/libghostty-vt.patches.md).

Ghostty the app is a native terminal emulator; `libghostty-vt` is its VT state machine, page-based screen storage, render state, search, selection, formatter, snapshot encoder/decoder, and input encoders packaged as a C library without a window, renderer, or PTY. Runner links only the static library (`libghostty-vt.a` / `ghostty-vt.lib`) and keeps every C handle strictly behind `crates/runner-terminal` so neither `runner-daemon`, `runner-app`, nor `runner-cli` ever sees a Ghostty type.

## Build, vendoring, and offline cache

`crates/ghostty-vt-sys/build.rs` compiles `vendor/libghostty-vt` with Zig `0.17.0` (`ZIG` env var overrides `PATH`) using `zig build -Demit-lib-vt -Demit-xcframework=false -Doptimize=ReleaseFast -Dtarget=<zig-target>` and generates Rust FFI bindings from `vendor/libghostty-vt/include/ghostty/vt.h` with `bindgen` (`ghostty_.*`, `Ghostty.*`, `GHOSTTY_.*`). Every Rust target maps to an explicit Zig target (`aarch64-macos.12.0`, `x86_64-macos.12.0`, `x86_64-windows-msvc`, `x86_64-linux-gnu`, `aarch64-linux-gnu`) so Zig never emits instructions for the build machine's newest CPU and macOS bundles keep their `12.0` minimum OS floor.

Zig's five external packages (`aro`, `highway`, `translate_c`, `uucode`, `wuffs`) stay out of git in a shared per-user offline `--system` directory (`${XDG_CACHE_HOME:-$HOME/.cache}/runner/libghostty-vt-deps/1.0.2-c56156db` on Unix, `%LOCALAPPDATA%\runner\libghostty-vt-deps\1.0.2-c56156db` on Windows, overridable via `LIBGHOSTTY_VT_ZIG_SYSTEM_DIR`). Run `make ghostty-deps` (`python3 script/fetch-libghostty-vt-deps.py`) once per machine to fetch and SHA-256-verify Ghostty's `libghostty-vt-1.0.2-deps.tar.gz` archive; CI caches the same directory. Each worktree places its Zig build cache inside its own `target/<profile>/ghostty-vt-zig-cache/` so concurrent `.worktrees/` never contend on locks.

Runner keeps four small, tracked local patches on top of `vt-1.0.2`, documented with removal criteria in [`vendor/libghostty-vt.patches.md`](../../vendor/libghostty-vt.patches.md): preserving explicit `-Dtarget=*-macos.<ver>` minimum OS versions in `src/build/Config.zig`, exposing already-parsed `CSI 22 t` / `CSI 23 t` title push/pop actions as effect callbacks, exposing read-only per-screen upward scroll counts and reset generations (`GHOSTTY_TERMINAL_DATA_SCROLL_UP_ROWS` / `SCREEN_GENERATION`) without altering `ScreenSet.generations`, and exposing the read-only duplicate `DECSET ?2026` reopen counter (`GHOSTTY_TERMINAL_DATA_SYNC_HOLD_REOPENS`).

## Safe wrapper and `!Send`/`!Sync` actor ownership

`crates/runner-terminal/src/vt/` wraps the raw C handles (`Terminal`, `RenderState`, `GridRef`, `TrackedGridRef`, `Selection`, `KeyEncoder`, `MouseEncoder`, `Decoder`) in safe Rust types that carry `PhantomData<*mut ()>` so the compiler enforces `!Send` and `!Sync` with zero `unsafe impl Send` or `unsafe impl Sync`. One-time initialization (`sys.h`, guarded by `std::sync::Once`) installs Runner's PNG decoder callback (backed by the `png` crate) and routes Ghostty's internal diagnostics into `tracing`.

Because handles cannot move across threads, Runner replaces the old `FairMutex<Term>` design with single-owner actor threads on both sides:

- **`TerminalModel` (in `runnerd`, `crates/runner-terminal/src/terminal/model.rs`):** one single-owner VT actor thread owns `vt::Terminal`, `InputTracker`, `program_status` record state, and the optional fixture recorder, paired with one dedicated FIFO host-effects worker so blocking `TerminalHost` callbacks never stall `vt_write` or re-enter the VT actor while preserving strict reply and event order. Synchronized-update holds (`DEC 2026`) arm a 150 ms deadline directly on the actor's `recv_timeout` loop.
- **`TerminalMirror` (in `runner-app`, `crates/runner-terminal/src/terminal.rs`):** one single-owner actor thread owns `vt::Terminal`, `vt::RenderState`, registered view find sessions, and `TrackedGridRef` anchors. Production transports push `TerminalFrame`s straight into a bounded non-blocking mailbox (`TerminalSubscription::install_sink`), collapsing overflow to a single `Resync` without blocking the producer. After applying output while `viewers > 0` (and outside a render hold), the actor updates `RenderState`, builds an immutable `Arc<ViewportSnapshot>` (including full-logical-line visible find highlights when find is open), swaps it into the shared slot, and wakes GPUI; hidden mirrors (`viewers == 0`) defer `RenderState` work until a pane attaches a `TerminalView` lease.

## Screen storage, scrollback, and reflow

Ghostty stores each screen (primary and alternate) as a doubly-linked list of fixed-size memory pages (`PageList`) with interned per-page style tables, grapheme side tables, and hyperlink tables. Positive `scrollback_lines` configures whole-page eviction (`SCROLLBACK_MAX_LINES = lines`, `SCROLLBACK_MAX_BYTES = usize::MAX`), while `0` disables scrollback (`SCROLLBACK_MAX_BYTES = 0`). Scrollback compression (`compress_history = true`) keeps idle memory low across dozens of open sessions.

When a terminal narrows or widens, Ghostty reflows soft-wrapped lines on the primary screen while keeping re-wrapped rows on screen until the active area overflows. The alternate screen has no scrollback and never reflows. `ScreenScrollTracker` reads `GHOSTTY_TERMINAL_DATA_SCROLL_UP_ROWS` and `GHOSTTY_TERMINAL_DATA_SCREEN_GENERATION` directly from the active screen, maintaining independent primary and alternate epochs so temporary alternate-screen excursions preserve primary scroll marks and held viewports across arbitrary PTY chunk splits.

## Native effect callbacks

During `vt_write`, `libghostty-vt` invokes registered C effect callbacks synchronously on the VT actor thread, which enqueue typed `TerminalEffect` values without any external Rust byte pre-scanners:

- **`WRITE_PTY`:** terminal query replies (`DSR`, `DECRQM`, Kitty keyboard queries, `OSC 4/10/11/12`, etc.). `TerminalModel` forwards replies to the PTY through its FIFO host-effects worker; `TerminalMirror` leaves host replies disabled so every query produces exactly one reply.
- **`PWD_CHANGED` (`OSC 7`):** validates a `file://` URI and `host.is_local_host` before updating the session's live cwd.
- **`COLOR_SCHEME` (`DEC 2031`):** answers color-scheme queries and mode subscriptions via `color_scheme_report_encode`.
- **`CLIPBOARD_WRITE`:** handles stock `OSC 52`, `OSC 1337 Copy`, and `OSC 5522` UTF-8 `text/plain` writes up to 1 MiB; `CLIPBOARD_READ` stays unset so clipboard reads remain denied.
- **`SIZE` (`CSI 14/16/18 t`) and `DEVICE_ATTRIBUTES`:** answers text-area/cell size queries via `size_report_encode` and serves DA1 (`\x1b[?6c`), DA2 (`\x1b[>0;2600;1c`), and DA3 (`\x1bP!|00000000\x1b\\`).
- **`PROGRAM_STATUS` (`OSC 7501`) and `SEMANTIC_PROMPT` (`OSC 133`):** drive Runner's record-tree status reducer (`program_status.rs`) alongside `ActivityFilter` (matching Ghostty's VT500 ESC-ends-OSC and CAN/SUB abort semantics).
- **`TITLE_CHANGED`, `TITLE_PUSH`, `TITLE_POP` (`OSC 0/2`, `CSI 22/23 t`):** maintain Runner's bounded 4,096-entry xterm title stack and emit authoritative title updates from `TerminalModel`.
- **`RENDER_HOLD` (`DEC 2026`):** Both `TerminalModel` and `TerminalMirror` feed every PTY byte and resize straight to `libghostty-vt` via one plain `vt_write` call in order, and Ghostty's `on_render_hold` callback only records the hold transition flag across grouped DECSET forms and arbitrary chunk splits without raw byte matching, byte deferral, or callback rendering (paired with the read-only DECSET-only `SYNC_HOLD_REOPENS` counter — Patch #4, excluding saved-mode restore `?2026r`, upstream proposal pending — so a repeated `DECSET ?2026` begin inside an active hold extends the 150 ms render deadline while a paired close/open within one write retains the earliest unpublished bound). While a hold is active on `TerminalMirror`, viewport display reads (rows, offset, find counts/indices/highlights, selection display/hit-testing, and link hover) return promptly from the immutable `ViewportSnapshot` published before the chunk, and display-affecting user interactions (find query/step/refresh/clear, selection edits, and local scrolling) are queued. Copy (`TerminalMirror::selection_text()`) stays synchronous as on `main`: it queries the mirror actor between writes, applies any queued hold selection edits onto the live grid without touching the frozen published snapshot, formats on demand via Ghostty's native formatter (`trim: is_block` so block selections keep per-row trailing-whitespace trimming while simple/line selections preserve written spaces and drop unwritten cells), and clears selection on Windows/Linux (`Ctrl+C` falls through to `\x03` immediately when empty) with zero deferral or input gates so Copy, Paste, and Enter keep their natural order (accepting that Copy during a hold may reflect live output that becomes visible at release, at most 150 ms or the renewed hold later). At release, queued interactions apply once (whole-screen scroll translated via the native scroll counter), live `TrackedGridRef` anchors resolve on the live grid, find recomputes once, and a single `RenderState::update` publishes the new snapshot without per-frame selection formatting. Complete synchronized frames (prefixed or unprefixed) therefore match plain output cost (one `RenderState::update` visible, zero hidden, zero per-frame selection work).

Phase 1 disables Kitty graphics storage (`GHOSTTY_TERMINAL_OPT_KITTY_IMAGE_STORAGE_LIMIT = 0`) and keeps grapheme clustering (mode `2027`) off and Kitty keyboard flags capped to bit 0 (`DISAMBIGUATE_ESC_CODES`) to match Runner's Phase 1 parity bar.

## Snapshots: binary local vs. VT companion

Local `runnerd` ↔ `runner-app` attach and resync use `SnapshotFormat::GhosttyBinary`, produced by `ghostty_snapshot_encode_alloc` with `continuation_max_bytes` enabled (`retain_continuation = true`, `compress_history = true`) so both screens, scrollback, modes, palette, cursor state, and unfinished mid-sequence bytes round-trip natively (with an optional self-delimiting `"RNTS"` footer when the xterm title stack is non-empty). If snapshot capture fails (for example, an unfinished OSC exceeding the continuation cap), the snapshot sets `unavailable: true`; the mirror retains its last good view and `runnerd` triggers a `Resync` as soon as encoding succeeds again.

Companion attach (`runner-ios` and remote desktop) keeps `companion::VERSION = 1` and `SnapshotFormat::Vt`, composed via `GhosttyFormatter` (`GHOSTTY_FORMATTER_FORMAT_VT`, `unwrap: true`) over the primary screen (with requested history, saved/active cursors, and bit-0-capped Kitty keyboard stack) followed by the alternate screen when active, title stack, continuation bytes, and `REP` state.

## Selection, search, anchoring, and input encoders

- **Selection (`selection.h`):** `TerminalMirror` delegates word (`select_word` with xterm boundaries), line (`select_line`), range (`set_selection_points`), hit testing (`selection_contains`), and unwrapped copy formatting (`format_active_selection`) to `libghostty-vt`. Ghostty expands tab cells to spaces on copy (including across soft wraps).
- **Search (`terminal/find.rs`):** `TerminalMirror::find_matches` walks `vt::Terminal` rows lazily inside the mirror actor with `regex` / `regex-automata` so counts stop at `MATCH_LIMIT` (1,000) without scanning deep scrollback, navigation steps across full history on demand, and rightmost non-overlapping matches, Unicode case folding, and combining-mark stripping match Runner's baseline semantics (Ghostty's `GhosttySearch` in `vt-1.0.2` emits overlapping ASCII-only hits across the full buffer). Visible viewport-intersecting highlights are computed with full logical-line soft-wrap context (including pre-hold wrap context during `DEC 2026` render holds) and published on `ViewportSnapshot` so `TerminalElement::prepaint` borrows them without copying or blocking on the actor.
- **Tracked anchoring (`grid_ref_tracked.h`):** `TrackedGridRef` pins anchor live drag selections (`SelectionState`), the active Cmd+F match (`MatchAnchor`), and the pre-find scrolled viewport top (`GridAnchor`) across scrollback, resize reflow, and `RIS` invalidation with deterministic pin untracking on drop.
- **Input encoders (`key.h`, `mouse.h`, `paste.h`):** `crates/runner-terminal/src/mappings.rs` delegates key, mouse, and bracketed-paste encoding to `libghostty-vt`'s encoders while keeping Runner's `classify_key` and macOS Option-as-Meta / IME rules intact.
