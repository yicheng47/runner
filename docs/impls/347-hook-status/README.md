## Why a program, not one mission

The transport is small, but the feature crosses every layer and every runtime once: a per-spawn hook injection per CLI (three different config surfaces), a watcher and a new status source with its own precedence rules (backend), a shared status vocabulary (backend + app), every consumer of that status (pane header, tab bar, sidebar rollups, mission cards, mission tab strip), and a design pass first. Slicing it means each piece lands green on its own, and a runtime can be useful before its adapter exists.

## Decisions that bind

1. **Minimal-first.** Ship only what each runtime can prove; an unprovable detail is left out, never approximated. Rich coverage differs by runtime and that is the design, not a gap.
2. **Runner never gains an approval or answer control.** Showing that a session is waiting on you, and focusing that pane when you click it, is the whole job. The CLI keeps its prompt.
3. **The mechanism is a port, not a design.** Per-invocation additive CLI injection, bounded observer hooks, a script file in a Runner-owned directory, serialized TOML commands — all from cmux (manaflow-ai/cmux, GPL-3.0-or-later, compatible with Runner's GPL-3.0). cmux's *product* decisions are explicitly not ported.
4. **Terminal observation is a permanent baseline; a hook adapter is a per-runtime upgrade.** A new runtime is supported the day it is added, with no adapter. Adapter work is never a precondition for shipping a runtime, and a failed bridge falls back rather than going dark.
5. **Only unresolved human interactions add a status-based delivery hold.** Working and Idle gate nothing. Claude raises question/plan requests and matched PermissionRequest early to protect the CLI prompt; automatically handled requests can briefly hold until the owning result. An unresolved dialog survives Escape until its resolution is observed. Ordinary interruption without a pending dialog returns to Idle with Interrupted outcome; new work restores Working. Typed-draft protection remains independent.
6. **No runtime publishes a continuation-proof turn boundary.** Idle is entered on the turn-end event and corrected by the next work event. This is safe *only* because Idle gates nothing; if that ever changes, this decision must be revisited.
7. **`Notification(idle_prompt)` is not a turn boundary on Claude Code.** 2.1.270 gates it behind `messageIdleNotifThresholdMs` (60 s default, disabled at 0, suppressed during a dialog). It is secondary confirmation only. TRAE's manual claim of an immediate notification remains unverified; its adapter is no longer planned.
8. **Claude Code publishes no interrupt event** and its `Stop` excludes user interruptions, so interrupts are recovered through Runner's own input layer (`input-interrupt`, `input-escape`), not inferred from silence.

9. **Codex human waits cannot be proven by elapsed time or Plan-mode call correlation.** Native 0.154.0 fixtures reproduce both false-positive paths. This slice emits no Codex interactions; question/approval dialogs remain unsupported until surfaced and resolved identities can be observed.
