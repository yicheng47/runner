## The defect, re-traced 2026-08-22 (two corrections to §M6.1 as written)

"Is the human typing in this slot" is a byte guess. `classify_local_input` (`runner-backend/src/session/manager/output.rs:10-31`) latches `SessionState::local_input_pending` (`manager/mod.rs:559`) on any printable or UTF-8 byte and on a bracketed-paste open (`:17`, `:23-27`); only an exact `\r` or `\x03` chunk clears it (`:14`); everything ESC-prefixed is activity-only (`:20-22`) — and so is **every other control byte, including Backspace `\x7f` and Ctrl-U** (`:28-29`). `reserve_delivery` (`manager/mod.rs:826-855`) returns `DeliveryReservation::PendingInput` while the latch is set (`:842`), the router parks the delivery with `pending_input_blocked = true` and **schedules no retry** (`router/mod.rs:776-791`), and the 30 s reconciliation tick skips pending sessions (`:776-779`, pinned by `router/tests.rs:801`).

1. **There is no 10-minute abandonment backstop.** `DRAFT_ABANDON_WINDOW` exists only in `docs/impls/0041-draft-aware-delivery-gate.md`; nothing in `crates/` implements it, on this branch or on `origin/main`. A draft typed then deleted parks every nudge and relay for that slot **until the human presses Enter or Ctrl-C, or the session respawns or exits**. The pill's "Clear input" button (`mission_workspace.rs:4274-4300`) sends a bare `\r` (`clear_mission_input`, `:2510-2529`) — it submits whatever is in the composer. §M6.1, `arch.md:522` and the M3.6 impl_log entry are corrected alongside this brief; do not build to the 10-minute claim.
2. **The composer is not the cursor line.** In the claude fixture (`runner-terminal/fixtures/claude-session.snapshot.txt`) the cursor is parked at `29,0` while the composer is the `❯ ` row mid-screen: Ink hides the terminal cursor and paints its own caret. "Read the composer row relative to the cursor" (§M6.1) does not work for claude-code; the design below locates the composer by the echo of the human's own keystroke instead.

What the native seam gives us that the webview never had: every byte of human input passes through one function, `TerminalSession::write_user_bytes` (`runner-terminal/src/terminal.rs:382-397`), fed by `send_key` (`:399-418`, raw keys), `paste` (`:421-427`), the IME commit (`runner-app/src/terminal_ime.rs:195`) and the element's mouse reports (`terminal/element.rs:202,293,362`); the same struct owns the live grid (`term`, `:107`) and sees every output chunk synchronously in `feed_output` (`:340`, `parser.advance` at `:353`, the M6.11 first-paint probe at `:354-361`). IME composition lives in `TerminalComposition` (`terminal_ime.rs:88`) and never reaches the PTY until commit — invisible to the latch today, visible to us. So the state can be *observed*: keys say when to look, the grid says what is there.

## Design — keys trigger, the grid decides

Put a per-session `InputTracker` on `TerminalSession` (module `runner-terminal/src/input_state.rs`, pure state machine plus a thin `Mutex` holder; `chat_lifecycle.rs` is the structural template — a pure-function core with `#[cfg(test)]` next to it). Do **not** name anything `draft`/`Draft*` in the app crate: `ComposerState.draft` (`surfaces/mission_composer.rs:10`) is the mission-feed text field and the collision will bite reviewers.

**Public state** (what the backend and the pill see):

```rust
pub enum InputState { Idle, Drafting, Submitted }
pub struct InputObservation {
    pub state: InputState,
    pub since: Instant,
    pub composing: bool,        // IME marked text present
    pub composer_visible: bool, // false while Drafting but the composer row cannot be found
}
```

`AwaitingHuman` is **not** added — it arrives with M6.2's hook signals; leave room in the enum's doc comment, nothing else.

**Input events** come from the session's own typed entry points — no change to the two duplicated surface key handlers (`surfaces/chat.rs:863`, `surfaces/mission_workspace.rs:2356`), both already call `send_key`:

- `send_key` classifies before encoding, via a pure `classify_key(key, ctrl, alt, shift) -> InputKind` beside `encode_key` in `mappings.rs:33`: plain `enter` → `Submit`; `shift-enter` (the `\x1b\r` multiline chord, `mappings.rs:41-43`), `tab`, any printable with `key_char` → `Content`; `backspace`, `delete`, ctrl-h/u/w/k → `Edit`; `ctrl-c` → `Cancel`; arrows, home/end/page, `escape`, function keys, other ctrl/alt chords → `Navigate`. `Navigate` and `Edit` never *start* a draft; the grid decides whether they end one.
- A new `TerminalSession::send_text(&str)` for the IME commit path (`TerminalInput::commit_text`, `terminal_ime.rs:190-196`, replaces the raw `write_user_bytes` there) → `Content(text)`. `paste` → `Content(text)` (first line is what the echo will show; see the paste rule below). `write_user_bytes` stays raw for mouse reports and the `\x16` image marker and counts as activity only. Align `chat.rs:990`, which injects the image marker through `inject_stdin` and bypasses the latch, with the mission path (`mission_workspace.rs:2485`, `write_user_bytes`).
- Composition: `replace_and_mark_text` (`terminal_ime.rs:263`) → `session.set_composing(true)`; `cancel_composition` (`:167`, also fired by `on_focus_out` at `chat.rs:627-635` / `mission_workspace.rs:1317-1324`) → `set_composing(false)`; `commit_text` (`:190`) → `set_composing(false)` then `send_text`. Note `unmark_text` (`:243`) *commits*; it must go through the same path.

**The echo-locate algorithm** (the core of "much better"):

1. `Idle` + `Content(text)`: snapshot the visible rows (`replay::row_to_string` per screen line — read screen lines by grid index, **not** `display_iter`, so a scrolled-up viewport does not change what we read) and enter the internal `Probing { typed, rows_before, at }` state. Probing is not reported; it is covered by the existing 2 s `RECENT_LOCAL_INPUT_WINDOW` that the bytes already stamp.
2. On each output chunk while Probing, after `parser.advance`: find the row `r` where `after[r] != before[r]`, `after[r]` and `before[r]` share a common prefix (the prompt — `❯ ` with a NBSP for claude, whatever codex and zsh draw), and the remainder of `after[r]` past that prefix begins with `typed` (one grapheme is enough; Ink draws the caret as an inverse-video cell, so compare characters, not styles). Found → `Drafting { row: r, prefix, empty_forms: [before[r]] }` and report. Not found on a chunk → keep probing; after `ECHO_WINDOW` (500 ms, measured lazily on the next chunk or input event) → `Idle`, unreported: the TUI swallowed the key (a y/n prompt, a select menu, a modal) and there is no draft. Prefer the match whose remainder starts with `typed` over any row that merely changed — the agent's transcript may contain the same letter.
3. `Drafting`: one `row_to_string` of row `r` per chunk. `after[r]` equal to an `empty_form` (the pre-key content, placeholder included) or to the bare `prefix` (trimmed) → `Idle`, reported — this is typed-then-deleted, Ctrl-U, Ctrl-C, and the post-submit redraw. Row `r` no longer starting with `prefix` → the composer moved (multi-line growth, the `/` autocomplete popup, a scroll): re-locate by scanning for the row starting with `prefix` nearest the old index; none found → stay `Drafting` with `composer_visible: false` (a full-screen menu over a draft). Further `Content`/`Edit`/`Navigate` while Drafting never re-probe; the grid is the arbiter.
4. `Drafting` + `Submit` (plain Enter only) → `Submitted`, reported. Exit on the grid: the composer row redrawn to an empty form → `Idle`, **re-capturing the empty form** (claude rotates its placeholder; the new empty row becomes the form to match). If after the echo the row still holds draft text (Enter fell into a popup, or the runtime took it as a newline) → back to `Drafting`. `Submit` while `Idle` is activity only (Enter accepting a menu row is not a submission).
5. `Cancel` while Drafting: no special case — claude clears its composer on Ctrl-C and the grid sees it; codex and shells likewise or not.
6. `composing: true` reports as `Drafting` regardless of the grid (the marked text is app-drawn; the TUI has not seen it). Commit turns it into a `Content` probe.
7. Paste: claude collapses a large paste into `[Pasted text #1 +N lines]`, so the echo will not contain the pasted text. For `Content` events longer than one line (or than ~40 chars) accept the weaker match — a changed row with the same prefix and a non-empty remainder that differs from the old one. Record the fixture (below) before trusting either form.

Invariant to design to and to state in the handoff: **no reported state is sticky, and no state is time-based.** `Drafting` exits only on the grid, and the grid is read on every chunk. There is deliberately no abandonment timer of any kind (Jason, 2026-08-22): a draft — visible, or hidden under a menu (`composer_visible: false`) — parks deliveries until the composer is observed empty, and the pane's pill is the release: it tells the human a draft is holding N messages and offers to submit it. A human who walked away mid-draft comes back to an honest pill, not to a nudge pasted into their sentence.

Cost: zero grid work while `Idle` (the snapshot happens at the first content key, not per chunk); one row read per chunk while Drafting/Submitted; a bounded scan only on relocation. Measure it. The tracker runs on the forwarder thread inside `feed_output` under the `term` lock it already holds; **report transitions to the backend after the lock is released, never under it** (lock order: `term` → nothing), and report transitions only — never per key, never per chunk.

## Backend — the observed tier above the latch

- `SessionState` gains `observed_input: Option<ObservedInput { state, composer_visible, since }>` beside the latch (`manager/mod.rs:553-573`), set through a new `SessionManager::report_input_state(session_id, InputObservation)` that `TerminalSession` calls on its `core.sessions` handle (the same handle `write_user_bytes` uses). Cleared with the latch in `install_handle` (`:917-918`), `kill` (`lifecycle.rs:78`) and exit reconcile (`:300`).
- `reserve_delivery` (`manager/mod.rs:826-855`) consults the observed tier first: `Drafting` (visible or not) → `PendingInput`; `Submitted` → `RecentlyTyping(remaining of the 2 s window)`; `Idle` → fall through to the existing `last_local_input_at` window (`:847-850`). Only when `observed_input` is `None` — a session whose terminal has not reported yet, or a headless session — does the byte latch decide, exactly as today. `classify_local_input` and `update_local_input_state` stay as that fallback tier (M6.2's `IdleDetector` demotion has the same shape); do not delete them.
- Release path: an observed `Drafting → Idle` emits `SessionDeliveryEvent::InputCleared` (`router/mod.rs:154-161`) through `notify_delivery_event` (`manager/mod.rs:777-803`) so the parked outbox flushes after `INPUT_CLEAR_FLUSH_GRACE` (`router/mod.rs:212`, listener arm `:1498-1500`) — the existing re-park-if-typing-resumes semantics (`router/tests.rs:1087`) carry over unchanged. `DeliveryReservation::PendingInput` and the router's park-without-retry arms (`router/mod.rs:776-791`, `:1126-1133`) stay as they are: the observed `InputCleared` is the only release, and it is enough because the grid is read on every chunk.
- `suppress_local_input_busy` (`manager/mod.rs:558`, `output.rs:361-390`) is **left alone** in this mission: it suppresses echo-Busy in the status projection, which is a status problem M6.2's `working` signal retires properly. Say so in the handoff if it misbehaves under the new state; do not re-source it here.
- Input-path hygiene while you are in `inject_direct_stdin_with_wait_timeout` (`output.rs:301-439`): nothing else changes — the ticketed gate, the rollback on write failure (`:391-392`), `InputQueueDrained` (`:417-419`) all stay.
