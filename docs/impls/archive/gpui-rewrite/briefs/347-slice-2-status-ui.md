## Backend contract

- Reuse the per-spawn injection, status file, watcher, and existing event path. Preserve rekeying, user-supplied `--settings` behavior, session generation binding, cleanup, bounded hook timeouts, and the reporter's fail-open behavior. Never edit the user's CLI configuration. Read payloads structurally; terminal prose and arbitrary strings are not status evidence.
- Keep process lifecycle, activity, outcome, attention, and observation source distinct. A baseline Idle is an estimate, never confirmed Ready. Populate both the initial app snapshot and incremental events, including mission feed consumers; attaching a view or switching windows must not lose source or attention.
- Hook observations own the session until teardown or explicit bridge failure. Byte output, title updates, and silence never override healthy hooks. On an explicit bridge failure, invalidate hook-owned waits and fall back to the baseline with estimated presentation. An absent adapter is baseline-only, not Error or a permanent unavailable state.
- Claude work events enter Working. `Stop` ends the displayed turn and a following work event can restore Working; no continuation-proof boundary exists, and Ready gates nothing. `Notification(idle_prompt)` is delayed, configurable secondary confirmation only. Subagent and stale-generation events must not finish or clear the main turn.
- Verify the actual payloads and ordering for `Notification(permission_prompt)`, `Notification(elicitation_dialog)`, relevant question/answer events, and plan approval before wiring them to a delivery hold. Distinguish a surfaced human wait from a raw permission request or automatically resolved interaction. Establish and test a short hold-and-cancel interval only where the evidence requires it; do not manufacture an interval from documentation assumptions.
- Retain available interaction identity and ownership through resolution. An unrelated tool finishing cannot clear another unresolved interaction. A question uses Answer needed; a plan approval uses Approval needed. Focus, silence, and a generic Escape keypress are not proof that an interaction resolved. Use verified resolution/continuation evidence, owning turn termination, or process replacement; if the installed CLI cannot prove a capability, report that limitation rather than guess.
- Extend the router's existing delivery reservation/notification path so an unresolved approval or question holds a nudge and its resolution releases queued delivery. Keep nudges eligible during Working, Ready, baseline-only sessions, and unavailable activity, subject to existing non-status gates.
- Preserve slice 1's ordered Ctrl+C / bare Escape recovery, including buffered tool events and later continuation. Track interruption separately from successful completion. Do not create a success/unread badge for an interrupt or consume a sibling pane's completion. An interrupt signal alone must not falsely clear an unresolved dialog.
- Keep Windows in scope for the shared model and UI. For this mission, explicitly document and test Windows as baseline-only for the existing POSIX Claude hook helper; do not claim native hook support or broaden this into a new cross-platform bridge. Windows hook transport remains a separate carry.
