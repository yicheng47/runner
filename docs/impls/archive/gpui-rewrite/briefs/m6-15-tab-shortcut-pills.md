## Behaviour (settled in spec 63 and on the canvas 2026-08-23)

1. **Numbering.** `1`…`9` are assigned top to bottom to the rows a click could activate, in display order: PINNED rows, then each *expanded* project's children (chat tabs and missions), then RECENT. Project header rows, the WORKSPACE nav, and the children of a collapsed project get no number. Ten or more rows: 1–9 only; no `⌘0`. The numbering comes from the same visible-row walk the sidebar already renders from (`resolved_sidebar_rows` `sidebar.rs:604`, `scope_rows` `:684`, `render_sidebar_contents` `:1613`) — compute a `tab_index_by_node: HashMap<String, u8>` once per render so the pills and the actions agree by construction.
2. **Jump.** `⌘N` activates the Nth visible row exactly as a click does: a tab row → `activate_sidebar_session` (`sidebar.rs:507`, route to Chat + `TabSet` activation); a mission row → `open_mission` (`:590`). No row at N → no-op. Per window (the focused window's sidebar). Works with the sidebar collapsed (nothing shown).
3. **Reveal.** While ⌘ is held **alone** for ≥ 150 ms, every numbered row shows its digit pill in the trailing slot; the pills vanish the instant ⌘ is released, another modifier joins, any key is pressed (a chord), or the window loses focus. Ordinary chords (⌘C, ⌘N, ⌘K) must never flash them. Modifier tracking: `window.on_modifiers_changed` as `terminal/element.rs:648` already does for ⌘-hover links — the sidebar registers its own, keeps `cmd_held_since: Option<Instant>`, arms a 150 ms timer (`cx.spawn` + `background_executor().timer`) that flips `show_shortcut_pills` only if ⌘-alone is still held, and clears on the conditions above. Notify only the sidebar entity.
4. **Pill** — `cmp/TabShortcutPill`: 16 × 16, `theme::raised()` fill, radius 4, digit in the mono UI face (JetBrains Mono) 10 px weight 500, `theme::muted()` (`$text-mid`); on the selected row the digit is `theme::text()` (`$text-hi`) so it reads on the `sidebar_selected` fill. **Never accent** — accent is reserved for attention and busy. It sits at the row's trailing slot (x 190 of the 216 row — the kebab's place) and **replaces** whatever lives there while ⌘ is held: the pin glyph on PINNED rows, the unread dot, a mission's status glyph, the hover kebab. The label shrinks by the slot difference and ellipsizes as today. Rows with nothing in the slot simply gain the pill. Rows without a number show nothing.
5. **Keymap.** Nine entries `select-tab-1`…`select-tab-9` (`cmd-1`…`cmd-9`), `KeymapScope::Global`, rebindable (`fixed: false`), titles "Go to tab 1"…; nine `gpui::actions!` (`SelectTab1`…`SelectTab9` or one action with a payload if the registry's `KeyBinding::new` path allows it cleanly) bound with **no context** so they work from terminals and text fields (macOS never delivers ⌘-digit to the PTY); handled on `NativeRoot`. They appear in Settings → Keyboard like the rest (check whether that pane lists from `entries()` or has its own table — `keymap.rs:85`).

## Tests

`sidebar_logic.rs` is the home of the pure tests: (a) numbering over a visible-row walk — pinned, expanded-project children, collapsed project skipped, RECENT, >9 rows capped, headers unnumbered; (b) the reveal decision as a pure function of (⌘ held alone since, now, other modifiers, key pressed, window active) → bool, including the 150 ms edge; (c) `select-tab-N` → the Nth row's activation target (tab vs mission). `keymap.rs` tests cover the nine entries' ids, defaults, and contexts.
