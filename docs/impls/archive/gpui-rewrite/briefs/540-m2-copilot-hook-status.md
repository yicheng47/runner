## Deliverable

Copilot joins Claude Code and Codex as a runtime with a hook status adapter on macOS. Windows stays baseline-only, gated exactly like the other two.

**Injection, per invocation, nothing persisted.** A Runner-owned plugin directory under app data, `<app data>/copilot-hooks/`, regenerated at startup beside `claude_status::clear_leftovers`: `plugin.json` (`{"name":"runner-status","version":…,"description":…}`) and `hooks/hooks.json` (`{"version":1,"hooks":{…}}`, PascalCase event keys, one `{"type":"command","command":…,"timeout":2}` per event). Each command runs Runner's bounded reporter script in that directory with the per-session feed path taken from the environment, `sh <dir>/report.sh "$RUNNER_COPILOT_STATUS_PATH" <Event>`; hooks inherit the spawn environment, verified. The reporter spools stdin into the shared `hook_feed` side-file format, exits 0, prints nothing (no decision, no `additionalContext`), and drains stdin when the path is unset. `trailing_runtime_args` adds `--plugin-dir <dir>` for Copilot when hooks are supported; `apply_runtime_args` sets `RUNNER_COPILOT_STATUS_PATH` and `RUNNER_COPILOT_STATUS_GENERATION` the way it does for Claude. A runner whose own args pass `--plugin-dir` still gets Runner's, the flag repeats. There is no per-invocation opt-out flag; a user with `disableAllHooks` in `settings.json` simply produces no feed, and the existing bridge-loss fallback leaves the session on estimated status. Events to register: `SessionStart`, `SessionEnd`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `PermissionRequest`, `Notification` with matcher `^(permission_prompt|elicitation_dialog|agent_idle)$`, `Stop`, `ErrorOccurred`, `PreCompact`, `SubagentStart`, `SubagentStop`. Unknown names are ignored by the CLI, so an event that turns out unsupported costs nothing.

**Payloads.** PascalCase events carry snake_case fields (`hook_event_name`, `session_id`, `tool_name` with Claude-mapped names such as `Bash`, `Edit`, `AskUserQuestion`, `tool_input`, `tool_result`, `stop_reason`, `stop_hook_active`, `transcript_path`, `reason`, `source: new | resume`). `PermissionRequest` is the exception and is camelCase: `hookName`, `sessionId`, `toolName` (lowercase native names such as `bash`, `edit`), `toolInput`, `permissionSuggestions`. No payload carries a tool-use id. `transcript_path` is `<COPILOT_HOME>/session-state/<id>/events.jsonl`, whose records include `tool.execution_start` / `tool.execution_complete` with `toolCallId`, `assistant.turn_start` / `turn_end`, `hook.start` / `hook.end`, `session.shutdown`.

**`session/copilot_status.rs`**, a `CopilotStatusWatcher` over the shared feed and transcript tail, plus `HookStatusWatcher::Copilot` in `pty_runtime.rs` with the interrupt signal wired like Claude's. Mapping, from spec decision 3:

- Working: `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `PreCompact`.
- Approval needed: `Notification(permission_prompt)`, correlated to the pending `PreToolUse` by tool name and structured input, cleared by the owning `PostToolUse` / `PostToolUseFailure` or the transcript's `tool.execution_complete`. `PermissionRequest` alone never raises attention: it fires 50 ms before `PostToolUse` for auto-approved commands (`echo`), and 7 ms before the notification for a real dialog (a file write), both observed.
- Answer needed: `PreToolUse(AskUserQuestion)` raised immediately, confirmed by `Notification(elicitation_dialog)`, cleared the same way as approvals.
- Idle: `Stop` (`stop_reason: end_turn`), corrected by the next work event if a `stop_hook_active` continuation follows; `Notification(agent_idle)` is secondary confirmation only.
- Response failed: `ErrorOccurred` with `recoverable: false` and `error_context: model_call`, only once you have captured it live (an unreachable model or a revoked token are the cheapest fixtures); if you cannot capture it, leave it unmapped and say so.
- Subagent events never change the main agent's state; `SessionStart` owns the generation and `source` distinguishes new from resume; `SessionEnd` ends it. Copilot publishes no interrupt event, so Escape and Ctrl+C recover through Runner's input layer exactly as for Claude Code.
- Only an unresolved approval or answer adds a crew delivery hold, through the existing normalized path. Working and Idle gate nothing.
