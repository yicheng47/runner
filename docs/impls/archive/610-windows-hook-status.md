Facts the missions lean on:

- **Feed file sharing.** Rust's `File::open` on Windows shares read, write and delete, so a hook appending while Runner holds the feed open is fine. The PowerShell append must open the feed with `FileShare` `ReadWrite | Delete` and write its record as one byte write, so a late hook never blocks `StatusFiles::drop` and cleanup never blocks a hook. Mission 1 review found that a .NET `Append` stream is still not an atomic append across processes, so the shipped reporter also serializes its write under a per-feed named mutex. Anything cleanup cannot remove is swept by `clear_leftovers` at the next launch, as today.
- **Watching a file, not a directory.** `HookFeed` watches the feed path itself through `notify`. Whether ReadDirectoryChangesW delivers events for a file path is a mission-1 test; `drain`'s one-second re-read covers it either way, so the worst case is a second of latency, not a lost record.
- **Git's `sh` is Claude's problem, not Runner's.** Claude resolves Git Bash the way it does for its Bash tool (Git for Windows is its install prerequisite); Runner injects the same `sh` command it injects on macOS. `C:\Program Files\Git\usr\bin\sh.exe` happens to be on JASONPC's native PATH and is present on GitHub's `windows-latest`, which is what the Windows reporter test uses; it skips with a message when absent.
- **Copilot's Windows transcript** is `%USERPROFILE%\.copilot\session-state\<session>\events.jsonl` (seen for the probe session, `copilotVersion` 1.0.85 in its `session.start` record), the path `CopilotStatusWatcher` already derives through `copilot_home`, so the transcript-correlated cancellation path needs no Windows branch.
- **Version skew.** macOS verified Claude Code 2.1.270, Codex 0.154.0 and Copilot 1.0.83; JASONPC has 2.1.273, 0.153.4 and 1.0.85. The Codex hook flags and events are identical across those two Codex versions; the smoke records name the versions they ran on. One 1.0.85 change to watch: its `~/.copilot/config.json` is headed "User settings belong in settings.json. This file is managed automatically." and holds only login state, while `copilot_trust` seeds `trustedFolders` into that same `config.json`; if the first Copilot spawn on JASONPC shows the folder-trust dialog, the seed has moved and that is a 540 follow-up, not a hook problem.
- **cmd.exe caps a command line at 8,191 characters.** An npm `codex.cmd` or `claude.cmd` shim launches through `cmd.exe /c` (`adapt_windows_batch_command`); on JASONPC an expanded line worked at 7,800 characters and silently ran nothing at 8,200. Hook argv therefore stays short: Codex points at its per-session `.ps1`, and Claude's `--settings` stays about 5.7 K characters under a long app data path.
- **Codex exec probes need `</dev/null`.** With an open stdin `codex exec` prints `Reading additional input from stdin...` and waits forever; two probes hung that way before the third closed stdin.

## Decisions that bind

1. **Per-runtime gate.** `hook_feed::hooks_supported(windows)` becomes `hooks_supported(runtime, windows)` and `inject_codex_hooks` reads it, so each bridge is lifted the day its JASONPC smoke passes and re-gated alone if it regresses. After mission 1 all three runtimes return true on both platforms; a runtime whose smoke fails is re-gated alone before merge, and the others still ship.
2. **No new binary.** Each adapter's hook command gets its Windows form in the shell its CLI already uses: Claude keeps the `sh` reporter under Git Bash; Codex and Copilot share one PowerShell reporter body. A Runner-owned native reporter executable was considered and rejected: PowerShell does not hand its stdin to a native child without piping, so PowerShell would still have to read the bytes, and the executable would add a sidecar to package, install and upgrade for no transport gain.
3. **One PowerShell reporter body, bytes only, 5.1-compatible, serialized appends.** Codex's reporter is a per-session `<feed>.ps1` that `HookFeed` writes beside the feed exactly as it writes the `.sh`, and each `-c` hook runs it as `try{& ([ScriptBlock]::Create([IO.File]::ReadAllText('<feed>.ps1'))) '<feed>' '<Event>'}catch{<drain stdin>};'{}'`. `ScriptBlock::Create` is not subject to execution policy, the reporter-path check and bridge loss are the `.ps1`'s, and `clear_leftovers` and `StatusFiles::drop` sweep it. Copilot's reporter is the same body inline in the plugin's `powershell` slot, with the feed from `RUNNER_COPILOT_STATUS_PATH`: a file, not argv, so its size never matters. (Mission 1 first put the body inline in every Codex `-c` value; review measured nine copies at about 11 K characters, past cmd.exe's line limit for an npm `codex.cmd`.) The body copies stdin as raw bytes to `<feed>.<8 hex chars>`, never through `Add-Content`, `$input` or text mode, then writes one UTF-8 record line (`generation`, `hook_event_name`, `payload_file`, the shape `read_report` already parses). The record append is serialized by the per-feed named mutex `runner-status-<hash>`, where the hash is an 8-hex-digit FNV-1a over the UTF-16 code units of the forward-slash feed path, computed the same way by the reporter and by the Rust test that holds the lock, so the kernel object name stays short (kernel names are capped at 260 characters) for any profile or app data path (bounded one-second wait; on timeout the payload is removed), with the feed opened existing-only under the lock and written at its end, because `FileMode.Append` is not an atomic append across processes on Windows: each stream keeps its own position, and review lost 96 of 100 records with overlapping writers. Every handle shares delete, so teardown always wins, and a hook never recreates a removed feed. The body has no double-quote character: strings are single-quoted (a `'` inside a path doubles to `''`), the record's JSON quotes come from `[char]34` and its newline from `[char]10`. No pwsh-7-only syntax, so a Codex fallback to Windows PowerShell 5.1 keeps working; Copilot requires pwsh 7 regardless. It always exits 0; the Codex command ends with `'{}'` so the CLI gets its acknowledgement.
4. **Forward-slash feed paths on Windows.** Every status feed path handed to a hook command or a `RUNNER_*_STATUS_PATH` env var uses `/` separators. Rust, PowerShell and MSYS accept both; Git Bash needs `/` for the basename strip. The rekey drop path keeps its backslashes: it works today through `cat` and `mv` and is not touched.
5. **macOS byte-for-byte unchanged, same vocabulary, no new surfaces.** Every macOS command string, plugin file and test keeps passing; Windows forms are `cfg!(windows)` branches in the functions that already compose the commands. The #624 details and the #625 heuristic removal follow the gate lift, never ride with it.
6. **A missing shell is the designed fallback.** If Claude cannot find bash, or pwsh is absent for Copilot, the hook fails, no record is written, and the baseline never latches off. Status stays estimated, which is exactly what the spec's `disableAllHooks` case already proves; Runner adds no detection of its own for this.

## Mission 1 — Claude Code, Codex and Copilot on Windows

What it touches:

- `session/hook_feed.rs`: the per-runtime gate; a Windows path-string helper (forward slashes) used by every command and env composition; the PowerShell reporter body builder beside `hook_command`; `HookFeed::start_powershell`, which writes the Codex reporter to `<feed>.ps1` exactly as `start` writes the `.sh` (decision 3); `clear_leftovers` and `StatusFiles::drop` also sweep `.ps1` and `.ps1.tmp`.
- `session/codex_status.rs`: `hook_command` returns the PowerShell form on Windows, ending in `'{}'`.
- `session/claude_status.rs`: the gate re-export and tests only; `APPEND_SCRIPT` is unchanged.
- `session/copilot_status.rs`: `install_plugin` adds a `powershell` key beside the existing `command` in every event entry, same Notification matcher, the body reading the feed from `$env:RUNNER_COPILOT_STATUS_PATH` and the generation from `$env:RUNNER_COPILOT_STATUS_GENERATION`; the file is identical on both platforms because Copilot picks the slot by OS. `report.sh` is still written everywhere, so `start_external`'s reporter check keeps working; if the crew wants bridge loss on Windows to mean "hooks.json gone" rather than "report.sh gone", the Windows reporter path is `hooks/hooks.json`.
- `router/runtime.rs`: `inject_codex_hooks`, `codex_status_args`, `claude_settings_args` and `copilot_status_args` use the per-runtime gate; `toml_edit::Value::from` serializes the PowerShell body (it contains `'`, `$`, `[`, `|`, `;`), and the body's lack of double quotes keeps the argv layer simple. `claude_settings_args` carries the `sh` command as today, with the forward-slash feed path.
- `session/manager/spawn.rs`, `session/pty_runtime.rs`, `session/manager/mod.rs`: gate call sites and env values.
- Tests: the Windows-empty assertions flip to per-runtime; new Windows-native reporter tests run the PowerShell body through `pwsh -NoProfile -Command` (and Windows PowerShell 5.1 where installed) with piped stdin covering pretty and large JSON, UTF-8 non-ASCII, feed paths with spaces and apostrophes, a missing feed directory (exit 0, nothing written), and teardown; the Claude `sh` reporter runs through Git's `sh` when present; the real PTY bridge tests gated `#[cfg(unix)]` get Windows counterparts or lose the gate where they are shell-agnostic; one test appends to a watched feed from another process to prove the single-file `notify` watch on Windows.
- Docs, in the same PR: `docs/arch/arch.md` §5.3 (the `--plugin-dir` sentence) and §5.10 (the Windows-agents sentence); `docs/arch/windows.md` first paragraph; `README.md` and `README.zh-CN.md` lose footnote ³ (hook status on both platforms for all three) and the 540 spec's Windows footnote closes; `docs/tests/archive/610-claude-hooks-windows-smoke.md`, `docs/tests/archive/610-codex-hooks-windows-smoke.md` and `docs/tests/archive/610-copilot-hooks-windows-smoke.md` in the shape of the [Codex](../../tests/archive/347-codex-hooks-smoke.md) and [Copilot](../../tests/archive/540-copilot-hooks-smoke.md) records; this plan's status and log.
