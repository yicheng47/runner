Implement **M6.8 — long-lived terminals** (`docs/impls/gpui-rewrite/m6-consolidation.md` §M6.8). Goal: a session's alacritty `Term` lives as long as the session, fed directly from the backend's output path; panes borrow it. Tab switches, route changes and re-opened panes re-render an existing grid instead of rebuilding one from a replay buffer. The backend's per-session output ring and everything that exists to keep it coherent are deleted. This is the Zed model (`~/repos/gui/zed/crates/terminal/src/terminal.rs`, architecture reference only, GPL, copy nothing): the terminal entity owns its `Term`; hiding a view hides a view.

## Why (the defect and the seam)

`surfaces/chat.rs` `ensure_owned_active_tab_attached` does `self.attached.retain(|id| active tab owns id)` on every tab activation, so the previous tab's `TerminalSession`s — and their `Term`s — are dropped; `mission_workspace.rs` does the same on route/mission changes (`attached.clear()` at 413/458/816/839/1470). Returning re-creates the session via `TerminalSession::attach` → `TerminalBridge::attach` → `session_output_snapshot` → `feed_snapshot_locked` (`runner-terminal/src/terminal.rs:754-766`): the backend's `output_buffer` ring (`manager/mod.rs:599`, 4096 chunks) replayed into a fresh `Term`. That ring is the webview-era replay source (xterm.js was recreated on every mount) and its only reader in the tree is this re-attach. M6.6 made the settle purge the ring and rely on a rows-nudge repaint to refill it; Node and crossterm coalesce two SIGWINCHes microseconds apart into "no change", so no repaint lands and the re-attached pane is blank until the next real resize. Patching the nudge keeps a racy contract around a buffer that should not exist.

## Design

1. **Registry.** `TerminalBridge` (`runner-terminal/src/terminal.rs:712`) holds strong `Arc<TerminalSession>` per live session id instead of `Weak`. A terminal is created eagerly on the first output for a session id with none (size from `session_last_size`, else the spawn size the backend reports) so output produced before any pane exists — a mission slot started while its pane is hidden — is captured from the first byte. Removed on `session/exit` and `session/archived` (and project archive). Resume/reset spawn a new child under the same id: replace the `Term` at that point (hook the backend's install point — emit a `session/spawned` event or reuse `session/updated` with a marker); a fresh child paints from scratch for every runtime. `chat.rs` / `mission_workspace.rs` `ensure_attached` becomes registry lookup; their `attached` maps keep per-pane state only and never drop a terminal. `TerminalSession::attach` no longer replays; `feed_snapshot_locked`, `resync_attached`, the seq-0 synthetic prefix and `Lagged` resync go.
2. **Feed path.** Feed the registry's terminals synchronously from the app's `SessionEvents::output(&OutputEvent)` implementation (bytes, under the `Term` lock, on the ingestion thread — what the PTY reader does in Zed), not from the JSON/base64 `AppEvent` broadcast that can lag. The broadcast keeps carrying `session/exit`, `session/updated`, `session/archived`. This also removes one base64 encode + decode and one JSON round trip per chunk (M6.7 finding; record it in the handoff, do not do the rest of M6.7). Keep `OutputEvent.seq` — `tui_ready_seq` (`terminal.rs:88,364`) and the `baseline_seq` transitions in `chat.rs:162` / `mission_workspace.rs:1423` depend on it; verify they still fire once the terminal sees the stream from the first byte.
3. **Delete in the backend:** `output_buffer`, `MAX_OUTPUT_BUFFER_CHUNKS`, `output_snapshot` / `ops::session::session_output_snapshot`, `purge_output_buffer`, the ring part of `purge_session_buffers` (keep whatever else it resets if still read — check `update_terminal_mode_state` consumers: the bracketed-paste flag feeds paste framing, the rest fed the synthetic prefix), `runtime_purges_on_resume`, `runtime_clears_on_resize` / `SessionState.clears_on_resize`, and the settle's purge + rows-nudge: `settle_pending_resize` becomes "persist `last_size` once per storm" and nothing else. Immediate ioctls, in-memory size reconciliation, kill/resume abandonment and the `--settings` composer from M6.6 stay exactly as they are.
4. **Multi-window**: unchanged semantics — secondary windows keep today's duplicate-chat placeholder (`windowing.rs` `refresh_chat_secondaries`); do not render one `Term` in two windows in this mission.
5. **Tests.** runner-terminal: replace the replay/snapshot tests (`terminal.rs:884-1205`) with registry tests — created on first output, survives view drop, removed on exit/archive, replaced on respawn, bytes never lost across a view re-attach, `tui_ready_seq` still advances. Backend: delete the purge/coherence tests, keep and re-pin the settle persist-once and width-chain tests, `make verify` green with CI ×10 budgets as today.
