## Why

Tagging `v0.6.0` today fires nothing: this branch has no `release.yml`, and `main`'s (`git show main:.github/workflows/release.yml`) is a Tauri matrix build with pnpm and `tauri-action` that the cutover tree swap deletes. Every shipped 0.5.x Tauri install polls `https://github.com/yicheng47/runner/releases/latest/download/latest.json` (`git show main:src-tauri/tauri.conf.json` lines 30-33, minisign `pubkey` there), so the first native release must also carry a Tauri-format update or those installs never move.

## Reference, not scripture

`~/repos/yicheng47/pulse/.github/workflows/release.yml` is the in-house native pattern (verify tag vs workspace version → Rust + Metal toolchain → Developer ID cert import → build/sign/notarize → Sparkle tools → signed appcast → attach to the release). Our `nightly.yml` already implements the cert import, `bundle-mac`, pinned Sparkle 2.9.5 tools, and the CI-green gate — copy those steps rather than pulse's where they differ. Secrets available: `APPLE_CERTIFICATE`, `APPLE_CERTIFICATE_PASSWORD`, `APPLE_ID`, `APPLE_PASSWORD`, `APPLE_TEAM_ID`, `SPARKLE_ED_PRIVATE_KEY`, `TAURI_SIGNING_PRIVATE_KEY`, `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`.

## Scope

1. **`release.yml`** — triggers: `push: tags: ['v*']` and `workflow_dispatch` with a boolean input `dry_run`. Job on `macos-15`, `timeout-minutes: 90`, `DEVELOPER_DIR` as in nightly. Steps: check out; **version guard** — for a tag, `./script/bundle-mac --print-version` must equal the tag minus `v` (the crate is hand-bumped to `0.6.0` before tagging; fail loudly otherwise), for a dry run use `${VERSION%-nightly}` and a `dry-run-<stamp>` release name; Rust toolchain (`rustup target add aarch64-apple-darwin x86_64-apple-darwin`), `rust-cache`, Metal toolchain, cert import and identity selection (copy nightly); `./script/bundle-mac --channel production` with `RUNNER_BUILD_STAMP`/`RUNNER_BUILD_SHA` computed once as nightly does → `target/release/Runner-<version>-universal.dmg`, signed, notarized, stapled; Sparkle tools pinned as in nightly; `generate_appcast --ed-key-file - --download-url-prefix "https://github.com/yicheng47/runner/releases/download/<tag>/" --link ... --maximum-versions 10` over a directory holding only this DMG → `appcast.xml` (the production feed `releases/latest/download/appcast.xml` resolves to whichever release is latest, so each release ships its own appcast); **bridge trio** — `tar czf Runner.app.tar.gz -C target/release Runner.app`, sign with `npx --yes @tauri-apps/cli@'@tauri-apps/cli@2.10.1 signer sign --private-key "$TAURI_SIGNING_PRIVATE_KEY" --password "$TAURI_SIGNING_PRIVATE_KEY_PASSWORD" Runner.app.tar.gz` → `Runner.app.tar.gz.sig` (never hand-roll minisign; the plugin verifies exactly the CLI's format), and `latest.json` with `version`, `pub_date`, `notes` (one line pointing at the release page) and `platforms.darwin-aarch64` **and** `platforms.darwin-x86_64`, both `{url: "https://github.com/yicheng47/runner/releases/download/v0.6.0/Runner.app.tar.gz", signature: <contents of the .sig>}` — the absolute `v0.6.0` URL, per the plan's carry-forward rule (every later 0.6.x re-uploads this same file; hard cutoff at 0.7.0: from then on no `latest.json`); **upload** all five (DMG, appcast.xml, tar.gz, .sig, latest.json) to a **draft** release for the tag (`gh release create <tag> --draft --verify-tag --title "Runner <version>"` then `gh release upload --clobber`); the workflow never publishes — publishing is the human's switch, because it flips `releases/latest` and every 0.5.x install starts updating. Dry run: identical, but the release is a draft named `dry-run-<stamp>` on a tag name that does not exist (drafts do not create tags) so the artifacts can be downloaded and inspected, then deleted by hand.
2. **`ci.yaml`**: `push`/`pull_request` branches gain `main` beside `gpui-nightly` — after the swap `main` must have CI, and nightly's "Require CI green" gate keys off it.
3. **`nightly.yml`**: `--full-release-notes-url` → `commits/main`; the `gh release create ... --target gpui-nightly` arm only runs if the rolling release is missing — change it to `--target main` for after the swap (the release exists, so it is dormant either way). Leave the two channel-isolation steps exactly as they are; they are the guard that a production publish never lands on the nightly feed and vice versa.
4. **`bundle-mac`**: only if `--channel production` turns out to need anything the nightly channel did not (it already names `Runner-<version>-universal.dmg`, bundle id `com.wycstudios.runner`, feed `releases/latest/download/appcast.xml`).

## Proof

The workflow cannot run here (secrets), so: `actionlint` if installed, otherwise `python3 -c 'import yaml,sys; yaml.safe_load(open(sys.argv[1]))' .github/workflows/release.yml`; `bash -n` on every multi-line `run:` block extracted to a temp file; a local rehearsal of the non-secret half — `./script/bundle-mac --channel production --dev` (ad-hoc signed; confirms the production names and plist) and the `latest.json` generator run against that bundle with a throwaway minisign-style key from `npx @tauri-apps/cli@'@tauri-apps/cli@2.10.1 signer generate -w /tmp/throwaway.key` (never the real secret), then `python3 -m json.tool latest.json` and a check that both platform keys carry the same URL and a non-empty signature. **Do not open the produced .app, do not tag, do not dispatch anything.** The real rehearsal is the human running the `dry_run` dispatch after landing.

## Gates

- `make verify` green (nothing Rust changed — formality), `git diff --check` clean, the YAML and shell checks above, the local production bundle's final line.
- Handoff: the step list, the exact `signer sign` invocation and how the `.sig` lands in `latest.json`, the dry-run design, and anything the production channel needed.
- **Do not commit, push, open a PR, tag, or dispatch.** Stop at a clean working-tree review on the feature branch.

reviewer: hunts — (1) the workflow publishing instead of drafting, or touching `releases/latest` by any path; (2) `latest.json` with one platform key, a relative URL, the URL of the current tag instead of the absolute `v0.6.0` one, or the signature file's contents mangled (whitespace, newline); (3) a hand-rolled minisign signature or an unpinned `@tauri-apps/cli`; (4) the version guard comparing against `0.6.0-nightly` or skipping on tags; (5) the appcast generated over a directory containing nightly DMGs, or the download-url-prefix pointing at the nightly release; (6) secrets echoed into logs (`set -x`, `echo`, `printf` of a key) — the private keys must only ever reach stdin or an argument of the signing tools; (7) CI triggers that still exclude `main`, or the nightly channel-isolation steps weakened; (8) the crew tagging, dispatching, or opening the bundle.
