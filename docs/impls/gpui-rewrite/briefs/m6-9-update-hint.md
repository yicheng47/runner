## What ships

A single accent-colored icon at the right end of the sidebar's Settings row, shown only while Sparkle has found an update that is not yet installed. That is the whole hint — no pill, no card (`main`'s `UpdatePromptCard` is **not** ported; this is a recorded deviation, decision 1 notwithstanding, by Jason's call on 2026-08-22 against the design in `design/runner.pen` → `cmp/SidebarC` → `sbFoot` → `sbSettings` → `sbUpdateIcon`).

Design (from the `.pen`): the Settings row is `[gear 14px] [gap 10] "Settings" [flex spacer] [circle-arrow-down 14px, $accent]`, row padding `[8,10]`, row `fill_container`; the sidebar-collapse toggle already lives in the titlebar (`app_shell.rs` ~222/490) and no longer belongs in the footer. `$accent` is `theme::accent()` (`#00FF9C` in the dark theme).

## Work

1. **Sparkle delegate → app state.** `crates/runner-app/src/updater.rs` wraps `SPUStandardUpdaterController` through objc2 `extern_class!` and only exposes `check_for_updates` / `automaticallyChecksForUpdates` / `lastUpdateCheckDate`. Add an `SPUUpdaterDelegate` object (objc2 `define_class!`, `NSObject` superclass, `MainThreadOnly`) implementing at least `updater:didFindValidUpdate:` (read `SUAppcastItem.displayVersionString` / `versionString`), `updaterDidNotFindUpdate:`, `updater:willInstallUpdateOnQuit:immediateInstallationBlock:` (optional; if implemented, return NO so Sparkle's standard driver keeps owning the install), and `updater:userDidMakeChoice:forUpdate:state:` / `updater:didAbortWithError:` so a user-skipped or failed update clears the hint. Pass it as the controller's `updaterDelegate` at `init_with_starting_updater` (currently `None`). Keep the delegate `Retained` on `NativeUpdater` for the controller's lifetime. Feed `Updater` a new field `available: Option<UpdateInfo { version: String }>` with a getter; the delegate reaches the `Entity<Updater>` through a weak handle + `cx.update` on the main thread (Sparkle calls delegates on the main thread — assert with `MainThreadMarker`). Notify observers when it changes. Non-macOS / unbundled stub: `available()` is always `None`.
2. **Footer icon.** In `surfaces/app_shell.rs` (the `settings_button` built around line 355–393): make the row `w_full` with the icon + label on the left and, when `global_updater(cx).read(cx).available().is_some()`, a `flex_none` 14 px × `app_zoom` `svg("circle-arrow-down.svg")` in `theme::accent()` pushed to the right edge (a `flex_1` spacer div or `justify_between`). Register the lucide `circle-arrow-down` SVG in `assets.rs` (24×24, stroke `currentColor`, width 2, same pattern as the existing icons). Tooltip on the icon: `Runner {version} is ready to install` (use the crate's existing tooltip helper if there is one — grep `Tooltip`/`tooltip` in `ui/`). The row's hover treatment is unchanged; the icon does not change color on hover.
3. **Click behavior.** Clicking the icon (stop propagation so the row's own click does not also open Settings) calls `updater.check_for_updates()` — with a found update Sparkle's standard driver resumes at its install prompt. Clicking elsewhere on the row still opens Settings as today. Observe the `Updater` entity from `AppShell` so the icon appears/disappears without a relayout trigger from somewhere else (`cx.observe(&updater, …)` at shell construction, `cx.notify()` in the callback — scope it, do not notify the world).
4. **Updates pane agreement** (`surfaces/settings/updates.rs`): when `available` is `Some`, show the version in the "Runner v{current}" block's line (e.g. a second muted line `Update available: v{version}`) so the pane and the footer agree. Nothing else in the pane changes.
5. **Dev escape hatch.** Outside a signed bundle Sparkle never finds an update, so add an env override read once at startup, `RUNNER_DEV_UPDATE_AVAILABLE=<version>`, that seeds `available` in the stub and macOS paths (debug builds only — `cfg!(debug_assertions)`), mirroring `main`'s `runner.dev.updateStatus` localStorage hatch. Document it in one line in the brief handoff.
