# M6 — Consolidation

Milestone plan for the work that follows UI parity: the verified defects and structural debt from the 2026-08-20 technical audit, plus the reopened hook-based session status (#347). Sits after M4 — M5 was closed 2026-08-21 (plan decision 13) — in the [program plan](plan.md) and runs during the Phase 6 daily-drive clock. Sizes: S < 50 lines, M 50–300, L > 300 or cross-cutting. Line numbers are as of `gpui-nightly` `9a2b218` and will drift.

## Why a milestone, not a backlog

M3–M4 are parity work: the gate is "same as `main`". Everything here is *beyond* `main` — fixes `main` also has, refactors the agentic build never volunteered, and one new capability. Left as a backlog it does not happen: the audit's own finding is that local patches accumulate and global refactors do not, unless someone schedules them. So M6 is a named stage with ordered missions and gates, like M4.

Two items that look like M6 are deliberately placed elsewhere:

- **Terminal selection and copy is M4.7**, not M6. xterm.js has selection and ⌘C natively, so its absence on the GPUI line is a parity gap and a daily-driver blocker, and it belongs under M4's exit gate.
- **Hook-based session status (#347, feature 52) is M6.2, right after the input-state mission (M6.1, promoted 2026-08-21)** — not pulled forward onto `main`. `main` is feature-frozen (plan decision 11, 2026-08-20): Jason will not carry two versions; the rewrite finishes, then the switch happens, then the work beyond parity starts. Feature 52 was specced against `src-tauri` paths; the port mapping is `src-tauri/src/*` ↔ `crates/runner-backend/src/*`.

## Landing rule

Everything lands on `gpui-nightly`. `main` is feature-frozen as of 2026-08-20 (plan decision 11): no new features, no ports back, one line of work until Phase 6 promotes `gpui-nightly`. Consequences: the M5 watermark records where `runner-backend` diverged from `src-tauri/src` and the diff is allowed to stop being adapter-shaped from M6 on; new migrations (the indexes in M6.2) are allocated on `gpui-nightly` and are deferred to cutover unless the M1 A/B gate (Tauri build and GPUI build alternately opening the same `runner.db` copy) is re-run to prove the bridge still works.

Sequencing with M4.6b (shell split): nothing in the app crate starts until it lands — it churns `main.rs`, `mission_workspace.rs`, `sidebar.rs`. Backend missions have no file overlap and can run alongside.

### M6.1 — Real input-state tracking for mission sessions — M, app + backend seam, **second in run order, right after the small M6.6** (added and promoted 2026-08-21, Jason: inaccurate draft detection is the most annoying daily defect)

Today "is the human typing in this slot" is inferred from bytes: printable input and pastes latch `local_input_pending`, Enter/Ctrl-C clear it, escape-prefixed traffic counts as activity only (M3.4), and the router's draft-aware DeliveryGate buffers deliveries behind that latch with a 10-minute abandonment backstop (M3.6). It was the only signal that could cross the Tauri webview boundary — xterm.js lived in the webview, the backend saw a byte stream — and it is wrong in the ways Jason hits daily: a draft typed then deleted still reads as pending; arrow-key navigation in a TUI menu reads as drafting; IME composition and mouse-mode clicks are invisible or misclassified; a TUI waiting on a y/n prompt looks like an idle agent with no human input. The native line removes the boundary: `TerminalInput` (IME), the key path (`send_key`), `TerminalSession`'s in-process alacritty `Term`, and pane focus are all Rust in the same process as the router, so the state can be observed instead of guessed. Design: a per-session `InputState` machine — `Idle`, `Drafting` (composer row non-empty, read from the grid relative to the cursor line, or IME marked text present), `Submitted`, `AwaitingHuman` (agent idle per M6.2's hooks while a prompt is on screen) — fed by key events before encoding, IME composition start/end, focus changes, and grid reads on the output edge; the DeliveryGate consumes it directly and the byte latch becomes the fallback tier for runtimes without hooks, the same shape as M6.2's `IdleDetector` demotion. What it retires: the 10-minute backstop (replaced by an explicit empty-composer observation), `suppress_local_input_busy` heuristics, and the activity-vs-draft guessing on escape sequences. Gate: a scripted two-agent mission where the human types, deletes, navigates a menu, composes Pinyin, and answers a y/n prompt, with the sidebar/feed status and nudge deferral correct at every step. Ships `Idle` / `Drafting` / `Submitted` from the native seam alone — no dependency on hooks; `AwaitingHuman` lands when M6.2 delivers the agents' own turn signals.

### M6.2 — Hook-based session status (#347 reopened 2026-08-20; spec `docs/features/52-hook-based-session-status.md`) — L, backend + status consumers, second M6 mission (was first until 2026-08-21)

The one structural fix on the coordination seam. Jason's 2026-08-01 won't-do is reversed: a reliable status detector needs the agents' own turn signals; the byte-flow `IdleDetector` (`session/pty_runtime.rs:37` 750 ms silence, `:49` 500 ms `RESIZE_GRACE`) cannot distinguish a permission prompt, a question, and an idle prompt — they are the same bytes-then-silence — and stays only as the fallback tier.

Scope as specced: spawn-scoped injection, nothing installed in the user's configs — claude-code via `--settings <file-or-json>` carrying a runner-generated hooks config; codex via its hooks system (managed `CODEX_HOME` mirror or `-c` overrides; re-verify against current codex-cli, the 0.145.0 findings are from July). Loopback receiver with per-session bearer token riding the existing env injection, fail-open handler. Per-runtime normalizers → `working` / `waiting` / `done` (+ `interrupted`); `RunnerStatus` gains Waiting and Done with a confidence tier (`hook` vs `heuristic`); freshness decay degrades to the heuristic instead of freezing. Phases: receiver + model → claude-code adapter → codex adapter → interrupt inference + decay.

What it retires downstream, confirmed per phase as it lands: the silence threshold and resize grace become fallback-only; turn-boundary delivery in the router (`DeliveryGate` / `SessionOutbox`, the 80 ms cooldown thread at `router/mod.rs:1179`, the 30 s reconciliation re-nudge at `:844`) keys off `done` instead of inferred idle. What it does **not** retire: `CLAUDE_LAUNCH_GATE_GRACE` 1500 ms, `SUBMIT_DELAY` 80 ms, the 120 ms paste sleep (`output.rs:449`), `RECENT_LOCAL_INPUT_WINDOW` 2 s — those cover input readiness of the agent's TUI, not status, and the renderer swap did not change them. Consumers ready today: sidebar attention rollups (needs-you tier), mission router nudge gating, blocked-inbox indicator, `mission_status` pending asks.

### M6.6 — Terminal resize smoothness (was the `RESIZE_SETTLE_MS` experiment) — S/M, backend + app, **landed 2026-08-21 (`6f020d4`)** (promoted 2026-08-21, Jason: resize feels worse than Zed's embedded terminal; small and felt on every window drag)

Traced 2026-08-21. On every frame of a drag the resize owner's `prepaint` (`runner-app/src/terminal/element.rs:739-756`) pushes the new grid size into `TerminalSession::resize` (`runner-terminal/src/terminal.rs`), which on the UI thread, synchronously: (1) calls `ops::session::session_resize` → `SessionManager::resize` (`runner-backend/src/session/manager/output.rs:486-551`), which runs a SQLite `UPDATE` (`repo::session::update_last_size`) **per resize event** and then takes a second pooled connection for a `SELECT … FROM sessions LEFT JOIN runners` (`runtime_clears_on_resize`, `:926`) just to learn the runtime's resize policy; (2) for full-repaint runtimes (claude, codex) parks the PTY ioctl behind a settle thread for `RESIZE_SETTLE_MS = 175` (`manager/mod.rs:58`), so the TUI receives no SIGWINCH during the drag; (3) reflows the alacritty `Term` — 10,000 lines of scrollback — under its lock. Result: the grid shows old content reflowed into the new width for the whole drag, then snaps when the one settled SIGWINCH finally makes the TUI repaint, with two DB round-trips per frame in front of every reflow. Zed (reference only) calls `set_size` in `prepaint` every frame, resizes its `Term` and sends the PTY resize to its event-loop thread immediately — no persistence, no debounce — so the TUI redraws continuously and the content tracks the drag.

Why the 175 ms exists: a `main`-era contract (M3.3). For full-repaint runtimes `main` purges the output ring and injects `ESC[2J ESC[H` on every width change so later replays are width-coherent, and xterm's fit-addon produced storms, so an un-debounced storm meant purge/clear flicker. On the GPUI line the ring only matters for replay on re-attach (`TerminalBridge`, M4.6e); the live grid is alacritty's. The ioctl never needed to wait for the ring — only the purge does. `settle_pending_resize` already holds the pieces: purge + in-band clear + a rows-nudge round trip that forces a fresh full repaint.

Scope: (1) ioctl immediately on every resize for all runtimes; keep the settle solely for ring coherence — at settle, purge + the rows-nudge so the TUI's fresh repaint lands in a clean ring — no in-band clear, see the addendum below (the 2026-08-21 width-chain invariants must hold: forks read the persisted size; it is written once per storm, not per frame). (2) Take both DB calls off the per-frame path: cache `clears_on_resize` in `SessionState` at spawn/resume; persist `last_size` at settle or from a background thread. (3) Measure before and after: owner `prepaint` time during a width drag over a codex slot and a shell chat, ioctls per drag. Gate: a drag over a live codex slot tracks like Zed's terminal with no end-of-drag snap; `make verify`; the M3.3 coalescing tests rewritten to the new contract, not deleted.

Addendum 2026-08-21 evening (Jason: Zed's embedded terminal leaves Claude's history alone on resize, Runner's does not — anthropics/claude-code#58906 is the same symptom from Claude's side). The history duplication is ours, not the TUI's: the settle's in-band `ESC[2J ESC[H` is broadcast to every attached live grid (`settle_pending_resize`, `output.rs:649-664` → `feed_encoded_locked`), and alacritty 0.26 implements `ESC[2J` on the primary screen as `Grid::clear_viewport` — it scrolls the whole viewport into scrollback (`term/mod.rs:1788-1801`, `grid/mod.rs:309-333`). So every settled width change files a copy of the stale, wrong-width viewport as history and the TUI's SIGWINCH repaint paints a second copy under it. (`main`'s xterm.js `clear()` wiped history instead — a different artifact from the same byte.) In the alternate screen the same bytes are a region reset, which is why Claude's `/tui fullscreen` renderer hides it for claude slots; codex and any primary-screen runtime still take it. The 175 ms window is the second source: the grid is already at the new width while the PTY is still at the old one, so the TUI's stale-width paints wrap into the new grid for the whole drag and the clear then files them. Zed never injects a clear — `Term::resize` reflow plus the TUI's own repaint is the whole story. Scope (1) therefore becomes: at settle, purge the ring and run the rows-nudge so the fresh repaint heads the clean ring; **never broadcast the clear to live grids** (re-attach replay is coherent without it, the purged ring starts with the repaint). Remove the `OutputEvent` clear and rewrite any test that pins it to pin the purge. Scope addition posted to the mission the same evening: Claude's fullscreen renderer on by default for claude-code spawns via a single `--settings {"tui":"fullscreen"}` composer, skipped only when the runner's own args already pass `--settings` (Runner owns the renderer for its spawns; the user file is not consulted) — see the brief.

### M6.8 — Long-lived terminals; delete the output ring — M, app + runner-terminal + backend, **landed 2026-08-21 (`3536c70`, merge `6cfae2d`)** (added 2026-08-21 23:10, Jason: blank pane on tab switch in the M6.6 nightly; "do we still even need the ring buffer?")

No. The backend's per-session `output_buffer` ring (`manager/mod.rs:599`, 4096 chunks) is the webview-era replay source — xterm.js was recreated on every mount — and its only reader in the tree is the pane re-attach (`TerminalBridge::attach` → `session_output_snapshot` → `feed_snapshot_locked`, `runner-terminal/src/terminal.rs:754-766`). It is still load-bearing only because the app drops its own terminals: `chat.rs` `ensure_owned_active_tab_attached` retains only the active tab's `TerminalSession`s on every activation and `mission_workspace.rs` clears its map on route changes, so coming back rebuilds a fresh `Term` from the ring. Zed has nothing like it: the terminal entity owns its `Term` for the terminal's lifetime; hiding a tab hides a view. M6.6's purge-then-nudge exposed the seam — Node and crossterm coalesce two SIGWINCHes microseconds apart into "no change", no repaint lands in the purged ring, and the re-attached pane stays blank until the next real resize. Fix the architecture, not the nudge: strong `Arc<TerminalSession>` per live session in `TerminalBridge`, created on first output and released on exit/archive, replaced on respawn; fed synchronously from `SessionEvents::output` (bytes under the `Term` lock, as Zed's PTY reader does) instead of the lagging JSON/base64 broadcast — which also retires one base64 and one JSON round trip per chunk from the M6.7 list; views borrow terminals and never drop them. Delete with it: `output_snapshot`, `purge_output_buffer`, `runtime_purges_on_resume`, `runtime_clears_on_resize` / `clears_on_resize`, the settle's purge + rows-nudge (settle = persist `last_size` once, nothing else), the seq-0 synthetic prefix and the `Lagged` resync. Brief: [briefs/m6-8-long-lived-terminals.md](briefs/m6-8-long-lived-terminals.md). Tactical alternative rejected: purge only when a repaint actually arrives plus a gap between the two nudge ioctls — ~40 lines that keep a racy contract around a buffer that should not exist. Landed the same night as `3536c70`; see the impl_log entry for the exit-releases-the-Term deviation and the folded-in queued-delivery semantics.

### M6.7 — Terminal render and ingestion performance (added 2026-08-21 from a read-only audit of the hot paths) — M, app + backend, after M6.1 unless streaming lag is felt first

Ranked by expected effect on perceived smoothness; "verified" = read in code, "inferred" = reasoned, not measured. The GPL guardrail holds — Zed's techniques are described, never copied.

1. **Every PTY chunk repaints the whole window** (verified). The waker feeds an unbounded channel; the drain bumps `revisions.terminal_wake` and notifies `AppStore` (`app_store.rs:239-262`), `main.rs:723-724` turns that into a `NativeRoot` notify, and the root's render (`app_shell.rs:49-93`) rebuilds sidebar, workspace, overlays and every pane. The M4.4 gate (`route.terminal_visible()`) only stops non-terminal routes — output from any attached session, including background panes and other tabs, re-lays-out the whole tree. Fix: terminal view as its own entity, notified per session; the shell only when its layout depends on it.
2. **Full grid walk + shaping every frame under the fair `Term` lock** (verified). `element.rs:812-1090` holds `term.lock()` — contended with the feeder at `terminal.rs:368` — across the whole `display_iter` loop: palette resolution (`:877-878`), procedural-cell classification (`:922-935`), a `shape_line` for the cursor cell (`:1022`). Nothing is cached between frames. Fix: copy the renderable content into a snapshot under `lock_unfair`, rebuild layout only when the grid changed (Zed's `sync` / `last_content`).
3. **Per-cell `String` + `Vec<TextRun>` allocation; batching only for pure ASCII** (verified, `element.rs:997-1001`, `:1036-1069`, `:1092-1109`). One non-ASCII or restyled cell breaks the run, so CJK/emoji-heavy or per-cell-coloured TUIs degenerate to one allocation + shaping request per cell. Fix: batch on style equality alone and pass the cell width as the forced advance to `shape_line` — that removes the grid-skew reason the spike introduced the ASCII-only rule.
4. **Procedural glyphs re-tokenize their path strings every frame** (verified, `glyphs.rs:420`, `:483/:500` twice per stroke, `:423-425` tessellation per cell, `:129-143` a content mask per cell). Fix: precompute per-glyph geometry once per (cell size, scale factor). Absorbs Tier 2's "glyph path pre-parse".
5. **~23 linear scans of every chunk before it is encoded** (verified: `output.rs:889` → `update_terminal_mode_state` `:832-868`, six scanners over 20 needles, each a full `windows(n).rposition` pass, `mod.rs:87-101`; `terminal.rs:706-710` adds three). Inferred cost ~180 K byte comparisons per 8 KB chunk — the same order as alacritty's parse. Fix: one `memchr`-driven pass for `0x1b` with a small state machine.
6. **~11 copies + a JSON round-trip per chunk** (verified: `pty_runtime.rs:655` `to_vec` → `output.rs:890` base64 → ring clone `:912` → `events.rs:51-59` `serde_json::to_value` → broadcast, where six subscribers deep-clone the payload — `app_store.rs:266`, `main.rs:321`, `:357`, `windowing.rs:56`, `mission_workspace.rs:290`, `terminal.rs:721` — five of them discarding `session/output` — then `terminal.rs:350` decodes). Fix: raw `Arc<[u8]>` to attached sessions on a side channel; JSON stays for low-rate events. Absorbs Tier 2's "typed PTY event transport".
7. **Lag-storm feedback loop** (verified). On broadcast `Lagged` (`terminal.rs:739-746`) `resync_attached` (`:803-821`) re-feeds the entire 4,096-chunk ring synchronously under `feed_gate` — exactly when the app is already behind; the same ring retains up to tens of MB per session (`output.rs:912`).
8. **Hover/link scan under sustained output** (inferred): `refresh_hovered_link` runs every prepaint (`element.rs:785-794`); its signature includes `last_seq`, so with ⌘ held during streaming `link_at` rebuilds a whole wrapped line per frame (`terminal.rs:619-696`). Mouse-move itself does not storm — `:620-622` gates on `changed` (verified good). Fix: a grid-changed flag, as Zed's hover path uses.
9. Zed techniques absent here, in words: cached content snapshot refreshed on term events only; `lock_unfair` held only for the copy; style-only run batching with forced cell-width advance; viewport-intersection culling that skips all cell work for off-screen terminals; notifies scoped to the terminal view. One thing this line usefully lacks: no cursor-blink timer, so no idle repaint source (verified).

Scope: items 1–4 are the app-side mission; 5–7 the backend side (no behavior change, `main`'s router/manager suites must stay green). Measure first: frame time with a streaming codex slot in a four-pane tab, CPU per MB of PTY output. Gate: a streaming agent in a background pane no longer re-renders the foreground; per-frame allocations on a static grid drop to zero; `make verify`.

## Not doing, and why

- **fsync on the event log.** Page-cache durability is the right trade for a local tool; the cost is a hard power loss mid-append, and the log's tail repair already handles a torn line. Recorded as a decision in `arch.md` under M6.4.
- **Renderer damage tracking beyond M4.6b.** PTY bursts are already coalesced (`try_recv` drain), non-terminal routes are gated (`route.terminal_visible()`), and gpui's `LineLayoutCache` reuses shaped lines; M4.6b's per-entity notify removes the remaining whole-window re-render. A dirty-row set out of alacritty is L and nothing currently felt justifies it.
- **A quit path.** The audit listed its absence as a defect; it was refuted — `stop_running_sessions_on_quit` (`bootstrap.rs:194-209`) is wired from ⌘Q, window close, and post-`run()`, kills the process group (SIGHUP → SIGKILL), and joins the forwarder (`lifecycle.rs:96-97`).
