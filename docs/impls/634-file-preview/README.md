## Decisions that bind

- **runnerd serves the files** (Jason, 2026-11-04). Resolving a session's root, listing folders, `git status`, the worktree list, reading a file and watching for changes all run in `runnerd` behind client-protocol requests and pushed events, so remote file access can later be served by the other computer's `runnerd` without a new model in the app. The app draws the tree and the file, highlights code and parses Markdown; `runnerd` carries no grammars and the protocol carries plain bytes.
- **The chosen root is saved by runnerd** (Jason, 2026-11-04): per chat, terminal and mission, in SQLite, so it survives restarts and follows the session's row. The recent-folder list is saved beside it.
- **One umbrella, merged as one PR** (Jason, 2026-11-04). Each mission branches from the umbrella and opens its PR against it, which lands as a fast-forward of the umbrella, since the repository allows only merge commits. The umbrella follows `main` by rebase, not by merging `main` in as AGENTS.md describes for umbrellas, keeps one commit per mission plus the docs and CI commits (Jason, 2026-11-05), and lands on `main` through #1157 with a merge commit.
- **Every platform** (Jason, 2026-11-04). macOS, Windows and Linux build and run every phase. A Linux piece that proves hard ships with the fallback named in the plan's Linux section and a follow-up issue rather than holding the umbrella.
- **The side panel's view contract is internal** (Jason on #1072, 2026-10-28). Files is the first view built on it, and Info and Sessions move onto it in m2. Third-party panel plugins stay deferred.
- **Ignored entries come from git.** `git status --porcelain=v2 -z --untracked-files=all --ignored=matching` reports each ignored folder once: in the Runner repository with `target/` built it lists 6 ignored entries in 17 ms, against 33,007 with `--ignored=traditional` (measured 2026-11-04). The same set tells the watcher which events to drop. No gitignore crate is added.
- **The operator drives the program** (Jason, 2026-11-04). The chat that runs the missions decides the crews' questions itself, merges each mission PR into the umbrella once review, CI and qa pass, rebases the umbrella onto `main` and starts the next mission, reporting each decision afterwards. The landing PR #1157 into `main` stays Jason's.
- **Live checks before the gate are scoped down** (Jason, 2026-11-04). Mission qa runs on macOS in the dark theme only; checks that need the real pointer (drags, resizing, hover-only states), remote access and the light theme are recorded as deferred, not run, and do not hold `needs-live-test`. The gate's own Verification run still covers them.
- **Markdown beyond the spec's list** (operator, 2026-11-05, under Jason's mandate): GFM tables and task lists render, task boxes read-only; inline and block HTML show as written; footnotes, math and anything else stay as text.
- **Linux's reveal row** (operator, 2026-11-04): "Open containing folder" through `xdg-open`, as the mission rail does, since Linux has no common call that selects a file.
- **The tree is resizable** (Jason, 2026-11-05, found in m4's live run): in the widened panel the divider between the file and the tree is dragged to trade width between them, saved as `file_tree_width` (160 to 480 px, 240 by default); the panel keeps its width. Since m7 the 420 px rule narrows the file first and never hides a tree that is on.
- **The file narrows first, and a tree that is on always shows** (Jason, 2026-11-05, from the umbrella's live run): as room runs short, the file narrows from its saved width down to the standard panel width while the tree keeps its width, and only then does the chat or mission give up its 420 px. The saved file width caps the file instead of reserving room ahead of the tree. The two-per-row Sessions roster is unchanged.
- **File links open in the side panel first** (Jason, 2026-11-05): a ⌘-click on a file path in any terminal opens it in a tab at its line in that surface's side panel when the panel and its Files view are on, the session is local and the path resolves inside the Files root, opening a collapsed panel on Files; anything else opens in the saved editor as before.
- **The side panel header holds the open surfaces as tabs** (Jason, 2026-11-05, after t3code; board '634 — Side panel surfaces · after t3code (2026-11-05)', `cwksG`), superseding option H's title and icon row, which grew with each view: each tab is the surface's icon and name, 28 px high, the shown one raised and semibold with a ×; then `+`, a gap and collapse.
- **Each surface opens once** (Jason, 2026-11-05): picking an open one switches to its tab, and Files stays one tab with one folder holding its own file tabs. × closes a tab and shows the one before it, or the empty list after the last.
- **The `+` menu** (Jason, 2026-11-05) lists the surfaces Settings offers, Info then Files, with a check mark when open and a key in a keycap, `I` and `F`; a click or the key while the menu has focus opens or switches and closes it, and Esc closes it. The keys act only while the menu or the empty list has focus, never globally.
- **The empty list** (Jason, 2026-11-05): a chat's panel with nothing open shows "Open a surface" over the same rows and keys, with "Press a surface's letter to open it"; the header shows only `+` and collapse, and the list takes focus when the panel opens on it.
- **A mission's Sessions roster is permanent** (Jason, 2026-11-05): always the first tab, with no × and never in `+`, so a mission never shows the empty list; `+` adds Info and Files. A surface offering one surface, such as a terminal-only tab or a chat with Info off, shows that tab permanently with no × and no `+`.
- **What opens** (Jason, 2026-11-05; the setting removed on 2026-11-06): a new chat's panel always opens on the list of surfaces, with focus left in the chat; a file opened from a ⌘-clicked terminal link opens the Files tab if it is closed and switches to it. The open surfaces are kept where the chosen view was, with the same lifetime: `chat_surfaces` replaces `chat_panel_view` and `rail_surfaces` replaces `rail_view`.
- **Changes waits for #1141** (operator, 2026-11-05): the design's dimmed "Coming with #1141" row is not built; #1141 adds the row, its key and its Settings switch.
- **Settings → Side panel → Panel's Views card is Surfaces** (Jason, 2026-11-05): Info and Files keep their switches, now meaning offered in `+`, turning one off closes its tabs, and each shows its key; the note says a mission always shows Sessions as its first tab, which cannot be closed.
- **Every open keeps a tab** (Jason, 2026-11-05): the preview tab is gone, as too hard to discover; a Keep button was rejected too. A click, Space, Enter, a Markdown link or a ⌘-clicked link opens the file in a tab that stays, and a file already open switches to its tab. Settings → Side panel → Files → Open with a single click is removed.
- **Zoom scopes to the file viewer while it has focus** (Jason, 2026-11-05): zoom in, out and reset, as bound or rebound, step or reset Settings → Side panel → Files → Font size there instead of the app's zoom; the tree and the rest of the app keep app zoom.
- **The tree beside an open file sits on the panel colour** (Jason, 2026-11-05): the app's `$panel`, one step lighter than the file on `$bg`; the standard-width Files view keeps its own background.
- **General → Open file links in is removed** (Jason, 2026-11-05): the stored `file_link_editor` stays, set only by the Open in control's chevron, and drives Open in and the editor fallback.
- **`files_read` returns image bytes** (operator, 2026-11-05; Jason reviewed the core change): an optional `want_bytes` brings a binary file's bytes under the same 10 MB limit and root check, so rendered Markdown draws local images while runnerd keeps owning every read.
- **Files opens wide with an empty view** (Jason, 2026-11-06; board `wNRzb`): once a folder is chosen, Files shows the tree and a file area, which lists the changed files or a quiet prompt. A tree that does not fit takes the panel until a file opens.
- **The file finder** (Jason, 2026-11-06; board `CGnPc`): ⇧⌘O and a search icon in the tree's header, names only, from anywhere in a chat or mission, centred over the whole view. `files_index` lists the root's files in `runnerd`, so this mission is `core-review`.
- **Code is always highlighted** (Jason, 2026-11-06): the Syntax highlighting setting is removed, as are the new-chat panel setting and the Settings header preview.
- **Closing Files gives the width back** (operator, 2026-11-06, Jason may overrule): closing the Files tab, or a surface list reset on re-entering a mission or chat, returns the panel to its normal width and keeps the file tabs, which come back when Files reopens. A file left open still keeps the panel wide while another surface's tab shows.
- **An open ignored file is read again, not watched** (m10, 2026-11-06): the watcher keeps dropping ignored paths, so that a build stays quiet; the view reads open ignored files every 3 seconds while Files shows, and skips redrawing one whose size and time have not changed. It costs a read of up to 10 MB per such tab per tick, against a new request, per-client state and per-file inotify watches in runnerd.
- **A repository's clean filters still run** (m11, operator under Jason's mandate, 2026-11-06): `git status` runs a `filter.<name>.clean` from the repository's config on a stat-dirty file, and Runner does not turn that off. It takes a repository whose local config someone set, which a clone does not bring and `safe.directory` stops for another owner, and Runner runs as that same user; blanking filters would change what status reports for a repository that normalizes content on purpose. Only `core.fsmonitor` is forced off.
- **One `git status` at a time per root** (m11, 2026-11-06): a view asking while one runs shares it, and the watcher, which must see the disk as of its event, waits for the next, which everyone then waiting shares. There is still no `git` timeout, so a status that never ends parks those waiting on it.
- **A saved root is forgotten only when it is gone** (m11, 2026-11-06): confirmed missing or no longer a folder. Any other error keeps it saved and shows the error with Try again. Whether an unmounted volume counts as gone is Jason's question in m11's pull request; today it does, as the spec says.
- **No CLI surface.** Agents already read files; the new requests are not exposed as `runner` commands.
