# 836 — implementation log

Dated record of how [#836](https://github.com/yicheng47/runner/issues/836) has moved, oldest entry first. The current state is in [README.md](README.md), and the phases in [plan.md](plan.md).

- **2026-10-08** — #836 filed as P1, the first step of remote access, with three routes in order: the same network, Tailscale, then a hosted relay.
- **2026-10-16** — The service's side of host enrollment went live. Phase 1 was specified on `main` (`0a65b80d`), with enrollment recoverable after a lost approval.
- **2026-10-18** — Jason set up the `nightly-remote` umbrella, following `main` by rebase, and the separate `remote-nightly` release ([#950](https://github.com/yicheng47/runner/pull/950)). Phase 1's codex duo mission was restarted once so the spec could be detailed first. It merged into the umbrella as [#945](https://github.com/yicheng47/runner/pull/945) after review, a hosted-service QA pass on macOS and Jason's live UI follow-up, which removed the app's service origin field. Jason released both routes together, Tailscale for users worldwide and the invite-only hosted service for mainland China, ordering the phases by how easily each is built and tested, and filed them as #951 to #954.
- **2026-10-19** — #951 closed, with its remaining live checks carried in the test record. The umbrella was rebased onto `main`, and Phase 1 was then squashed in place into one commit: Jason found the umbrella's many commits made rebasing hard, so each phase now lands as one squash-merged commit.
- **2026-10-19** — Client trust settled. Jason rejected trusting a signed-in account alone, because an administrator could then open any host's terminals. Pairing by QR code was considered and dropped: a desktop browser cannot scan it, and the person is usually away from the host when they want access. The model became a PIN set at the host and checked by a password-authenticated exchange, as Chrome Remote Desktop does, entered once per device, with a lock after five wrong tries, a notification for every new device and a device list with Revoke. Phase 1's per-enrollment host key would unpair every device at each reconnect and leave a Tailscale-only host with no key, so each host keeps one identity key for both routes, with Reset identity for a suspected leak. Jason asked how a person could know any of this; the spec now says what they are told, what they are shown, and what they can check in Runner's open-source host code, with the build caveat and the browser limit.
- **2026-10-19** — Phase 2 planned as m2, host trust, and m3, the companion protocol. Reading the code found that the Linux secret file ignores the item name, so the identity key needs its own file, and that the CLI cannot yet read a PIN without echo.
- **2026-10-19** — Reviewing the trust model, Jason noted that an office server could be shared by colleagues. The host's device list already allows it, and only the service's routing, which admits the owning account alone, would change; sharing stays out of 0.17, and the spec records the path. A device keeps a separate key for each host it pairs with.
- **2026-10-19** — Jason approved the plan. The spec additions were folded in with m2's brief, [`836-m2-host-trust.md`](../briefs/836-m2-host-trust.md), and m2 started as a codex duo mission; its Settings commit waits on the Pencil frames.
