# 836 — implementation log

Dated record of how [#836](https://github.com/yicheng47/runner/issues/836) has moved, oldest entry first. The current state is in [README.md](README.md), and the phases in [plan.md](plan.md).

- **2026-10-08** — #836 filed as P1, the first step of remote access, with three routes in order: the same network, Tailscale, then a hosted relay.
- **2026-10-16** — The service's side of host enrollment went live. Phase 1 was specified on `main` (`0a65b80d`), with enrollment recoverable after a lost approval.
- **2026-10-18** — Jason set up the `nightly-remote` umbrella, following `main` by rebase, and the separate `remote-nightly` release ([#950](https://github.com/yicheng47/runner/pull/950)). Phase 1's codex duo mission was restarted once so the spec could be detailed first. It merged into the umbrella as [#945](https://github.com/yicheng47/runner/pull/945) after review, a hosted-service QA pass on macOS and Jason's live UI follow-up, which removed the app's service origin field. Jason released both routes together, Tailscale for users worldwide and the invite-only hosted service for mainland China, ordering the phases by how easily each is built and tested, and filed them as #951 to #954.
- **2026-10-19** — #951 closed, with its remaining live checks carried in the test record. The umbrella was rebased onto `main`, and Phase 1 was then squashed in place into one commit: Jason found the umbrella's many commits made rebasing hard, so each phase now lands as one squash-merged commit.
- **2026-10-19** — Client trust settled. Jason rejected trusting a signed-in account alone, because an administrator could then open any host's terminals. Pairing by QR code was considered and dropped: a desktop browser cannot scan it, and the person is usually away from the host when they want access. The model became a PIN set at the host and checked by a password-authenticated exchange, as Chrome Remote Desktop does, entered once per device, with a lock after five wrong tries, a notification for every new device and a device list with Revoke. Phase 1's per-enrollment host key would unpair every device at each reconnect and leave a Tailscale-only host with no key, so each host keeps one identity key for both routes, with Reset identity for a suspected leak. Jason asked how a person could know any of this; the spec now says what they are told, what they are shown, and what they can check in Runner's open-source host code, with the build caveat and the browser limit.
- **2026-10-19** — Phase 2 planned as m2, host trust, and m3, the companion protocol. Reading the code found that the Linux secret file ignores the item name, so the identity key needs its own file, and that the CLI cannot yet read a PIN without echo.
- **2026-10-19** — Reviewing the trust model, Jason noted that an office server could be shared by colleagues. The host's device list already allows it, and only the service's routing, which admits the owning account alone, would change; sharing stays out of 0.17, and the spec records the path. A device keeps a separate key for each host it pairs with.
- **2026-10-19** — Jason approved the plan. The spec additions were folded in with m2's brief, [`836-m2-host-trust.md`](../briefs/836-m2-host-trust.md), and m2 started as a codex duo mission; its Settings commit waits on the Pencil frames.
- **2026-10-19** — m2 merged into the umbrella as [#957](https://github.com/yicheng47/runner/pull/957), with its live checks left for a `remote-nightly` build.
- **2026-10-19** — Terminal size settled before the rest of the protocol, as its hardest part. Jason asked for a separate buffer per client; a PTY has one size and its programs draw for that grid, so a second size cannot be made from the same output. Orca's source showed the same constraint met with one owner per terminal, a desktop banner with Take back, and no automatic restore when the phone leaves. With the phone set aside, Jason chose its browser form: opening a terminal in a browser takes control, leaving keeps the size, and typing at the desktop or Take back returns it. Reading the app found that a desktop pane pushes its own size on each repaint, which would undo any remote resize, so `runnerd` now ignores a size from anyone but the controller. #838 was left out of the rule. Jason could not reproduce it on the current build, so it stays open, to be rechecked in Phase 3 without blocking it.
- **2026-10-19** — The desktop side of Terminal size was drawn first as a banner over a pane that showed the browser's grid, which left a grid larger than the pane to be scaled or cropped. Jason proposed covering the pane instead, as the two-window case covers a duplicate chat, and the design moved to `design/specs/836-terminal-size.pen` as a card over a scrim with Take back. It needs no foreign-size rendering and keeps desktop keystrokes out of a terminal a browser is using; typing no longer takes control back, and watching a browser's session from the desktop is left for later.
- **2026-10-19** — Runner's designs moved from the repo's `design/` to `runner/desktop/` in the private `YeelinksCo/yeelinks_design`, where the server's and iPhone app's designs also go; the 836 files kept their names under `runner/desktop/specs/`.
- **2026-10-19** — Looking at the split-pane frame, Jason asked that a browser take over a split tab as a whole. The desktop's tab layouts are already `runnerd`'s tab nodes, so the companion protocol's overview gains tabs, which #952's read list did not have, and a browser opens a tab by attaching each of its terminals. Control stays per terminal, and the desktop draws one card over the whole tab. A per-pane card for a chat opened apart from its split was drawn and dropped: a chat has no sidebar row of its own, so it cannot be opened alone, and a mission opens as a unit too.
- **2026-10-20** — The umbrella was rebased onto `main` at 0.16.7, keeping #957's merge commit as the previous rebase had. Jason approved Terminal size's desktop frames. The rest of the companion protocol was written, and Jason approved it the same day. Reading the client protocol shaped it: a terminal's snapshot carries its whole scrollback, so `attach` caps the history a browser receives; a slow subscriber today gets a resync and must attach again, so a browser that falls behind gets a fresh snapshot instead; and a mission's ask is answered by a signal rather than in a terminal, so version 1 adds `answer` and `post` beside reads and terminals.
- **2026-10-20** — m3 merged into the umbrella as [#966](https://github.com/yicheng47/runner/pull/966), completing Phase 2's code. It has no live check; m2's still wait on a `remote-nightly` build.
- **2026-10-20** — Phase 3's spec drafted for Jason's review, contract first, since `runner_server`'s relay channel and browser channel build on it. CPace was proposed over SPAKE2: draft 21 is in the RFC Editor's queue, needs no trusted constants, and its ristretto255 pieces are already in the tree through `snow`. Pairing became `XXpsk3`, not Phase 2's `IK`, because the browser takes the host's key from inside the exchange. Reading the relay task found one WebSocket carrying every browser, so a slow phone could stall the others and the service would buffer without limit; records gained credit-based flow control, which is also what lets the protocol's Falling behind work over a relay.
- **2026-10-20** — Jason approved Phase 3 as drafted, without reviewing every detail, and asked for a codex crew. m4, the channel, started as a codex duo mission; the pairing notification and the Connected now row moved to m6, so m4 changes no app code and waits on no Pencil frames.

- **2026-10-20** — Jason approved counting every structurally valid `pairFinish` authentication failure, including tampering, since it cannot be distinguished from a wrong PIN; malformed frames and invalid CPace points do not count. He also made m5 terminals-first: overview, status and terminal requests with their pushes; mission feed, follow, unfollow, answer and post stay out of `welcome`'s `features` until a later mission, without a protocol version change. Credit flow control stays in m4.
