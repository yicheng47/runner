## Decisions that bind

- **Work lands on `nightly-remote`.** Each mission's worktree is cut from `origin/nightly-remote`, and its PR targets `nightly-remote`, which `ci.yaml` gates like `main`.
- **The umbrella follows `main` by rebase** (Jason, 2026-10-18), not by merging `main` in as `AGENTS.md`'s umbrella rule says: `git rebase --rebase-merges origin/main`, then each mission merged since the last rebase squashed in place as below, then `git push --force-with-lease`, only while no mission branch is open against it. Before pushing, check that the umbrella's own diff is unchanged and run the workspace gates; when `runner-cli` changed on both sides, also run `make guide-cli-check`.
- **Each phase lands as one commit** (Jason, 2026-10-19), so a rebase replays one unit per mission and `git revert` undoes one. Phase 1's [#945](https://github.com/yicheng47/runner/pull/945) was squashed in place on 2026-10-19; its five commits remain on the pull request. The repository allows only merge commits, so a mission's pull request lands as a merge commit, and the next rebase squashes it in place into one commit with the spec and plan commits before it, keeping each tree (Jason, 2026-10-21). m2 to m5 ([#957](https://github.com/yicheng47/runner/pull/957), [#966](https://github.com/yicheng47/runner/pull/966), [#975](https://github.com/yicheng47/runner/pull/975), [#976](https://github.com/yicheng47/runner/pull/976)) were squashed so on 2026-10-21.
- **Installed builds come from a separate release** (Jason, 2026-10-18; [#950](https://github.com/yicheng47/runner/pull/950)). `/nightly run remote` cuts `remote-nightly` from the umbrella, and `nightly` stays on `main`. Every channel shares the app's bundle id and data directory, so the umbrella adds no database migration: an install must be able to go back to `nightly` or production.
- **One route in this release** (Jason, 2026-10-23). The release ships the invite-only hosted service as a private beta. Settings → General's **Local only**, off by default, keeps Runner to one computer for anyone who doesn't want it (Jason, 2026-10-24, replacing the 2026-10-23 Remote access switch, which was off by default). Tailscale, planned with it on 2026-10-18, moved out into its own future feature, [#954](https://github.com/yicheng47/runner/issues/954). The phases were ordered by how easily each part is built and tested, so the relay came first.
- **The person decides who reaches their terminals** (Jason, 2026-10-19). The host trusts a device only after it has been paired with a PIN set at the host; the service decides whom it routes, and only the host decides whom it trusts. The spec's Client trust section has the model.
- **A terminal has one size and one controller** (Jason, 2026-10-19): the desktop app or one browser. Opening a terminal in a browser takes control, leaving keeps the size, and a card over the desktop pane, in the two-window overlay's style, returns it only through Take back. A browser opens a desktop tab or mission as a unit, and one card covers all of it. The phone's rule comes with #912, and [#838](https://github.com/yicheng47/runner/issues/838) stays outside it, rechecked in Phase 3 without blocking it. The spec's Terminal size section has the rule.
- **Clients are Runner apps** (Jason, 2026-10-21). The client is Runner on another computer, later the iPhone app, not a browser; the service keeps accounts and relays channels, and serves no terminal page or client code. With Tailscale one Runner reaches another directly. The spec's [Clients are Runner apps](../../features/836-web-remote-control.md#clients-are-runner-apps) has why.
- **It reaches `main` as one PR** once the relay route passes Jason's testing. Its briefs and test records stay on it until then. Landing retires the umbrella's CI trigger and the `remote-nightly` channel.
