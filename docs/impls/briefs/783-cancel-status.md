## The bug and the leading hypothesis

The #777 smoke run (`docs/tests/777-runtime-adapter-smoke.md`, findings 1, 2 and 5) cancelled a running tool. Claude Code (Esc), Antigravity (Esc, then one Ctrl+C) and Copilot (its two-Esc sequence) showed the cancellation in the terminal while Runner stayed Working. Copilot also kept its `copilot-2` approval interaction and had no outcome. A recovery prompt fixed all three. Codex passed, because its watcher waits for the rollout's native abort rather than the input interrupt flag.

Hypothesis, not yet proven live: #758 (`b55fe7bf`, shipped in 0.12.5) made Runner answer the kitty keyboard query in every pane. An agent that pushes `CSI > 1 u` then gets Esc as `ESC[27u` and Ctrl+C as `ESC[99;5u` (`runner-terminal/src/mappings.rs`, `encode_kitty_key`). The backend recognises only the single bytes `\x1b` and `\x03`, so the interrupt flag the watchers drain is never set (`runner-backend/src/session/pty_runtime.rs` `write_to`, about line 1295). `classify_local_input` (`session/manager/output.rs:17`) has the same single-byte test for clearing `local_input_pending`. The #758 PR says pi, Claude Code and Codex query the protocol and Antigravity pushes `CSI > 1 u` at startup. Copilot is unknown.
