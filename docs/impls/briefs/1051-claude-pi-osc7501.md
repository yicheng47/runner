## Problem and outcome

Phase 1 (#1400, shipped in 0.20.2) moved Codex to OSC 7501 with identity hooks only. Claude Code and pi still install full status hooks: chats take status from hooks unless the user turns **Status hooks** off, and missions always use hooks (`spawn_spec.rs` applies the switch to chats only). Since #1320, a hooks-off Claude Code or pi chat already gets status, waits, failures and unread badges from OSC 7501 (`StatusSemantics::program_status_without_hooks`), verified live in `docs/tests/runs/1320-osc7501-codex-hooks-off-mac.md`.

Jason's decision (2026-11-20): make the same move as Codex, OSC 7501 plus a version gate, with no hooks fallback. Outcome: Claude Code and pi take status from OSC 7501 in chats and missions, keep only identity hooks, lose the Status hooks switch, and require versions that send OSC 7501.

## Deliverables

1. **Identity hooks only (plus narrow pi UI prompt wait overlay).** Claude Code keeps `SessionStart` (conversation key and transcript path, including after `/clear`); pi keeps its `session_start` extension handler, `editor_draft` (draft delivery protection), and narrow `ui_prompt_start`/`ui_prompt_end` + `session_shutdown` handlers as a wait-only overlay deduplicated behind native OSC 7501 `blocked` so unannotated `ctx.ui.custom(factory)` dialogs — standalone or stacked over another prompt — show Needs you (`Unknown`) and hold delivery until prompt end or shutdown, while native/annotated waits show one wait and clear once and OSC 7501 retains authority for Working, Done, Failed and Interrupted (Jason, 2026-11-20). Add `UserPromptSubmit` (or pi's `input` equivalent) only if mission turn-start confirmation or mid-turn delivery needs it, as Codex did, and say why in the review handoff. Remove every other status hook for chats and missions: Claude's PermissionRequest, PermissionDenied, PostToolUseFailure, Elicitation, ElicitationResult, PreToolUse, PostToolUse, PreCompact, PostCompact, Notification, Stop and StopFailure, and all other pi extension status handlers.
2. **OSC 7501 is authoritative** for both runtimes in chats and missions (`program_status_authority`, scoped to the root record like Codex's `program_status_root_app` wherever a foreign root report could otherwise release a wait or swallow completion): `working`; `blocked` with its kind (`permission` → Approval, `question` → Answer, `auth` or absent → Unknown) holding crew delivery; `done` → Completed with an unread badge when unfocused; `error` → Failed; `idle`. Startup delivery (folder trust, first turn) and mission delivery hold and release keep today's behavior without status hooks.
3. **Outcomes the hooks used to give.** Keep **Interrupted** on Esc or Ctrl+C mid-turn and Failed on an API error, taking them from the transcript or key input where OSC 7501 has no signal (Codex's `program_status_transcript_outcomes` is the model). Claude Code's command approval, AskUserQuestion, ExitPlanMode review and MCP elicitation forms, and pi's confirm, select/input/editor and custom prompts, must still surface as waits through their `blocked` kind. Hook-only detail that OSC 7501 cannot carry, such as tool names or "Compacting context", is listed in the PR as a known loss rather than kept through a hook.
4. **Child records.** The root record alone decides Working, Done, the unread badge and crew delivery. Claude Code's `id=` child records (background tasks and subagents) never change those; they only add detail text such as "2 background tasks". Grok gets the same rule in phase 4; no Grok work here.
5. **Remove the switch and gate versions.** Drop `RuntimeLaunchOption::StatusHooks` for Claude Code and pi in **Settings → Agents → Launch** and ignore legacy saved `status_hooks = false` rows for them, as Codex does. Copilot, OpenCode and Grok keep the switch. Raise `min_version` in `runtime_metadata.rs` to Claude Code 2.1.295 and pi 1.1.0; the existing gate shows **Update needed** and updates on start. An agent that never reports, because the user set `CLAUDE_CODE_DISABLE_TERMINAL_TITLE=1` or `PI_PROGRAM_STATUS=0`, falls back to terminal activity.
6. **Docs.** `docs/guide/reference/supported-agents.md` and its zh-CN page (capability table, Status hooks row, minimum versions, the opt-out variables above), `docs/guide/guides/troubleshooting.md` and its zh-CN page, `docs/arch/runtime-integration.md`, `docs/arch/arch.md` where it describes these hooks, and `docs/tests/regression/runtimes.md` cases that assume Claude Code or pi hooks (RT-STATUS-01 to 05, 07, 08, 10, 11, 14, 15 and 18). Check parity with `python3 script/check-guide-translations.py`.

Non-goals: OpenCode, Copilot and Grok (phase 4), Windows verification, notifications (#904).
