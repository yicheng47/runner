## Deliverable

Hook-based status on Windows for all three runtimes, same vocabulary, same surfaces, macOS byte-for-byte unchanged (plan decision 5).

**Per-runtime gate (decision 1).** `hook_feed::hooks_supported(windows: bool)` becomes `hooks_supported(runtime, windows)`; Claude Code, Codex and Copilot return true on both platforms, everything else false. `inject_codex_hooks` reads it instead of its own `windows` short-circuit. Every call site follows: `router/runtime.rs` (four functions), `spawn.rs` `apply_runtime_args` (env for all three), `pty_runtime.rs` (three watcher selections), `manager/mod.rs` `start_runtime_watchers` (`install_plugin` now runs on Windows too). The `#[cfg(windows)]` tests that assert empty Windows args flip to the per-runtime truth.

**Forward-slash feed paths on Windows (decision 4).** One helper in `hook_feed.rs` renders a status feed path with `/` separators; every hook command and every `RUNNER_*_STATUS_PATH` env value goes through it. Rust-side `Path` handling is unchanged. The Claude rekey drop path is not touched.

**Claude Code.** No new reporter: `claude_settings_args` emits the same `sh` hook commands as macOS with the forward-slash feed path; `APPEND_SCRIPT` and `hook_command` stay as they are; `HookFeed::start` writes the `.sh` beside the feed as on macOS. Claude runs the command under its own Git Bash; if it cannot, no record is written and the baseline never latches off (decision 6).

**Codex.** `codex_status::hook_command` returns, on Windows, an inline PowerShell body ending in `'{}'`, injected exactly as today through `-c hooks.<Event>=[{hooks=[{type="command",command=…,timeout=2}]}]` with `toml_edit::Value::from` doing the TOML quoting. `--enable hooks --dangerously-bypass-hook-trust` are unchanged. Codex 0.153.4 here runs it as `pwsh -NoProfile -Command <body>` with the JSON payload on a stdin pipe that closes after the payload.

**Copilot.** `install_plugin` adds a `powershell` key beside the existing `command` in every event entry (same matcher on `Notification`, same `timeout: 2`), holding the same PowerShell body with the feed read from `$env:RUNNER_COPILOT_STATUS_PATH` and the generation from `$env:RUNNER_COPILOT_STATUS_GENERATION`; when the path env is empty it drains stdin and exits 0, like `report.sh`. Copilot picks the slot by OS, so the plugin file is identical on both platforms and macOS keeps running `command`. `report.sh` is still written on Windows, so `start_external`'s reporter check keeps working. Copilot 1.0.85 here runs `command` and `powershell` entries alike as `pwsh -nop -nol -c <body>`, with the parent env and the stdin payload; the transcript is `%USERPROFILE%\.copilot\session-state\<id>\events.jsonl`, which `copilot_home` already yields.

**The PowerShell reporter body (decision 3), one builder in `hook_feed.rs` shared by Codex and Copilot.** Contract, equal to `APPEND_SCRIPT`: copy stdin as raw bytes (`[Console]::OpenStandardInput()` into a `MemoryStream`; never `$input`, `Read-Host` or `Get-Content`, the console input encoding on this PC is gb2312 and would corrupt any non-ASCII prompt) into `<feed>.<8 hex chars>` in the feed's directory; then append one UTF-8 line `{"generation":"<env>","hook_event_name":"<Event>","payload_file":"<name>"}` through `[IO.File]::Open($feed, Append, Write, ReadWrite -bor Delete)` as a single write; on any failure remove the payload and still exit 0; the Codex form prints `'{}'` last. No double-quote character anywhere in the body: strings are single-quoted, a `'` inside a path is doubled, the JSON quotes come from `[char]34`, the newline from `[char]10`. No pwsh-7-only syntax (Windows PowerShell 5.1 must run it; test it there too). Inline, not a `.ps1` file, so execution policy never matters and `clear_leftovers` has nothing new to sweep. A Windows `HookFeed` constructor for the reporter-less Codex case sets the reporter path to the feed itself after creating it (today's `start_with_reporter` checks the reporter before the feed exists), so `drain`'s bridge-loss check still fires when the feed is removed.
