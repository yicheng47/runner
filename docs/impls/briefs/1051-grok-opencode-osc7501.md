Grok and OpenCode still take status from their status hooks and keep the switch. Phase 4 makes the same move for both, following phase 2's pattern. What the agents send, probed on 2026-11-20 against the installed binaries with Runner's probe reply (records are `:`-separated, `msg` and `title` base64):

- **Grok 1.0.89:** answers the `7501;?` probe, then root `app=grok` reports: `idle` at start; `working` with `msg` ("Waiting for response…", "Thinking", "Responding", the pending command); `blocked:kind=permission` with the command in `msg` when approval is needed; `done` with `msg` ("Turn complete in 2.5s."); a Ctrl+C cancel gives `working` ("Cancelling") then `idle`, with no `done`; `clear` on exit. No `error` or child record was observed. The #1051 table also lists `kind=question`, `kind=auth`, a `title` key and subagent child records; opt-out is `program_status = "off"`.
- **OpenCode 2.3.2** (program status since 2.1.0; source `packages/tui/src/context/{program-status.ts,session-tabs.tsx}`): answers the probe, then sends one root `app=opencode` summary plus one child record per pending session (`id=ses_…`). Root is `working` (with the session `title`), `blocked` with `kind=permission` or `kind=question` (or no kind when several sessions wait on different kinds), or `idle`. **It never sends `done` or `error`**: a finished turn is root `working` → `idle`, and each child ends with `clear`. Several sessions in one TUI make the root `N sessions working` / `N sessions need input`.

## Deliverables

1. **Identity hooks only.** Each runtime keeps only what identifies the conversation and confirms turn starts, as its hooks-off path does today: Grok's SessionStart and UserPromptSubmit reports, OpenCode's conversation-route identity reports. Remove every other status hook or plugin status report for chats and missions, and say in the review handoff what each kept hook is for.
2. **OSC 7501 is authoritative,** scoped to the root record (`app=grok`, `app=opencode`) in chats and missions: `working`; `blocked` with its kind (`permission` → Approval, `question` → Answer, `auth` or absent → Unknown) holding crew delivery; Grok `done` → Completed with an unread badge when unfocused; `error` → Failed; `idle`. Child records (Grok subagents, OpenCode per-session records) never change Working, Done, the unread badge or crew delivery; at most they add detail text. Startup delivery and folder trust keep today's behavior without status hooks.
3. **Outcomes the protocol does not carry.** OpenCode completion is root `working` → `idle`: Completed with an unread badge when unfocused, unless the turn was cancelled or failed. Keep **Interrupted** on Esc or Ctrl+C mid-turn for both runtimes (cancel-key pairing as in phase 2; Grok's `Cancelling` → `idle` is that case). Take **Failed** from a native non-hook source where one exists (a transcript or stored session error, as phase 2 did); if OpenCode has none, stop and report to Jason before opening the PR rather than keeping a status hook. Hook-only detail OSC 7501 cannot carry is listed in the PR as a known loss.
4. **Remove the switch and gate versions.** Drop `RuntimeLaunchOption::StatusHooks` for Grok and OpenCode in **Settings → Agents → Launch** and ignore legacy saved `status_hooks = false` rows for them; Copilot keeps the switch. Set `min_version` to Grok 1.0.89 and OpenCode 2.1.0; the existing gate shows **Update needed** and updates on start. An agent that never reports (Grok `program_status = "off"`, or no reply to the probe) falls back to terminal activity.
5. **Docs.** `docs/guide/reference/supported-agents.md` and its zh-CN page (capabilities, Status hooks row, minimum versions, the opt-out), `docs/guide/guides/troubleshooting.md` and its zh-CN page where they cover these runtimes, `docs/arch/runtime-integration.md`, `docs/arch/arch.md` where it describes these hooks, and the `docs/tests/regression/runtimes.md` cases that assume Grok or OpenCode hooks. Check parity with `python3 script/check-guide-translations.py`.
