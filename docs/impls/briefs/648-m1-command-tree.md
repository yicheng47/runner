## Deliverable

`runner` becomes a general CLI: every tool in the app's registry has a command, inside a mission nothing changes, and a caller is the person or a roster handle.

**Shared socket client.** Move `endpoint`, `connect_app` and the call-tool path out of `cli/src/mcp.rs` into code both binaries use. The crate has no lib target today and `mod ipc; mod mcp;` are declared only in `mcp_main.rs`; declaring the same module in both bin roots compiles it twice and trips dead-code warnings under `-D warnings`, so a `[lib]` target is the expected route. `runner-mcp` keeps working, including the `serve_directly` handshake from #621 and its two tests: mission 3 removes it (decision 8), but until then it is how these missions are launched and watched, so do not remove or stub it here. The client connects per command, calls one tool, and returns the result; a connect failure or timeout is exit 3 with exactly "Runner is not running. Open Runner and retry." on stderr.

**The command tree** (`cli/src/main.rs` and new modules beside it), exactly as the spec's command reference lists it: `status`, `project`, `role`, `crew` (slots as `add`, `set`, `remove`, `lead`, `order` by handle), `mission`, `chat`, `session`, the mission-scoped `msg`, `signal`, `ask`, and `call <tool> [json]`. Leave `spawn`, `ps`, `wait`, `stop <handle>` and `done` unimplemented; `runner help` names them as reserved for #562. `mission feed` prints the requested window only; `--follow`, `--types`, `--from` and `help agents` are mission 2. Every command takes `--json` (the tool's JSON result verbatim on stdout) and `-q` (only the id of the object created or changed); the default is a hand-rolled table or key-value block, readable without either flag. stdout carries data, stderr carries messages. Exit codes: 0 success, 1 the tool refused (its message on stderr), 2 usage or an unresolvable reference, 3 Runner not running.

**References** are resolved by the CLI with the matching list tool before the target tool is called, so no tool changes for this: roles by handle; crews and projects by id or exact name, an ambiguous name exiting 2 with the matching ids; missions and sessions by id or unique id prefix, an ambiguous prefix exiting 2 with the matches. `mission_list` omits archived missions and has no include-archived flag: decide how `mission unarchive` and `mission show` resolve an archived mission (full id only is acceptable) and say so in the handoff and the spec.

**Two modes, one identity rule.** The mode switch is `env::resolve()`. `Mission`: mission-scoped commands default to the caller's mission and handle, and `msg post`, `msg read`, `signal` and `ask` append to the event log directly as today, with no socket and no tokio runtime started. `OffBus`: mission-scoped commands need `--mission <id>` and go through the socket; without it they are a usage error, exit 2, naming `--mission` (this replaces today's soft notice and exit 0, deliberately). `Partial` stays exit 2. An explicit `--mission` that differs from the caller's own goes through the socket like an outside call. Outside, `--as <handle>` is passed as the tool's `from`; without it nothing is passed and the caller is `human`. `mission answer <question_id> <choice>` posts `human_response` with `{question_id, choice}` as the person, takes the id `mission show` prints for each pending ask (`pending_asks[].question_id`, the `human_question` event id), and refuses `--as`. `ask` outside a mission needs `--as` and exits 2 without it. `msg read` stays inside-only; outside it exits 2 and points at `mission feed`.

**Defaults and inputs.** `mission start`, `chat start` and `project create` use the current directory unless `--project` or `--cwd` (`--path` for projects) is given. `--goal` fills `goal_override`, and the title defaults to the goal's first line, else the crew name and the date. Long text comes from a flag or a file, and `-` reads stdin (`--goal-file -`). On `update` and `set`, an empty value clears an optional field. `crew add --effort` calls `slot_update` after `slot_create`.

**`runner status`** is the health check: it connects, reads the app version from the handshake, and prints the CLI version, the socket path, the sidecar's presence, and the mode (inside mission `<id>` as `@handle`, or outside). Remove the `status busy|idle` alias, `signal::run_status`, and its help text. The three launch-prompt lines in `router/prompt.rs` that say "no need to call `runner status`" lose that clause, along with whatever pins their text.
