# 任务

任务承载为同一个目标工作的智能体、各自的终端，以及共享的消息和问题记录。可以从已保存的小队启动，也可以先创建空任务，再按需添加成员。

任务从启动器页面启动：**⇧⌘M** / **Ctrl+Shift+M**、启动器的 **任务（Mission）** 条目、命令面板中的 **新建任务（New mission）** 以及小队页面的 **启动任务（Start mission）** 都会进入这里。选择小队，或按 **⇧Enter** / **Shift+Enter** 选择 **空任务（Empty mission）**，然后输入目标并按 **Enter**。任务使用启动器的项目和起始文件夹，启动后才创建标签页。任务标题取目标的第一个非空行（最多 60 个字符），否则为小队名称加日期，再否则为“Mission”加日期；可在任务菜单中重命名。在启动器默认页输入小队名称也能找到它，排在智能体和角色之后。拆分窗格的启动器没有任务条目，因为任务占据整个标签页；在拆分窗格中按 **⇧⌘M** 会显示启动器页面，不创建标签页。

任务标签页将标题栏、成员标签、消息流和输入框放在同一张独立卡片中，旁边是占满高度的侧面板卡片。每个任务分别保留侧面板的展开或收起状态、已打开的界面和当前显示的界面。打开“文件”或某个文件、点击终端链接以及收起面板都只影响该任务。新任务采用最近一次展开或收起的选择，重启后各任务也从该选择开始。面板、文件阅读区和文件树的宽度仍是共享设置。侧面板标题栏始终以无法关闭的 **会话** 标签开头；其后的 **+** 以标签打开 **信息** 和 **文件**，关闭它们会回到之前的标签。“文件”显示任务的检出，见[聊天、标签页与窗口](../guides/chats-and-windows.md#在侧面板中浏览文件)。在其中打开文件会把面板加宽到任务旁边，任务连同终端抽屉至少保留 420 px：窗口变窄时文件收窄到面板的常规宽度，树保持显示；加宽的面板中会话卡片每行显示两张。在成员终端或抽屉的 Shell 中 ⌘ 点击（Ctrl 点击）文件路径，会在此面板的标签页中打开并定位到该行，“文件”标签若已关闭会重新打开，见[在侧面板中阅读文件](../guides/chats-and-windows.md#在侧面板中阅读文件)。终端抽屉展开为任务下方的另一张卡片，标题栏保留 Shell 标签、+ 和隐藏按钮。展开的侧边栏、侧面板和抽屉之间均为 6 px 的调整大小间隙。抽屉保持已保存的高度；Shell 获得焦点时，其边框变亮，任务边框恢复普通状态。收起面板或隐藏抽屉可为任务留出更多空间。

## 目标与成员

启动小队任务时，Runner 为每个槽位启动一个会话，并将目标、角色指令、团队约定与协调指令交给每个成员。成员各自处理分工，并等待必要的交接。任务保存自己的成员列表，小队则保持为可复用的模板。

**空任务（Empty mission）** 启动后没有会话。空任务仅在本机可用；远程任务需要选择小队。从任务中添加角色并分配工作。每个加入的成员都会收到共享任务上下文。操作者可以在运行中添加或移除任意成员。移除成员会停止其会话，但保留任务历史。

指定的任务工作目录由成员共享。Runner 不会创建分支、worktree 或仓库副本。请在启动前建立所需隔离，并在目标中说明。

## 消息流与终端

消息流将消息、问题、回答和生命周期事件记录到持久事件日志。成员可以按代号给另一成员发消息、向小队广播，或请操作者作决定。Runner 将协调消息交给相关智能体；详细工作过程和输出保留在各自的终端中。

通过消息流的问题卡片回答问题。普通补充使用消息输入框。在开头输入 `@` 并选择成员，添加收件人标签；重复操作可选择多人。点击标签可移除，或在草稿为空时按 Backspace 移除最后一个标签。没有标签或开头提及时，消息会广播给小队。只有收件人会收到收件箱通知。正文中的提及仅作为文字。也可以[使用 CLI](../guides/drive-runner-from-agents.md)读取消息流、发送消息或回答待处理问题。

收件箱通知只在成员空闲时投递；回合中发送的消息会等到该回合结束。Claude Code 是例外：它会把工作期间输入的内容排队，并在下一次调用工具时展示给智能体，因此发给正在工作的 Claude Code 成员的消息会在其回合进行中送达。智能体终端中未发送的草稿会暂停收件箱投递，并显示 **收件箱等待中（Inbox waiting）**。根据屏幕识别的草稿，暂停至最后一次按键后的十分钟；输入法组合更新也算按键。十分钟未操作后，Runner 可能把通知追加到草稿后并一起提交。Pi 的原生草稿报告不受此上限限制。

退出应用或将终端控制权交给另一客户端时，未完成的输入法组合不再阻止投递。提交草稿或清空输入框后恢复投递；Codex 或 Antigravity 历史中仍可见的已提交文本不会阻止投递。终端重绘导致输入框移动时，Runner 会跟踪当前输入框，例如 Antigravity 和 Claude Code 的情况。如果确认输入框为空后投递仍暂停，请使用 **提交 / 清除（Submit / clear）** 重置输入跟踪。

Runner 自己输入的收件箱通知不算草稿。如果智能体没有接受它的回车，该成员会显示 **消息未提交 — 请按回车键（Message not submitted — press Return）**。智能体的回合结束或提示关闭时，Runner 会对这条通知再按一次回车，其余情况下大约每两分钟重试一次。只有你在通知出现后没有按过任何键，Runner 才会自动再次按回车。移动光标后仍显示 Runner 通知的标签，但需你自行提交；修改文字后则视为你的草稿。即使超过十分钟，Runner 也不会在自己遗留的通知上再输入第二条。智能体针对 Runner 的通知开始回合后，这段文字就不再是 Runner 的遗留通知，因此智能体历史中仍可见的同一条通知不会阻止投递。如果成员空闲且有未读消息，它的通知仍显示为未提交，或仍有草稿暂停投递，而 Runner 并没有尚未确认的回车，Runner 会重新检查输入框。只有终端光标仍停在这条通知上，或你此后在该终端中输入过内容时，通知才继续暂停投递；终端光标停在空输入框时，两种暂停都会解除。如果某个成员有未读消息、投递却暂停超过两分钟，Runner 会在消息流中添加一条警告，写明该成员和原因。`runner mission show` 会在 RECENT WARNINGS 下列出这条警告。仍在启动中的成员不会收到这种警告；启动状态可能持续整个首轮，长时间的回合同样不会触发。在空闲成员的终端里按回车而没有启动任何回合，不会阻塞它的收件箱：该成员约十秒内显示为忙碌，随后恢复空闲，等待中的消息随即投递。

消息流右侧滚动条会在滚动或悬停于消息流时出现，离开后隐藏。它显示你在长历史中的位置。拖动滑块、点击轨道或在其上滚动可移动消息流。接近末尾时新消息会让消息流保持在底部；阅读旧消息时，使用 **新消息（New messages）** 返回底部。

## 关联聊天与汇报

智能体从 Runner 聊天中启动的任务会关联到该聊天；从应用、终端或 Runner 外部智能体启动的任务不会关联。一个任务最多关联一个聊天：侧边栏把任务显示在该聊天下方，任务也向该聊天汇报。可在侧边栏中，或用 `runner mission link` 和 `runner mission unlink` 建立、改换或解除关联，见[聊天与窗口](../guides/chats-and-windows.md#聊天下方的关联任务)。只能关联智能体聊天，不能关联终端或任务成员，且聊天与任务须属于同一项目，或两者都不属于项目。在应用中归档聊天时会先确认并将其未归档的关联任务一并归档（在 CLI 中为 `runner session archive` 传入 `--with-missions` 可一并归档关联任务，省略则只归档聊天）；归档任一方都会保留关联，**设置 → 已归档** 仍可分别恢复聊天与任务，永久删除聊天则会解除关联。任务标题栏会显示关联的聊天，点击即可打开。

Runner 为每个任务给出一个状态：有待回答问题或成员等待输入或审批时为 **需要处理（Needs you）**；成员崩溃或其回合失败时为 **失败（Failed）**；Runner 重启时有成员正处于回合中、且该成员此后尚未运行新的回合时为 **已中断（Interrupted）**；有成员在工作时为 **工作中（Working）**；所有成员空闲 30 秒且没有待处理事项（包括 Claude Code 成员的后台任务和计划唤醒）时为 **已稳定（Settled）**；没有成员运行后为 **已结束（Ended）**。任务每次进入需要处理、失败、已中断或已稳定，Runner 都会向关联聊天发送一行指向该任务的汇报：

```text
[runner] Mission 01M6DD9ZQK4R8V2TBN5C7XW3EH "Fix the login bug" needs you. Read it with runner mission show 01M6DD9ZQK4R8V2TBN5C7XW3EH.
[runner] Mission 01M6DD9ZQK4R8V2TBN5C7XW3EH "Fix the login bug" was interrupted by a Runner restart. Read it with runner mission show 01M6DD9ZQK4R8V2TBN5C7XW3EH.
```

`runner mission show` 将这一状态显示为 `STATE`，与之并列的 `STATUS` 表示任务正在运行、已停止还是已完成。任务可以同时是 `STATE settled` 和 `STATUS running`：成员都已空闲，但其会话仍在运行。已中断的任务显示 `STATE interrupted (Runner restarted at <time>)`，成员表中回合丢失的每个成员显示 `interrupted`。

汇报会等到聊天空闲且输入框为空；只要有未发送的草稿，就一直等待。聊天空闲时，Runner 会重新检查暂停汇报的草稿，终端光标停在空输入框时，汇报即可送达。多个任务的汇报按从早到晚逐条送达。尚在等待的汇报会被更新的状态替换，因此忙碌过的聊天只会收到最新状态。工作中状态和成员之间的交接从不汇报。Runner 停止（更新、退出或 `runner daemon stop`）并在下次启动时恢复任务成员后，原本处于回合中的成员会回到空闲状态，那一回合已丢失：聊天会收到一次已中断汇报，并且在这些成员各自重新运行一个回合之前，任务不会稳定下来，因此给它们发消息即可继续。重启前已稳定的任务保持已稳定，不发送汇报。已停止的聊天会在恢复后收到等待中的汇报；已归档的聊天收不到汇报，其任务继续运行。从侧边栏或从另一个聊天的命令行关联任务时，会发送一条包含任务当前状态的汇报。启动或关联任务时加上 `--no-report`，可保留关联但不汇报。

## 权限

任务启动使用运行时的广泛访问模式，通常为 **Bypass** ；pi 使用受信任的工作区。角色已保存的权限参数不会改变这一策略。请在目标中写清限制，并据此选择工作目录。

**设置 → 智能体 → 启动** 中的 **Bypass** 和 **状态钩子** 开关仅适用于聊天。任务忽略这两个开关，仍保留宽松权限和投递团队消息所需的钩子。Codex 的 **远程插件目录** 开关也适用于任务。

## 停止、恢复与归档

- **停止成员** 仅停止该智能体。 **恢复（Resume）** 继续已保存的对话； **重新启动（Restart）** 为该任务成员开启全新对话。
- **停止任务** 会停止其成员。 **恢复（Resume）** 会恢复已停止的会话。
- **归档（Archive）** 停止活动成员并从活动列表移除任务。消息流仍可在 **设置 → 已归档（Settings → Archived）** 中查看。 **恢复（Restore）** 重新打开任务，但所有成员保持停止。使用 **恢复（Resume）** 继续已保存的对话。消息流会记录每次重新打开。

任务暂停时，侧边栏和折叠分组中的未读回复绿点会隐藏。未读回复仍被保存，恢复后如仍有未读内容，绿点会重新出现。暂停期间查看角色会话仍会将其回复标为已读。错误和审批指示器保持原有行为。

“完成”消息或空闲智能体并不自动意味着所有会话已退出。停止与归档都不会撤销仓库修改。

关闭 Runner 后，任务可以继续在后台服务中运行。此行为由 **设置 → 通用 → 退出 Runner 时（Settings → General → When Runner quits）** 控制。重新打开与恢复行为见[会话](sessions.md)。
