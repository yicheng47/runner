# Chats, tabs and windows

Arrange separate sessions into split tabs, organize them in the sidebar, and use multiple windows without losing track of which terminal you are controlling.

## Know the three surfaces

| Surface | What it holds |
| --- | --- |
| Window | A real operating-system window |
| Tab | A group of panes, represented by one entry in the Projects sidebar |
| Pane | One slot holding a single chat or shell session |

**⌘N** / **Ctrl+N** and **New tab** in the sidebar or the command palette show the launcher as a workspace page, with the recent tab’s project in an editable picker, its folder, and a dashed **New tab** row in Recents. With the launcher already showing, they use the tab the page opened from, or the most recently viewed tab if that tab is gone. A tab in Recents, or no tab, gives **No project**. The sidebar does not select or expand the preselected project. Remote computers use their own tabs and projects. The **+** beside Recents always starts with **No project**. A project’s **+** puts the row under that project and locks the page’s project picker to it, as in a split pane; see [Projects](../concepts/projects.md). **⇧⌘M** / **Ctrl+Shift+M** and starting from a crew keep the active project selected in an editable picker, with the row in Recents. The row stays where the page opened, whatever the picker or **Change** then do, and what you start files under the project the picker shows. No tab is saved until you start a chat, terminal or mission, which replaces that row. When the row has nowhere to show, in the Active view or under a collapsed section, **New tab** in the sidebar is selected instead, and the preselected project’s row is not. Choosing a project or dismissing its menu with Esc returns focus to the launcher’s search, where ↑/↓ move through the rows. The page has no pane header or split menu; the Runner mark and “Start something new” stay on every step. The **×** in the page’s top-right corner, the **×** that appears when you hover the row, and **⌘W** / **Ctrl+Shift+W** close the launcher and return to the previous tab or page, as does Esc on the default page. With no tab or page to return to, the launcher stays and shows no ×. Selecting any sidebar row also leaves the launcher. **⌘T** / **Ctrl+Shift+T** starts a shell in an available empty pane or a new tab. Use a [mission](../concepts/missions.md) when agents need a shared feed.

Archiving or closing the active tab, or archiving a mission on screen, shows the tab you viewed most recently, passing over one that is open in another window unless they all are. With no tab left, the launcher shows in Recents with **No project**. For about half a second after that landing, **⌘W** / **Ctrl+Shift+W** and a pane’s **×** do nothing, so a quick second press does not close the tab you just landed on; a terminal closes with no prompt and cannot be restored. Archiving one chat of a split leaves its pane empty.

Each pane is an island: a rounded card with its own 40 px header, separated from other panes and the expanded sidebar by 6 px. The outer inset stays 8 px, including the left edge when the sidebar is collapsed. The header holds the runtime mark, the name with its menu chevron and the account when available; at its right, the status, the Stop or Resume button, the split control, maximize in a split tab, and ×. The side panel is a separate island. Each chat or terminal tab keeps its own panel: whether it is open, which surfaces are open and which one shows. Opening or collapsing it affects only that tab; a new tab starts from the last open or collapsed choice, and after a restart tabs start from that choice again. Panel, file-viewer and tree widths are shared settings. Its toggle lives at the top-right of the pane area. The panel's header holds the surfaces you opened, **Info** and **Files**, as tabs; click one to switch to it, and the **×** on the shown tab closes it, showing the one before it. **+** after the tabs lists every surface with a check mark on the open ones and its key: click one, or press **I** or **F** while the list is open, to open it or switch to it, and Esc closes the list. Each surface opens once, and Files keeps its own file tabs. With every tab closed, the panel says **Open a surface** and lists them with the same keys, which work while that list has focus; a new chat's panel opens on this list, with focus left in the chat. A tab of only terminals gets a side panel holding the Files tab alone, with no **×** and no **+**, and the same toggle, width and resize as a chat's; in a tab that splits a chat with a terminal, the panel stays open and shows the last focused chat while the terminal has focus. The [Files view](#browse-files-in-the-side-panel) shows the project's files.

Use the **Stop chat** icon right after the status at the right of a chat’s header while it runs, or the **Resume chat** icon in the same place once stopped. The button keeps its place as the status changes: a longer status grows to the left, and while the chat is starting or resuming, which have no lifecycle button, its place stays empty. The status shows state only. In narrow panes, detail hides first, then the name truncates, then the account hides, then the status label hides and leaves its dot; the lifecycle and pane buttons stay visible. Stopped chats show a centered **Chat stopped** card with one **Resume** button and its current shortcut; × archives. Short panes drop the badge, shorten or hide the reason, and hide the title only if needed to retain Resume. **⇧⌘X** / **Ctrl+Shift+X** and **⇧⌘R** / **Ctrl+Shift+R** act on the focused chat. Click the chat’s name or its chevron to open its menu: **Rename…**, **Fork chat** and **Pin**, or **Unpin** when the tab is pinned. × archives, with confirmation when the chat is running. Double-click the name to rename it directly. Rename edits the name in place: Enter saves and Esc cancels. A terminal’s header shows no status, and its menu has **Rename…** and **Pin**. Closing a terminal pane with ×, the close shortcut or its sidebar action never asks for confirmation, even while a command runs; this also applies remotely. Any shell exit closes its pane, including a failed command used to exit the shell. Planned quit/update recovery still restores terminal panes.

Closing the focused pane in a split with **×** or **⌘W** / **Ctrl+Shift+W** moves keyboard focus to the surviving pane, so you can keep typing without clicking it. Closing an unfocused sibling keeps focus where you were working. If you move to another tab or input while a close or archive is pending, its completion leaves your new focus in place.

## Browse files in the side panel

Opening Files or a file, including from a terminal link or **⇧⌘O** (**Ctrl+Shift+O**), changes only the current tab’s panel. Switching tabs restores each tab’s surfaces and selected surface.

The **Files** view shows one checkout or folder as a tree with its git status. A chat or terminal in a project opens on its own checkout: the worktree its working directory is in, or the main checkout; a mission opens the same way from its working directory. A working directory below the checkout's top opens expanded and tagged `cwd`. Outside a project, the view asks which folder to show: type a path and press Return, click the folder button for the system folder picker, or pick one of your projects or recently chosen folders. Runner remembers the chosen folder for that chat, terminal or mission, across tab switches and restarts.

The header names the checkout, with a branch icon for a linked worktree, and counts its changed files. While `git status` runs it reads **Reading status…**, and the tree can already be browsed. Changed files carry a coloured letter: **M** modified, **A** added, **R** renamed, **U** untracked and **!** unmerged. A checkout with too many changes to mark, past 200,000 files, says so under the tree. A folder shows a dot when something beneath it changed, and deleted files are not listed. Gitignored entries, such as `target/`, or `.worktrees/` in the main checkout, are dimmed. The tree updates as files change on disk, keeping open folders and the selection. Outside a git repository the tree is plain, with no letters or count. Icons come from the icon theme chosen in [Settings → Side panel → Files](#set-up-the-side-panel), Catppuccin by default, which follows light and dark mode.

Click the checkout's name to open the picker: **Choose folder…** at the top; then every worktree of the repository with its branch and short commit, the main checkout first; then your projects for a chat or terminal outside a project, and recent folders. Typing filters the list, and a full path, starting at the root or at `~`, roots the tree there when you press Return. Right-click a folder for **Show files from here**, **Copy path** and **Reveal in Finder**, which is **Show in Explorer** on Windows and **Open containing folder** on Linux; a file offers the last two.

Click a folder to open or close it, and a file to [open it in a tab](#read-a-file-in-the-side-panel). With the tree focused, ↑ and ↓ move the selection, → opens a folder or steps into it, ← closes it or steps to its parent, and typing jumps to the next entry starting with those letters. When a remembered folder is gone, Runner opens the session's own checkout instead. When that is gone too, as after a mission's worktree is removed, the view says **This folder no longer exists** and offers the project's checkout or the picker. A chat, terminal or mission on another computer shows **Files aren't available here**.

## Read a file in the side panel

Click a file in the tree to open it in a tab above the file; each file you open keeps its tab until you close it. With the tree focused, Space or Return opens the selected file. A file already open switches to its tab, and switching tabs selects the file in the tree, opening its folders. The active tab shows ×, the others show it on hover, and a changed file's tab carries its status letter. Closing the last tab returns to the empty view.

Once a folder is chosen, Files widens the side panel: the file area takes the inner side and the tree moves to the outer edge. Until a file is open, the file area lists the checkout's changed files, one click from opening, or shows a short prompt when nothing changed or the folder is not in git. When the window has no room for both, the tree takes the panel until you open a file. A file you leave open keeps the panel wide on its other surfaces too. Closing the Files tab returns the panel to its usual width; your file tabs stay and come back when you open Files again. The tree button at the right of the tab strip hides or shows the tree, and the panel grows by the tree's width rather than squeezing the file. Drag the panel's edge to size the file, and drag the divider between the file and the tree to size the tree: the panel keeps its width, and the file never narrows below the panel's usual width. The chat, or the mission and its terminal drawer, keeps at least 420 px: when the window is too narrow, the file narrows first, down to the panel's usual width, while the tree keeps its width; only then does the chat or mission give up room. The tree shows whenever its button is on. A widened mission panel places two Sessions cards per row.

Press **⇧⌘O** (**Ctrl+Shift+O**), or click the search icon in the tree's header, to find a file by name from anywhere in a chat or mission: the panel opens on Files if it was closed, and the finder opens over the panel. It searches the names and folders of the files under the folder shown, skipping what git ignores. Type to filter, use ↑ and ↓ to choose, Return to open and Esc to close. With the side panel or Files turned off in Settings, the key goes to the terminal instead.

When the tabs outgrow the strip, it scrolls sideways with faded edges, and a list button with the count lists every open file with its folder; click one to switch to it. With the Files view focused, ⌃Tab and ⌃⇧Tab (Ctrl+Tab and Ctrl+Shift+Tab on Windows and Linux) move between file tabs, and ⌘W (Ctrl+Shift+W) closes the active one. With focus elsewhere, or no file open, ⌘W closes the pane as usual.

Files are read-only, shown with line numbers in the font and size set in [Settings → Side panel → Files](#set-up-the-side-panel), the terminal's by default. Code in about two dozen common languages, among them Rust, TypeScript and JavaScript, Python, Go, C and C++, C#, Java, Kotlin, Swift, Ruby, PHP, shell scripts, JSON, TOML, YAML, HTML, CSS, SQL and Makefiles, is highlighted in the colors of the [terminal palette](appearance.md#theme-and-palettes) chosen for light or dark mode; other files show as plain text. A large file shows its text at once and its colors a moment later. Long lines scroll sideways and are never wrapped. Drag to select text, double-click a word to select it, press ⌘A (Ctrl+A) to select the whole file, and press ⌘C (Ctrl+C) to copy; a selection can run past what is on screen. ⌘F (Ctrl+F) opens the find bar over the file, with the match count and the match-case and regular-expression toggles; Return and ⇧Return step to the next and previous match, and Esc closes the bar. ⌘-click (Ctrl-click) a line to open the file at that line in your editor. When the file changes on disk, the view reads it again and keeps its place. With focus in the file, its find field or a rendered page, ⌘+ and ⌘− (Ctrl+= and Ctrl+−) change only the viewer's text size, one pixel at a time from 8 to 32 px; this is the **Font size** in [Settings → Side panel → Files](#set-up-the-side-panel). Elsewhere, the tree included, they zoom the whole app. ⌘0 (Ctrl+0) resets the app's zoom everywhere, the viewer included.

A Markdown file opens rendered, unless Settings says otherwise: headings, lists and task lists, tables, quotes, code blocks highlighted as code, links, and images from the project. HTML in the file shows as written. Drag to select text on the page and press ⌘C (Ctrl+C) to copy it. The `</>` button in the tab strip switches to the highlighted source and back, and ⌘F (Ctrl+F) on the rendered page switches to the source to search it. A link to a web page opens in your browser, and a link to another file in the folder shown opens that file in a new tab; a link that leads outside the folder does nothing.

The **Open in** control at the right of the strip shows the app the file opens in; click it to open the active file there at the line in view. Its chevron lists the editors Runner finds on your PATH, among Zed, VS Code and Cursor, then **Default app** and **Reveal in Finder**, which is **Show in Explorer** on Windows and **Open containing folder** on Linux. The chevron is where you choose your editor: the one you pick is what the control opens, and what ⌘-click on a path in a terminal falls back to when the side panel cannot show the file.

⌘-click (Ctrl-click on Windows and Linux) a file path in a terminal to open it here: in the side panel of that chat, terminal tab or mission, in a tab at the path's line, with the line selected; a file already open switches to its tab and scrolls to that line. A collapsed panel opens, the Files tab opens if it was closed and shows, and the panel widens as an opened file does; the terminal keeps focus. This happens when the side panel and its Files view are on, the session runs on this computer, and the path is inside the folder the Files view shows; a Markdown file cited at a line shows its source there. Any other path opens in the editor picked with **Open in**, and URLs open in your browser. Hovering a link names where the click will open it.

A binary file shows its name and size with **Open in default app**. A file over 10 MB is not read: it shows its size and an **Open in** button for the control's app. Files git ignores, such as logs and build output, are read again every few seconds instead of being watched. A file deleted while its tab is open keeps the last version read, dimmed under a banner saying it was deleted, and its tab carries a red **D**; **Close tab** is the only action.

## Set up the side panel

**Settings → Side panel** has two pages. On **Panel**, turning off **Show the side panel** hides the panel and its toggle in every tab; the switches below keep their values, dimmed. **Info** and **Files**, each shown with its key, decide whether **+** offers that surface in every chat, terminal tab and mission; turning one off closes its open tabs. With only one on, a chat shows that surface's tab alone, with no **×** and no **+**, and a chat or terminal tab with both off has no panel. With Files off, ⌘-click (Ctrl-click) on a path in a terminal opens the file in your editor. A mission always shows Sessions as its first tab, which cannot be closed.

On **Files**, **File icons** chooses the tree's icons: **Catppuccin**, which follows light and dark mode, **Material** or **Minimal**. **Font** sets code and Markdown code blocks in **Same as terminal**, the bundled JetBrains Mono, or any monospace font installed on the computer, the list **Settings → Terminal → Font family** shows. A saved font that is no longer installed shows as JetBrains Mono and stays chosen. **Font size**, 8 to 32 px like the terminal's, follows the terminal's font size until you change it, and rendered Markdown text scales with it. **Markdown files open as** **Rendered** or **Source**; the `</>` button still switches a tab between the two.

## Split and navigate

Use **⌘D** / **Ctrl+Shift+D** to split right and **⇧⌘D** / **Alt+Shift+D** to split down. Search for an agent or role in the empty pane’s launcher, choose **Terminal** for a shell, or select a chat from the sidebar. In a split tab, drag the six-dot grip before a pane’s runtime mark to reorder the layout; the layout picker offers common arrangements. The maximize button beside a pane’s split control, or **⇧⌘↩** / **Ctrl+Shift+Enter** for the focused pane, lets that pane fill the tab while the other panes keep running, hidden. The same button, highlighted while the pane is maximized, or the shortcut restores the split with its sizes. Moving to another pane of the tab, from the sidebar, with **⌘[** / **⌘]** (**Ctrl+[** / **Ctrl+]**) or through an attention jump, restores the split and focuses that pane; splitting the maximized pane restores the split first, and closing it leaves the rest of the tab split. Maximize is not saved: relaunching, reconnecting and restored windows show the split. Splitting is bounded by the available window size. New windows have a fixed minimum based on the saved sidebar width and zoom when they open, with enough height for the sidebar’s fixed controls. Later zoom or sidebar changes do not update an open window’s minimum.

Use **⌘[** / **Ctrl+[** and **⌘]** / **Ctrl+]** to move focus between panes. **⌘1–9** / **Ctrl+1–9** selects the corresponding visible sidebar row: a tab or mission in either view. **⇧⌘[** / **Ctrl+Shift+[** and **⇧⌘]** / **Ctrl+Shift+]** move through recently viewed pages.

Drag files from Finder or File Explorer onto a chat pane, a mission drawer terminal or a mission slot to insert their paths at the prompt, quoted as when you paste files. The terminal highlights while the files are over it and takes focus when you drop them; nothing runs until you press Return.

Programs in a pane, such as Neovim, Helix or tmux, can copy text to your clipboard with OSC 52 while a window shows that pane in its active tab; a copy from a pane no window shows, including one hidden behind a maximized pane, is dropped. On Linux, a copy to the primary selection goes to the primary selection. A copy over 1 MiB is ignored, and in a remote window the text lands on the computer you are using. Programs cannot read your clipboard this way.

For shell splits, Runner follows the shell's reported working directory. It installs that reporting for zsh and bash on macOS. Windows shells without their own directory-reporting prompt use the original launch directory for a split, even after `cd`.

## Find in a terminal

Press **⌘F** / **Ctrl+Shift+F** in a chat pane, a terminal, a mission slot or a mission drawer terminal to open the find bar over the terminal’s top-right corner; the terminal keeps its size. Text selected in the terminal fills the query, and pressing the shortcut again while the bar is open selects the query. Each pane has its own find bar, which keeps its query until you close it. On Windows and Linux, **Ctrl+F** still reaches the shell.

Matches update as you type, across the output and its scrollback, including text that wraps onto the next line. A plain query ignores case; turn on **Aa** to match case and **.\*** to search with a regular expression. A plain query also ignores combining marks, emoji variation selectors and joiners, which the terminal keeps beside the character they modify, so selected or pasted text such as a decomposed é, ❤️ or a joined emoji is found. A decomposed e with a combining accent then also finds a plain e, while a precomposed é stays distinct, and a query of only such marks counts as empty. A regular expression cannot match the marks themselves. The count shows the current match and the total, up to 1000+. It reads **No results** or **Invalid regex** in red, and an invalid pattern keeps the last matches highlighted until it is valid again. Every visible match is tinted amber and the current one is solid amber.

Matches are numbered from the newest output. Enter or **⌘G** / **F3** moves to the next, older match, and ⇧Enter or **⇧⌘G** / **Shift+F3** to the previous, newer one; both wrap at the ends. The terminal scrolls only to bring an off-screen match to the middle. While the bar is open, new output updates the matches and the count, the current match stays on its text, and once a match is selected the view stays where it is.

Esc closes the find bar while it has focus; click the terminal to give it focus, and Esc then goes to the program. Closing with Esc or **×** clears the highlights and scrolls the terminal back to where it was before you opened find; switching to another tab or mission, or from a mission slot to another slot or the feed, closes find the same way. A mission drawer terminal stays on screen when you switch slots, so its find stays open. A program using the alternate screen, such as `less`, `vim` or a full-screen agent interface, has no scrollback there, so find searches only the visible screen and the bar says so.

## Organize the sidebar

Use the sidebar context menus to rename and organize tabs, group them into folders, and pin work you return to often. A chat row’s menu lists **Rename…**, **Fork chat** and **Pin**, then **Archive** after a separator; a split tab’s lists **Rename tab…**, **Pin** and **Archive all**, which archives every pane; a terminal’s lists **Rename…**, **Pin** and **Close terminal**. [Projects](../concepts/projects.md) group work by directory; folders organize sidebar entries. Status markers show activity, attention and stopped sessions. Use them to find the terminal to inspect, rather than treating an idle marker as a completed review.

Use the list-filter button beside Search or **⌘.** / **Ctrl+.** (**Switch sidebar view**) to switch between **Projects** (the default) and **Active**. The shortcut also expands a collapsed sidebar. Runner remembers your choice. Active lists **Agents** and **Terminals**, hides an empty heading, and shows each heading's visible count. Agents holds chats and missions together, and a chat heads the same linked group of its missions as in Projects; an ended mission stays in its group until you archive it. Click a heading to collapse or expand it; Runner remembers which headings are collapsed. Active includes running chats, terminals and missions with live members, including idle agents and shells. Under each heading, rows keep the order their tabs and missions were created, oldest first, and new work joins the end; status changes, unread output, renames and restarts never move a row. The second line shows the project and relative folder, or the working directory for work outside a project. Renaming edits only the title, keeping this location visible.

Active has one row per tab, like Projects. A tab with any agent pane appears under Agents; a tab of only terminals appears under Terminals. Split tabs use the split icon and tab name, derived from the first chat or terminal pane unless you name the tab. Selecting a row opens its tab on the pane that needs attention, or on the tab's last focused pane when none does. Mission members roll up into one mission row. A stopped chat or unlinked mission stays only for unread output or an error, while a linked mission stays in its group until archived; selection alone does not keep a row visible. A finished unread response stays until viewed, and an error stays until cleared. Every running terminal is listed, including idle shells; an exited terminal closes immediately. Terminal activity uses Runner's existing output-based Busy estimate; drawer terminals are excluded. Active keeps context menus; drag and reorder remain in Projects.

The footer shows live weekly Codex, Claude Code and Antigravity CLI usage when those agents are installed and enabled. Antigravity CLI shows its **Gemini Models** weekly pool percentage in the footer, and lists its **Gemini Models** and **Claude and GPT models** pools separately in the Usage popover and **Settings → Usage**. When enabled sidebar badges exceed the available footer width, Runner keeps the highest-usage badges that fit followed by a compact `+N` badge; clicking the strip still opens all agents in Usage. Antigravity CLI usage checks require **1.5.8 or newer**: signed-out checks never open browser login automatically, showing a terminal `agy login` prompt instead, while older or unidentified builds leave Antigravity CLI usage unavailable without running sign-in checks. Open **Settings → Usage** to show or hide all badges or individual agents, choose a check interval (5, 15, 30 or 60 minutes), and show or hide the 5-hour window. The compact Sidebar preview sits above the badge switches and follows your choices, with the same usage control, Host button and Settings gear as the footer. The usage control is transparent at rest and shows its button background on hover. Its sample controls are inactive; at narrow widths, the sample moves below its label. Hiding usage keeps Host and Settings in place. Weekly limits always remain available in Usage; Claude Code shows the active account. The popover’s Settings action opens this page. When a refresh fails or Runner restarts, it keeps the last numbers it received and their age; after a restart, a limit that has reset since those numbers arrived is not shown. Select it to open Usage, which lists every usage window and when it resets. The separate gear opens Settings. An available Runner update appears beside the Runner name.

Codex also shows a separate **Credits remaining** balance below its limits in both Usage and Settings → Usage. Balances are rounded to the nearest whole credit for display, while the exact underlying value is retained; unlimited credits show **Unlimited**, and missing credit data shows **Unavailable**. Credits remain visible when the 5-hour limit is hidden or no quota windows are reported. A failed refresh silently keeps the last balance and its original age; quota reset times do not expire credits. Sidebar percentages and near-limit alerts continue to use quota windows.

**⌘K** / **Ctrl+Shift+P** opens the command palette to find chats, missions, roles, crews and commands. **⌘S** / **Ctrl+B** toggles the sidebar.

## Missions under the chat that started them

A mission that an agent starts from a chat is linked to that chat. In Projects, the chat's tab heads a group, with link lines from the chat to each linked mission. Each mission row shows the mission's state: a hand when it needs you, an alert when it failed, an amber pause when a Runner restart interrupted a member mid-turn, a spinner while it works, and a dot when it settles with output you have not read. Once no member runs, the row looks like any stopped mission: a grey flag, and the dot only while it has unread output. On each change to needs you, failed, interrupted or settled, the chat receives one short `[runner]` line; see [Drive Runner from agents](drive-runner-from-agents.md#start-from-a-runner-chat).

Use the chevron on the chat's row to collapse the group into one row that shows how many missions it holds and the most urgent state, in the order needs you, failed, interrupted, working, settled. Runner remembers collapsed groups. The chevron works the same in Active, and collapsing a group in either view collapses it in both. In Active, the collapsed row keeps its height and shows this summary in place of the folder line, with the most urgent state's icon at its end; expanding brings the folder line back. A collapsed group's missions get no number shortcuts. Dragging or pinning acts on the whole group: Pin and Unpin on a linked mission pin or unpin the chat's tab. Archiving a chat that has unarchived linked missions asks for confirmation and archives those missions with it (use **Unlink from <chat>** first to keep a mission active, or `runner session archive` without `--with-missions` from the CLI to archive only the chat); archiving a mission takes it out of the group.

To link a mission by hand, drag its row onto the middle of an agent chat's row, which then reads **Link to <chat>**; the top and bottom of the row keep the usual reorder markers. Dropping between a group's missions links the mission to that group's chat at that place, and a tab holding several agent chats asks which one. A mission's menu has **Link to chat**, a submenu with a search field over the agent chats in the mission's project, and **Unlink from <chat>** when the mission is linked; in Active, the menu is the way to link. Only an agent chat that is not archived can be linked, in the mission's project or with both outside a project, and linking a mission that already has a chat moves the link. The chat receives one `[runner]` line with the mission's current state.

Drag a linked mission out of its group to a place among the project's rows to unlink it there, or among the Pinned rows to unlink and pin it. **Unlink from <chat>** puts the mission right below the group, or back in its project unpinned when the group was pinned. When the last mission leaves, the group dissolves and the chat keeps its place. The mission's header reads **linked to <chat>**, which opens the chat, or **linked to <chat> (archived)**. A window showing another computer shows its groups and, when the host supports it, links or unlinks missions with the same menu, picker and drag controls.

## Use another window

Press **⇧⌘N** / **Ctrl+Shift+N** to open another Runner window. If a chat or mission is already being driven in another window, Runner shows an **Open in another window** overlay. Use its handoff controls to focus or bring the subject here. A terminal has one owning window at a time; the overlay prevents two windows from sending competing input.

Close the window with **⇧⌘W** / **Alt+F4**. Its layout is saved, and sessions can keep running. On Windows, closing the last window follows **Settings → General → When Runner quits**. On macOS, quitting the application is separate from closing a window.

On Windows, launching Runner while it is running, from the Start menu, a shortcut or the taskbar, brings the running app forward instead of starting a second copy: its main window reopens if you closed it and restores if it is minimized. A launch while Runner is quitting waits for it to exit and then starts; if Runner is still running after 10 seconds, the launch starts another copy anyway. The development build and the installed Runner are separate apps and can run side by side.

**⌘W** / **Ctrl+Shift+W** acts on the focused pane or chat tab (or hides a focused mission drawer, or closes the launcher page). It is different from closing the whole window. Use **Stop** when you specifically want to halt an agent, and **Archive** when you want a chat out of active lists.

For alerts while the app is in the background, open **Settings → Notifications**. Chat events are enabled by default; mission events are opt-in. **Usage → Near the limit** is on at 80% by default; choose 50–90% to receive one alert per usage window and reset period. It covers Codex, the active Claude Code account and Antigravity CLI across both pools, and excludes 5-hour windows when that limit is hidden. Clicking a usage alert opens Settings → Usage. Hiding badges does not stop checks while usage alerts are on; scheduled checks stop when both are off. Clicking a notification opens its chat or mission. When the active window shows another computer, local alerts can still appear; clicking one returns a window to this computer and opens the local item.

See [Keyboard shortcuts](../reference/keyboard-shortcuts.md) for all defaults and customization.

## Work on another computer

Once signed in, choose a computer in the sidebar’s picker; see [Remote access](remote-access.md) to sign in. Chat creation, pane splits and resizing, shell panes, chat lifecycle and sidebar organization use the same controls on that host. Remote missions use the same feed, answer cards, recipient composer, member tabs and terminal drawer. The launcher's crew step lists the host's crews; creating or editing a crew stays on the host. Available actions depend on the host’s version. The command palette searches that computer’s chats and missions; Role and Crew open the host’s read-only lists, with chat and mission launch actions. Creating/editing/deleting roles or crews, Settings and Archived are available after returning to this computer.

The launcher uses the host’s agents and roles and shows its active Claude account. **Change** opens the host’s folder browser; local windows use the OS folder picker. The launcher lists the host’s projects for chats and missions. Launcher recency is shared across projects and windows, with a separate list for this computer and each remote host. Use ↑/↓ and Enter to select a ranked or pinned row; Esc on the default page returns to the previous tab/view; in a split pane it clears a search. Returning to this computer restores its own tabs, selection and sidebar state.

## Background tasks

Agent updates run in the background while the window stays usable. A pill at the bottom-right names the most urgent task and counts the others. Click it to open the task list, which shows versions, the latest output step, progress and actions. Priority is possible input, failure, running, then finished.

The pill's **×** hides it while work continues. It returns when a task may need input or fails; success does not reveal it. **Answer** or **Show output** opens that task's terminal dialog. The dialog never opens automatically, so typing in a chat stays in that chat. **Hide**, Escape and the dialog's close button leave the installer running.

Stop on a running task interrupts its installer and checks the executable. A working executable removes the row; a broken one leaves **Reinstall**. Failures stay with **Retry**, **Show output** and dismissal. When every task succeeds, the result stays for five seconds, then the pill and finished rows clear. Existing agent chats keep their old version until they restart.

The pill and list belong to this computer. A remote computer's update recovery stays with its remote pane and does not join the local list. Tasks are temporary and disappear when Runner's background service restarts.
